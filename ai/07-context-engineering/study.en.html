Context Engineering: Managing Context and Memory

🎯 After this lecture you can

  • You'll explain what goes into the model's context (System, tools, history, tool results, the question) and how context engineering differs from prompt engineering
  • You'll store the conversation history in PostgreSQL: a conversationId, the whole ChatMessage in jsonb, the tool messages included
  • You'll write /chat with a history: load → System + history + question → store response.Messages
  • You'll explain why the tokens grow with every question, and send only the last N messages into the context with MessageCountingChatReducer

⚡ Key points

  1. The model is stateless: "memory" is the history that we send with every request.
  2. Context = System + tool descriptions + history + tool results + the question. All of it is tokens: price, limit and speed.
  3. The history lives in the database: conversationId, the whole ChatMessage in jsonb, every message, tool messages included. We do not store the system prompt.
  4. /chat: load → [SystemPrompt(), .. history, question] → save [question, .. response.Messages].
  5. The database keeps everything; only part of it goes to the model: MessageCountingChatReducer.

Context

▶ Slides 6–8

Our /chat builds a new list on every request: System + one question. "Four of us tomorrow at 20:00?" and then "And at 21:00?": for the second one the model has no idea what we are talking about.

Context is everything that goes to the model in one request:

Part Who writes it
System prompt us
Tool descriptions us
History from the database
Tool results our code
The new question the user

The biggest part is often the tool results: get_menu returns the whole menu, and it stays in the history.

✅ Check yourself think first, then open the answer
But ChatGPT remembers the conversation?
ChatGPT's server remembers, not the model: it resends the whole history every time.

History in the database

▶ Slides 9–13

We store the history on the server, in PostgreSQL: we do not trust the client with it, and in memory it would be lost on restart. One row is one message:

Entities/Message.cs
public class Message{    public Guid Id { get; set; }    public Guid ConversationId { get; set; }   // which conversation it belongs to    public int Position { get; set; }          // order in the conversation: 0, 1, 2…    public string Role { get; set; } = "";     // user / assistant / tool — for looking at the DB     [Column(TypeName = "jsonb")]    public string Json { get; set; } = "";     // the whole ChatMessage     public DateTime CreatedAt { get; set; }}

DbSet<Message> Messages in DataContext, then a migration. Saving and loading: the whole ChatMessage in jsonb, tool messages included:

Ai/Chat/ChatHistoryStore.cs
public class ChatHistoryStore{    // jsonb reorders keys — "$type" is no longer first    private static readonly JsonSerializerOptions Json =        new(AIJsonUtilities.DefaultOptions) { AllowOutOfOrderMetadataProperties = true };     private readonly DataContext _db;    public ChatHistoryStore(DataContext db) { _db = db; }     public async Task<List<ChatMessage>> LoadAsync(Guid conversationId, CancellationToken ct)    {        List<string> rows = await _db.Messages            .Where(m => m.ConversationId == conversationId)            .OrderBy(m => m.Position)            .Select(m => m.Json)            .ToListAsync(ct);         return rows.Select(j => JsonSerializer.Deserialize<ChatMessage>(j, Json)!).ToList();    }     public async Task AppendAsync(Guid conversationId, IEnumerable<ChatMessage> messages, CancellationToken ct)    {        int position = await _db.Messages.CountAsync(m => m.ConversationId == conversationId, ct);        foreach (ChatMessage message in messages)        {            _db.Messages.Add(new Message            {                Id = Guid.NewGuid(),                ConversationId = conversationId,                Position = position++,                Role = message.Role.Value,                Json = JsonSerializer.Serialize(message, Json),                CreatedAt = DateTime.UtcNow            });        }        await _db.SaveChangesAsync(ct);    }}
⚠️

AllowOutOfOrderMetadataProperties = true is required: jsonb reorders the keys, so "$type" is no longer first.

✅ Check yourself think first, then open the answer
Why don't we store the system prompt in the history?
We add it from code every time. That way changing it takes effect even in old conversations.
Do we store response.Text or response.Messages?
response.Messages: it also contains the tool calls and results that must be restored in the next request.

The token budget

▶ Slides 15–18

The whole history goes with every question, so InputTokenCount (🔢 in: in the console) keeps growing, with a jump after get_menu. That causes four problems: cost, the context window limit, stale data and the model's attention.

Strategy What it means
🎯 Selection only what this question needs goes into the context
🗜️ Compression a short summary of the old part
✂️ Last N only the latest messages

Everything in the database, part of it to the model. IChatReducer shrinks the list before it is sent to the model:

Controllers/AssistantController.cs · Chat
#pragma warning disable MEAI001   // reducers are still experimentalprivate static readonly IChatReducer Reducer = new MessageCountingChatReducer(10);#pragma warning restore MEAI001 // inside Chat:List<ChatMessage> history = await _history.LoadAsync(conversationId, ct);IEnumerable<ChatMessage> recent = await Reducer.ReduceAsync(history, ct); ChatMessage question = new(ChatRole.User, request.Message);List<ChatMessage> messages = [SystemPrompt(), .. recent, question];// ... GetResponseAsync, AppendAsync — unchanged
⚠️

Reducers are still experimental (MEAI001). Use #pragma warning disable MEAI001 or <NoWarn> in the .csproj.

✅ Check yourself think first, then open the answer
The menu dropped out of the context. Where does the model get the price?
It calls get_menu again, and gets the current price too.
