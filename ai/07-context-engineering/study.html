Context Engineering: კონტექსტისა და მეხსიერების მართვა

🎯 ამ ლექციის შემდეგ შეძლებ

  • ახსნი, რა შედის მოდელის კონტექსტში (System, tool-ები, ისტორია, tool-ების შედეგები, შეკითხვა) და რით განსხვავდება context engineering prompt engineering-ისგან
  • საუბრის ისტორიას PostgreSQL-ში შეინახავ: conversationId, მთელი ChatMessage jsonb-ში, tool-ების შეტყობინებების ჩათვლით
  • /chat-ს ისტორიით დაწერ: ჩატვირთე → System + ისტორია + შეკითხვა → შეინახე response.Messages
  • ახსნი, რატომ იზრდება ტოკენები ყოველ შეკითხვაზე, და MessageCountingChatReducer-ით კონტექსტში მხოლოდ ბოლო N შეტყობინებას გაგზავნი

⚡ მთავარი

  1. მოდელი stateless-ია: „მეხსიერება“ ისტორიაა, რომელსაც ყოველ მოთხოვნაში ჩვენ ვუგზავნით.
  2. კონტექსტი = System + tool-ების აღწერები + ისტორია + tool-ების შედეგები + შეკითხვა. ყველაფერი ტოკენია: ფასი, ლიმიტი და სიჩქარე.
  3. ისტორია ბაზაშია: conversationId, მთელი ChatMessage jsonb-ში, ყველა შეტყობინება, tool-ებისაც. System prompt-ს არ ვინახავთ.
  4. /chat: ჩატვირთე → [SystemPrompt(), .. history, question] → შეინახე [question, .. response.Messages].
  5. ბაზაში ყველაფერი ინახება, მოდელთან მხოლოდ ნაწილი მიდის: MessageCountingChatReducer.

📍 ლექცია გააცდინე?

  1. ნახე პრეზენტაცია: სლაიდები ლექციის მთელ გზას აჩვენებს
  2. წაიკითხე თემები: ~6 წთ, თითოს ბოლოს „შეამოწმე თავი“
  3. გაიარე ტესტი: 8 კითხვა
  4. გააკეთე დავალებები

კონტექსტი

▶ სლაიდები 6–8

ჩვენი /chat ყოველ მოთხოვნაზე ახალ სიას ქმნის: System + ერთი შეკითხვა. "Four of us tomorrow at 20:00?" და მერე "And at 21:00?": მეორეზე მოდელმა არ იცის, რაზეა საუბარი.

კონტექსტი ყველაფერია, რაც მოდელთან ერთ მოთხოვნაში მიდის:

tool-ების აღწერები ჩვენ

tool-ების შედეგები ჩვენი კოდი

ყველაზე დიდი ხშირად tool-ების შედეგებია: get_menu მთელ მენიუს აბრუნებს, და ის ისტორიაში რჩება.

ისტორია ბაზაში

▶ სლაიდები 9–13

ისტორიას სერვერზე, PostgreSQL-ში ვინახავთ: კლიენტს მას არ ვანდობთ, და მეხსიერებაში რესტარტზე დაიკარგება. ერთი ხაზი ერთი შეტყობინებაა:

Data/ChatMessageRecord.cs
public class ChatMessageRecord{    public Guid Id { get; set; }    public Guid ConversationId { get; set; }   // which conversation it belongs to    public int Position { get; set; }          // order in the conversation: 0, 1, 2…    public string Role { get; set; } = "";     // user / assistant / tool — for looking at the DB     [Column(TypeName = "jsonb")]    public string Json { get; set; } = "";     // the whole ChatMessage     public DateTime CreatedAt { get; set; }}

DataContext-ში DbSet<ChatMessageRecord> ChatMessages და migration. შენახვა და ჩატვირთვა: მთელი ChatMessage jsonb-ში, tool-ების შეტყობინებებით:

Ai/ChatHistoryStore.cs
public class ChatHistoryStore{    // jsonb reorders keys — "$type" is no longer first    private static readonly JsonSerializerOptions Json =        new(AIJsonUtilities.DefaultOptions) { AllowOutOfOrderMetadataProperties = true };     private readonly DataContext _db;    public ChatHistoryStore(DataContext db) { _db = db; }     public async Task<List<ChatMessage>> LoadAsync(Guid conversationId, CancellationToken ct)    {        List<string> rows = await _db.ChatMessages            .Where(m => m.ConversationId == conversationId)            .OrderBy(m => m.Position)            .Select(m => m.Json)            .ToListAsync(ct);         return rows.Select(j => JsonSerializer.Deserialize<ChatMessage>(j, Json)!).ToList();    }     public async Task AppendAsync(Guid conversationId, IEnumerable<ChatMessage> messages, CancellationToken ct)    {        int position = await _db.ChatMessages.CountAsync(m => m.ConversationId == conversationId, ct);        foreach (ChatMessage message in messages)        {            _db.ChatMessages.Add(new ChatMessageRecord            {                Id = Guid.NewGuid(),                ConversationId = conversationId,                Position = position++,                Role = message.Role.Value,                Json = JsonSerializer.Serialize(message, Json),                CreatedAt = DateTime.UtcNow            });        }        await _db.SaveChangesAsync(ct);    }}
⚠️

AllowOutOfOrderMetadataProperties = true აუცილებელია: jsonb key-ებს თავისებურად ალაგებს, "$type" კი პირველი აღარ იქნება.

მოთხოვნები

  • /chat ისტორიით შენს პროექტში: ChatHistoryStore (jsonb), ChatRequest conversationId-ით, ბაზაში ყველა შეტყობინება, System prompt — ბაზის გარეშე
  • GET /chat/stream ისტორიით: პარამეტრები Guid conversationId, string prompt (id-ს კლიენტი ქმნის); iterator ჯერ ისტორიას ტვირთავს, ნაწილებს yield return-ით აგზავნის, სტრიმის ბოლოს კი updates.ToChatResponse().Messages-ს ინახავს
  • reducer: MessageCountingChatReducer ორივე endpoint-ში — ბაზაში ყველაფერი, კონტექსტში ბოლო N
  • GET /conversations/{id} — საუბარი UI-სთვის: მხოლოდ ტექსტიანი შეტყობინებები, { role, text }
  • README — ბიუჯეტის ცხრილი: ერთი საუბარი 6 შეკითხვით (2 მათგანზე tool-ი, რომელიც ბევრ მონაცემს აბრუნებს). სვეტები: შეკითხვა · InputTokenCount reducer-ის გარეშე · InputTokenCount MessageCountingChatReducer(6)-ით
  • კონსპექტის ტესტი (8 კითხვა) — ქულა ჩაწერე
