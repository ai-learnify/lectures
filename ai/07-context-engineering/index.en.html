Today's topic

Context Engineering: Managing Context and Memory

🤔Why you need this

Our chat calls tools and streams, but on the second question it no longer remembers the first: the model is stateless. Today we see what goes to the model in every request and who decides it — we do. We store the conversation history in PostgreSQL, the tool messages included, and send the model only what it needs, so that the cost and the context don't grow with every question. With agents this becomes the key skill.

🎯By the end of the lecture you can

  • You'll explain what goes into the model's context (System, tools, history, tool results, the question) and how context engineering differs from prompt engineering
  • You'll store the conversation history in PostgreSQL: a conversationId, the whole ChatMessage in jsonb, the tool messages included
  • You'll write /chat with a history: load → System + history + question → store response.Messages
  • You'll explain why the tokens grow with every question, and send only the last N messages into the context with MessageCountingChatReducer

Three options — which one would you choose?

📱 The client sends it

The frontend sends the whole conversation in every request

✗ The client can change the history · more traffic every time

A Dictionaryin a Singleton, keyed by the conversation id

✗ Disappears on restart · doesn't work with two servers

🐘 PostgreSQL

A table: one row = one message, by conversationId

✓ It stays · every server sees it · we can look at it and analyse it

Ai/Chat/ChatHistoryStore.cspublic class ChatHistoryStore{    // jsonb reorders keys — "$type" is no longer first    private static readonly JsonSerializerOptions Json =        new(AIJsonUtilities.DefaultOptions) { AllowOutOfOrderMetadataProperties = true };     private readonly DataContext _db;    public ChatHistoryStore(DataContext db) { _db = db; }     public async Task<List<ChatMessage>> LoadAsync(Guid conversationId, CancellationToken ct)    {        List<string> rows = await _db.Messages            .Where(m => m.ConversationId == conversationId)            .OrderBy(m => m.Position)            .Select(m => m.Json)            .ToListAsync(ct);         return rows.Select(j => JsonSerializer.Deserialize<ChatMessage>(j, Json)!).ToList();    }     public async Task AppendAsync(Guid conversationId, IEnumerable<ChatMessage> messages, CancellationToken ct)    {        int position = await _db.Messages.CountAsync(m => m.ConversationId == conversationId, ct);        foreach (ChatMessage message in messages)        {            _db.Messages.Add(new Message            {                Id = Guid.NewGuid(),                ConversationId = conversationId,                Position = position++,                Role = message.Role.Value,                Json = JsonSerializer.Serialize(message, Json),                CreatedAt = DateTime.UtcNow            });        }        await _db.SaveChangesAsync(ct);    }}

5 questions

1Why doesn't the model remember the previous question, and how do we “remind” it?The model is stateless: it only sees this request · we send the history in every request — the memory is in our code, not in the model
2What goes into the context, and which part grows fastest?System + the tool descriptions + the history + the tool results + the new question · often the tool results (e.g. the whole menu), which stay in the history
3Why do we store the whole ChatMessage in jsonb and not a Text column?Contents has different types: text, functionCall, functionResult, the thought signature · AIJsonUtilities.DefaultOptions stores them with $type · jsonb reorders keys → AllowOutOfOrderMetadataProperties
4Why don't we store the System prompt in the database?It's ours, not part of the conversation: it has today's date in it and the rules may change · we build it again on every request and put it at the top of the list
5What does MessageCountingChatReducer(10) do, and what stays in the database?It keeps the last 10 messages in the context and drops the tool messages · everything stays in the database · the model gets the price again with a tool
