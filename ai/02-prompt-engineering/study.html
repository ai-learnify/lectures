პირველი გამოძახება და Prompt Engineering

ლექციის სრული მასალა თავებად, ~14 წუთი კითხვა. შენი პროგრესი ბრაუზერში ინახება. ეს გვერდი პრეზენტაციას მიჰყვება: სლაიდის შეცვლისას შესაბამისი ნაწილი მოინიშნება.

⚡ 5 წუთში

თუ მხოლოდ ეს დაგამახსოვრდა, ლექციის მთავარი იცი:

  1. IChatClient LLM-ის „DbContext“-ია: კოდი GetResponseAsync-ს იძახებს, Gemini-სთან კი provider ლაპარაკობს. პროვაიდერის შეცვლა — ერთი ხაზი.
  2. API key User Secrets-შია (Gemini:ApiKey), არასდროს კოდში ან Git-ში.
  3. ChatOptions ყოველ მოთხოვნას ეყენება. პასუხში Usage (input, output, ფიქრის ტოკენები) და FinishReason (stop / length) გვეუბნება, რა დაჯდა და რატომ გაჩერდა.
  4. მოდელს ChatMessage-ების სიას ვუგზავნით: System (ჩვენი წესები), User (მომხმარებელი), Assistant (მოდელის პასუხი).
  5. კარგი system prompt = როლი + თემები + ფორმა + რა არ უნდა გააკეთოს. Few-shot მაგალითები პასუხს ზუსტ ფორმატში აფიქსირებს, რომ C# კოდმა გამოიყენოს.

📍 ლექცია გააცდინე?

  1. წაიკითხე თავები — სულ ~14 წთ. ყოველი თავის ბოლოს არის „შეამოწმე თავი“
  2. გაიარე ტესტი — 11 კითხვა, ქულით
  3. გააკეთე კლასის დავალება სახლში
  4. საშინაო დავალება — შემდეგ ლექციაზე განვიხილავთ

IChatClient — LLM-ის „DbContext“

სლაიდი 7

EF Core-იდან ეს იდეა უკვე იცი: კოდს DbContext-ით და LINQ-ით წერ, ბაზასთან კი provider ლაპარაკობს (SqlServer, Npgsql). ბაზის შეცვლა = provider-ის შეცვლა; LINQ ადგილზე რჩება.

Microsoft.Extensions.AI ზუსტად ამას აკეთებს ენობრივი მოდელებისთვის:

  • IChatClient — ერთი interface ყველა ჩატ-მოდელისთვის. მთავარი მეთოდი: GetResponseAsync.
  • provider-ები ამ interface-ს ახორციელებენ: Google.GenAI (Gemini), Microsoft.Extensions.AI.OpenAI (OpenAI და OpenAI-compatible სერვისები), OllamaSharp (ლოკალური მოდელები).

ჩვენი კოდი მხოლოდ IChatClient-ს იცნობს. სხვა პროვაიდერზე გადასვლა = client-ის შექმნის ერთი ხაზის შეცვლა.

💡

Microsoft.Extensions.AI .NET-ის ოფიციალური „AI ფენაა“ — ისევე, როგორც ILogger ლოგირებისთვის. მასზე დგას Microsoft Agent Framework-იც (ლექცია 14). DI-ში რეგისტრაცია და კონფიგურაცია — ლექცია 3-ზე.

პირველი endpoint: POST /api/ai-lab/ask

სლაიდი 9

RestaurantApi-ში ვქმნით „ლაბორატორიას“ — ცალკე Controller-ს ექსპერიმენტებისთვის. ის კლიენტისთვის არ არის: მასზე მოდელის ქცევას ვსწავლობთ.

DTO-ები — მზა, დააკოპირე (Dtos/AiLab/AskDtos.cs):

Dtos/AiLab/AskDtos.cs
using Microsoft.Extensions.AI; public record AskRequest(string Prompt); public record AskResponse(    string Text,    long? InputTokens,    long? OutputTokens,    long? ReasoningTokens,    string? FinishReason){    public static AskResponse From(ChatResponse response) => new(        response.Text,        response.Usage?.InputTokenCount,        response.Usage?.OutputTokenCount,        response.Usage?.ReasoningTokenCount,        response.FinishReason?.Value);}

From — პატარა static მეთოდი, რომელიც ChatResponse-ს ჩვენს DTO-ად აქცევს. ყველა დღევანდელ endpoint-ში გამოგვადგება.

Controller — ერთად ვწერთ:

Controllers/AiLabController.cs
using Google.GenAI;using Microsoft.AspNetCore.Mvc;using Microsoft.Extensions.AI; [ApiController][Route("api/ai-lab")]public class AiLabController : ControllerBase{    private readonly IChatClient _chat;     // დროებით აქვე ვქმნით — ლექცია 3-ზე DI-ში გადავა    public AiLabController(IConfiguration config)    {        _chat = new Client(apiKey: config["Gemini:ApiKey"])            .AsIChatClient("gemini-3.8-flash");    }     [HttpPost("ask")]    public async Task<IActionResult> Ask(AskRequest request)    {        ChatResponse response = await _chat.GetResponseAsync(request.Prompt);        return Ok(AskResponse.From(response));    }}

ხაზ-ხაზ:

  • IConfiguration config — .NET-ის კონფიგურაცია (appsettings.json + User Secrets + …), DI გვაძლევს constructor-ში.
  • new Client(apiKey: config["Gemini:ApiKey"]) — Google-ის SDK-ის client; key-ს User Secrets-იდან ვაწვდით.
  • .AsIChatClient("gemini-3.8-flash") — client-ს საერთო IChatClient-ად აქცევს; პარამეტრი მოდელის სახელია (მოდელების სია). ცვლადის ტიპი interface-ია, ობიექტი კი Gemini-ს.
  • GetResponseAsync(request.Prompt) — აგზავნის HTTP მოთხოვნას და ელოდება პასუხს. async, რადგან ეს ქსელის ოპერაციაა.
  • ChatResponse — პასუხი: Text, Usage (ტოკენები), FinishReason.
  • ?. — Usage და FinishReason შეიძლება null იყოს (ყველა provider ყოველთვის არ აბრუნებს).
⚠️

new Client(...).AsIChatClient(...) Controller-ის შიგნით — ესაა ის, რასაც DI-ზე ვერიდებოდით: Controller თვითონ ქმნის თავის დამოკიდებულებას. დღეს ეს შეგნებულად ასეა, რომ ყურადღება მოდელზე იყოს. ლექცია 3-ზე IChatClient-ს DI-ში დავარეგისტრირებთ.

{  "text": "Try grilled eggplant with walnuts…",  "inputTokens": 10,  "outputTokens": 19,  "reasoningTokens": 212,  "finishReason": "stop"}
ველი რას ნიშნავს ლექცია 1-დან

outputTokens რამდენი ტოკენია პასუხი output ფასი (ძვირი)

რა არის reasoningTokens? Gemini 3.8 Flash reasoning მოდელია: პასუხის დაწერამდე „ფიქრობს“. ფიქრის ტექსტს ჩვენ ვერ ვხედავთ, მაგრამ მის ტოკენებს output-ის ფასით ვიხდით. ამ მაგალითში 19-ტოკენიან პასუხზე 212 ფიქრის ტოკენი დაიხარჯა — ანუ ვიხდით 231 output ტოკენს.

📘 ტერმინები
reasoningTokens

რას ნახავ: "finishReason": "length", ტექსტი ცარიელი ან შუაში მოჭრილი, reasoningTokens კი ლიმიტის ტოლი. Gemini პასუხამდე ფიქრობს და ფიქრის ტოკენებიც ამ ლიმიტში ითვლება — 15 ტოკენი ფიქრზე დაიხარჯა და პასუხისთვის აღარ დარჩა. სცადე 300 და შეადარე.

💡

Gemini 3 და Temperature. 👉

Max Tokens reasoning მოდელზე: ლიმიტი ყოველთვის მარაგით — ფიქრსაც უნდა ეყოს. მოკლე პასუხი გინდა? ეს prompt-ში დაწერე („ერთი წინადადებით“), არა ლიმიტით.

Prompt engineering: როლები, system prompt, few-shot

🎯 ამის შემდეგ: დაწერ system prompt-ს, რომელიც ასისტენტს საზღვრებს უწესებს, და few-shot-ით მიიღებ ზუსტ პასუხს.

ნაწილი 3 · როგორ ვესაუბროთ მოდელს?

სლაიდი 15

ლექცია 1-ზე ვნახეთ: მოდელი შემდეგ ტოკენს მთელი ტექსტის მიხედვით ირჩევს. ე.ი. რასაც მას ვაწვდით, ის ცვლის პასუხს. Prompt engineering არის ამ ტექსტის გააზრებულად აწყობა: ვინ არის ასისტენტი, რაზე ლაპარაკობს, რა ფორმით პასუხობს.

მოდელს ვუგზავნით შეტყობინებების სიას

სლაიდი 16

ChatGPT-ს თავაზიანობა და „ასისტენტობა“ არავინ უთხრა ჩატში — ეს system შეტყობინებაშია, რომელსაც აპლიკაცია ყოველ მოთხოვნაში მომხმარებლისგან ფარულად აგზავნის. ჩვენც ზუსტად ასე ვაკეთებთ.

მოდელს ერთ ტექსტს კი არა, შეტყობინებების სიას ვუგზავნით. თითოს აქვს როლი:

Assistant მოდელი მისი წინა პასუხები (ისტორიაში)

მოდელი სიას თავიდან ბოლომდე „კითხულობს“ და წერს შემდეგ Assistant შეტყობინებას.

3 კითხვა ასისტენტს — ჯერ გამოიცანი

სლაიდი 18

POST /api/ai-lab/assistant-ზე სამი კითხვა:

  1. ჩვეულებრივი: „ხვალ 8-ზე ოთხნი ვიქნებით. ვეგეტარიანული გაქვთ?“ — პასუხობს მოკლედ, თემაზე.
  2. სხვა თემა: „დამიწერე ლექსი დედის დაბადების დღეზე“ — თავაზიანად უარს ამბობს და თავის თემას უბრუნდება.
  3. ფასი: „ხინკალი რა ღირს?“ — ფასს არ იგონებს.

შემდეგ იგივე კითხვები /ask-ზე გაუშვი (system prompt-ის გარეშე) და შეადარე: ლექსს სიამოვნებით დაწერს, ფასსაც დამაჯერებლად „მოიგონებს“ — ეს ლექცია 1-ის hallucination-ია.

⚠️

System prompt უსაფრთხოების გარანტია არ არის. ის ცვლის, რა არის სავარაუდო, მაგრამ მოდელი მაინც შეიძლება შეცდეს ან მომხმარებელმა „გადაარწმუნოს“ („დაივიწყე წინა ინსტრუქციები…“ — ამას prompt injection ჰქვია). რაც აუცილებლად უნდა შესრულდეს — ფასი, ფასდაკლება, ვის რისი უფლება აქვს — ამოწმებს C# კოდი. დაწვრილებით ლექცია 19-ზე.

Zero-shot vs few-shot

სლაიდი 19
  • Zero-shot — მოდელს მხოლოდ ვუხსნით, რა გააკეთოს. მარტივ ამოცანაზე ხშირად საკმარისია.
  • Few-shot — ახსნას ვუმატებთ რამდენიმე მაგალითს: „შეკითხვა → სწორი პასუხი“. მოდელი მაგალითებს ნიმუშად იღებს და იმავე ფორმით აგრძელებს.

რატომ გვჭირდება? AI-ის პასუხს ხშირად ადამიანი კი არ კითხულობს, არამედ ჩვენი C# კოდი იყენებს:

დაიმახსოვრე:

  1. IChatClient — LLM-ის „DbContext“: ერთი API ყველა მოდელისთვის; პროვაიდერის შეცვლა — ერთი ხაზი. key — User Secrets-ში (Gemini:ApiKey), არასდროს კოდში ან Git-ში.
  2. ChatOptions — Temperature და Max Tokens ყოველ მოთხოვნაზე ცალკე. Gemini 3-ზე Temperature-ს ნაგულისხმევზე ვტოვებთ; Max Tokens — მარაგით, რადგან ფიქრიც ამ ლიმიტშია.
  3. Usage და FinishReason — input, output და ფიქრის ტოკენები (ფიქრიც output-ის ფასით ფასდება); stop / length.
  4. შეტყობინებების სია — System (ჩვენი წესები), User (მომხმარებელი), Assistant (მოდელი).
  5. System prompt = როლი + თემები + ფორმა + საზღვრები. ის ალბათობას ცვლის, არა გარანტიას — აუცილებელ წესებს C# ამოწმებს.
  6. Few-shot — 3–5 მაგალითი User/Assistant წყვილებად; პასუხი ზუსტ ფორმატში მოდის, რომ კოდმა გამოიყენოს.
