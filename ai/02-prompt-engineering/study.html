პირველი გამოძახება და Prompt Engineering

🎯 ამ ლექციის შემდეგ შეძლებ

  • IChatClient-ით Gemini-ს გამოძახება საკუთარი API-დან და key-ის უსაფრთხოდ შენახვა
  • ChatOptions-ის დაყენება და პასუხიდან ტოკენების (Usage) და FinishReason-ის წაკითხვა
  • System prompt-ის დაწერა, რომელიც ასისტენტის როლს, თემებს და პასუხის ფორმას ზღუდავს
  • Zero-shot-ისა და few-shot-ის გარჩევა და few-shot-ით ზუსტი პასუხის მიღება

⚡ მთავარი

  1. IChatClient LLM-ის „DbContext“-ია: კოდი GetResponseAsync-ს იძახებს, Gemini-სთან კი provider ლაპარაკობს. პროვაიდერის შეცვლა ერთი ხაზია.
  2. API key User Secrets-შია (Gemini:ApiKey), არასდროს კოდში ან Git-ში.
  3. ChatOptions ცალკეულ მოთხოვნას ეყენება. პასუხში Usage (ტოკენები, ფიქრის ტოკენების ჩათვლით) და FinishReason (stop / length) გვეუბნება, რა დაჯდა და რატომ გაჩერდა.
  4. მოდელს შეტყობინებების სიას ვუგზავნით: System (ჩვენი წესები), User, Assistant.
  5. კარგი system prompt = როლი + თემები + ფორმა + საზღვრები. Few-shot მაგალითები პასუხს ზუსტ ფორმატში აფიქსირებს, რომ C# კოდმა გამოიყენოს.

  2. წაიკითხე თემები: ~8 წთ, თითოს ბოლოს „შეამოწმე თავი“

▶ სლაიდები 6–10

პარამეტრები კოდში

▶ სლაიდები 11–13

ლექცია 1-ის პარამეტრები C#-ში ChatOptions-შია: Temperature, TopP, MaxOutputTokens. AskRequest-ს ორ არასავალდებულო ველს ვამატებთ:

public record AskRequest(    string Prompt,    float? Temperature = null,    int? MaxOutputTokens = null);

და Ask-ში ChatOptions-ს ვქმნით (null = მოდელის ნაგულისხმევი):

სცადე: Temperature 0 და 2 სამ-სამჯერ: 0-ზე პასუხები თითქმის ერთნაირია, 2-ზე ყოველ ჯერზე სხვა. მერე MaxOutputTokens: 15: ტექსტი ცარიელია და finishReason არის length, რადგან ლიმიტი ფიქრმა შეჭამა.

როლები და system prompt

▶ სლაიდები 15–18

მოდელს ერთ ტექსტს კი არა, შეტყობინებების სიას ვუგზავნით. თითოს თავისი როლი აქვს:

როლი ვინ წერს რას შეიცავს
System ჩვენ, კოდში ვინ არის ასისტენტი და რა წესები აქვს
User მომხმარებელი კითხვა
Assistant მოდელი მოდელის პასუხი
csharp
List<ChatMessage> messages =[    new(ChatRole.System, "You are…"),    new(ChatRole.User, request.Prompt)]; ChatResponse response = await _chat.GetResponseAsync(messages);

კარგი system prompt ოთხი ნაწილისგან შედგება: 👤 როლი · 🎯 თემები · 📏 ფორმა · 🚫 საზღვრები.

Controllers/AiLabController.cs · Assistant
private const string RestaurantName = "Supra";private const string OpenHours = "12:00–23:00"; [HttpPost("assistant")]public async Task<IActionResult> Assistant(AskRequest request){    List<ChatMessage> messages =    [        new(ChatRole.System, $"""            You are the assistant of the restaurant "{RestaurantName}". სცადე /assistant-ზე: ჩვეულებრივი კითხვა მენიუზე, სხვა თემა („ლექსი დაწერე“) და ფასი („ხინკალი რა ღირს?“). ასისტენტი თემაზე რჩება და ფასს არ იგონებს.

⚠️

system prompt ალბათობას ცვლის და გარანტიას არ იძლევა. მომხმარებელმა შეიძლება მოდელი „გადაარწმუნოს“, ამიტომ მნიშვნელოვანს C# ამოწმებს (ლექცია 19).

✅ შეამოწმე თავი დაფიქრდი, მერე გახსენი პასუხი
System და User ორივე ტექსტია. რა განსხვავებაა?
System ჩვენი წესებია და მომხმარებელი მას ვერ ხედავს. User მომხმარებლის კითხვაა.
📘 ტერმინები

ChatMessage

4

zero-shot და few-shot

▶ სლაიდები 19–20
  • Zero-shot: მოდელს მხოლოდ ვუხსნით, რა გააკეთოს.
  • Few-shot: ახსნას 3–5 მაგალითს ვუმატებთ („შეკითხვა → სწორი პასუხი“).

პასუხს ხშირად C# კოდი იყენებს, მაგალითად if (label == "Negative"). zero-shot შეიძლება შინაარსით სწორი, მაგრამ ფორმით არასწორი იყოს („უარყოფითი“, Negative.). მაგალითები ფორმას აფიქსირებს. კოდში ისინი User/Assistant წყვილებია სიაში:

Controllers/AiLabController.cs · ReviewSentiment
[HttpPost("review-sentiment")]public async Task<IActionResult> ReviewSentiment(AskRequest request){    List<ChatMessage> messages =    [        new(ChatRole.System, "Classify the restaurant review. " +            "Answer with one word only: Positive, Negative or Mixed."),        new(ChatRole.User, "The khinkali was delicious, the service fast"),        new(ChatRole.Assistant, "Positive"),        new(ChatRole.User, "We waited an hour, the food came cold"),        new(ChatRole.Assistant, "Negative"),        new(ChatRole.User, "The dishes are good, but the prices are very high"),        new(ChatRole.Assistant, "Mixed"),        new(ChatRole.User, request.Prompt)    ];     ChatResponse response = await _chat.GetResponseAsync(messages);    return Ok(AskResponse.From(response));}
👉

მაგალითებში ჩასვი რთული შემთხვევაც ("Good, but pricey" → Mixed): ზუსტად საზღვარზე ცდება zero-shot.

💡

მოდელი მაინც ტექსტს წერს და არა C# ტიპს, ამიტომ პასუხი სიასთან შეამოწმე. ზუსტ ტიპს ლექცია 3 გვაძლევს (structured output).

✅ შეამოწმე თავი დაფიქრდი, მერე გახსენი პასუხი
few-shot მაგალითები ყოველ მოთხოვნაზე იგზავნება?
