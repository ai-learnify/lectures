The first call and Prompt Engineering

🎯 After this lecture you can

  • call Gemini from your own API with IChatClient and keep the key safe
  • set ChatOptions and read the tokens (Usage) and FinishReason from the response
  • write a system prompt that sets the assistant's role, topics and answer format
  • tell zero-shot from few-shot and explain why AI works better with examples

⚡ Key points

  1. IChatClient is the "DbContext" of LLMs: your code calls GetResponseAsync, and a provider talks to Gemini. Switching providers is one line.
  2. The API key lives in User Secrets (Gemini:ApiKey), never in code or Git.
  3. ChatOptions apply to a single request. In the response, Usage (tokens, including thinking tokens) and FinishReason (stop / length) tell you what it cost and why it stopped.
  4. We send the model a list of messages: System (our rules), User, Assistant.
  5. A good system prompt = role + topics + format + boundaries. AI works better with examples (few-shot): examples pin the answer to an exact format so C# code can use it.

First call

▶ Slides 6–10

Microsoft.Extensions.AI is to language models what EF Core is to databases: you write code against one interface (IChatClient), and a provider talks to the actual service (Google.GenAI for Gemini).

1. key → User Secrets. Get the key at aistudio.google.com, then in the project folder:

bash
dotnet user-secrets initdotnet user-secrets set "Gemini:ApiKey" "AIza..."

2. Two NuGet packages:

bash
dotnet add package Microsoft.Extensions.AIdotnet add package Google.GenAI
⚠️

An API key is a password. Never put it in code, appsettings.json or Git: bots find leaked keys on GitHub within minutes.

3. The first endpoint. The DTOs:

Parameters in code

▶ Slides 11–13

Lecture 1's parameters live in ChatOptions in C#: Temperature, TopP, MaxOutputTokens. We add two optional fields to PromptRequest:

Dtos/Diagnostics/PromptDtos.cs
public record PromptRequest(    string Prompt,    float? Temperature = null,    int? MaxOutputTokens = null);

and create ChatOptions in Ask (null = the model's default):

Controllers/AiDiagnosticsController.cs
var options = new ChatOptions{    Temperature = request.Temperature,    MaxOutputTokens = request.MaxOutputTokens}; ChatResponse response =    await _chat.GetResponseAsync(request.Prompt, options);

Try it: Temperature 0 and 2, three times each: at 0 the answers are almost the same, at 2 they differ every time. Then MaxOutputTokens: 15: the text is empty and finishReason is length, because thinking used up the limit.

👉

On a reasoning model always set the limit with room to spare. Ask for a short answer in the prompt ("in one sentence"), not with the limit.

✅ Check yourself think first, then open the answer
MaxOutputTokens = 50 and the answer is empty. Why?
Gemini thinks before answering, and thinking used up the whole limit.

Roles and the system prompt

▶ Slides 15–18

We send the model not one text but a list of messages. Each has its own role:

Role Who writes it What it contains
System us, in code who the assistant is and its rules
User the user the question
Assistant the model the model's answer
csharp
List<ChatMessage> messages =[    new(ChatRole.System, "You are…"),    new(ChatRole.User, request.Message)]; ChatResponse response = await _chat.GetResponseAsync(messages);

A good system prompt has four parts: 👤 role · 🎯 topics · 📏 format · 🚫 boundaries.

The assistant is a separate controller, with its own DTOs:

Dtos/Assistant/ChatDtos.cs
public record ChatRequest(string Message); public record ChatReply(string Text);
Controllers/AssistantController.cs · Chat
[HttpPost("chat")]public async Task<IActionResult> Chat(ChatRequest request){    List<ChatMessage> messages =    [        SystemPrompt(),        new(ChatRole.User, request.Message)    ];     ChatResponse response = await _chat.GetResponseAsync(messages);    return Ok(new ChatReply(response.Text));} private static ChatMessage SystemPrompt() => new(ChatRole.System, """    You are the assistant of the restaurant "Supra".    You answer only about the menu, bookings and opening hours (12:00–23:00).    Answer in at most 3 sentences, in the language the guest writes in.    On any other topic, politely decline and say what you can help with.    Never invent prices or ingredients — say they are on the menu.    """);

Try POST /api/assistant/chat: a normal menu question, an off-topic one ("write a poem") and a price ("how much is khinkali?"). The assistant stays on topic and does not invent prices.

⚠️

A system prompt changes probabilities; it is not a guarantee. A user may "talk the model round", so anything important is checked in C# (lecture 19).

✅ Check yourself think first, then open the answer
System and User are both text. What is the difference?
System is our rules and the user does not see it. User is the user's question.
📘 Terms
system prompt
the assistant's role, boundaries and answer format; written by the developer
ChatMessage
one message with a role (System / User / Assistant) and text

Zero-shot and few-shot

▶ Slide 19
  • Zero-shot: we only explain to the model what to do.
  • Few-shot: we add 3–5 examples to the explanation ("question → correct answer").

The main idea: AI works better with examples. Examples show the answer's form, tone and hard cases.

The answer is often used by C# code, for example if (label == "Negative"). Zero-shot may be right in content but wrong in form ("negative", Negative.). Examples pin down the form. In code they are sent as User/Assistant pairs, with every request.

⭐ In code (extra — in class only if time remains). Review classification in FeedbackController (SentimentRequest(string Text), SentimentResponse(string Sentiment)):

Controllers/FeedbackController.cs · AnalyzeSentiment
[HttpPost("sentiment")]public async Task<IActionResult> AnalyzeSentiment(SentimentRequest request){    List<ChatMessage> messages =    [        new(ChatRole.System, "Classify the guest's review of the restaurant. " +            "Answer with one word only: Positive, Negative or Mixed."),        new(ChatRole.User, "The khinkali was delicious and the service was fast"),        new(ChatRole.Assistant, "Positive"),        new(ChatRole.User, "We waited an hour and the food came cold"),        new(ChatRole.Assistant, "Negative"),        new(ChatRole.User, "The dishes are good, but the prices are very high"),        new(ChatRole.Assistant, "Mixed"),        new(ChatRole.User, request.Text)    ];     ChatResponse response = await _chat.GetResponseAsync(messages);    return Ok(new SentimentResponse(response.Text));}
👉

Include a hard case among the examples ("Good, but pricey" → Mixed): that boundary is exactly where zero-shot fails.

💡

The model still writes text, not a C# type, so check the answer against the list. Lecture 3 gives us an exact type (structured output).

✅ Check yourself think first, then open the answer
Are few-shot examples sent with every request?
Yes, they are part of the message list. That is why inputTokens grows.
📘 Terms
zero-shot
a prompt with instructions only
few-shot
a prompt with instructions and a few examples

🏠 Homework

A classifier in your project

With code · an endpoint + a table in the README

Requirements

  • An endpoint POST /api/assistant/classify — the user's text → one category for your project (at least 3 categories, e.g. Search / Order / Question)
  • System prompt: the task + the list of categories + “Answer with one word only” (no examples)
  • A check in the README: 5 different texts in Swagger. Table: text · the model's answer · does it pass a check like if (category == "Search") (✓ / ✗) · inputTokens
  • Language: the same text in Georgian and in English — inputTokens in the table
  • The study notes quiz (8 questions) — write down your score

✓ Done when

The endpoint answers all 5 texts; the README has the table (answer, ✓ / ✗, tokens) and the quiz score

⭐ Bonus

  • Few-shot: add 3 examples as User/Assistant pairs (the ⭐ code in the study notes) and add a “few-shot answer” column to the table. Where did ✗ turn into ✓? How much did inputTokens grow?
  • A text that fits no category — what does it return? Add Other and check in the Controller: if the answer isn't in the list → Other

💡 Details

  • Classification doesn't need a long answer, but keep MaxOutputTokens with room to spare (e.g. 200) — Gemini thinks first
  • If the model writes Search., search or a whole sentence, don't fix it in code — put ✗ in the table. That's lecture 3 material
  • Pick texts so that one or two are “on the boundary” (e.g. a question and an order at once)
