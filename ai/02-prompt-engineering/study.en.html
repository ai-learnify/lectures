  1. IChatClient is the “DbContext” of LLMs: the code calls GetResponseAsync, and a provider talks to Gemini. Switching providers — one line.

Chapter 1 · ~5 min read

The first call: Gemini from our API

🎯 After this your API will have an endpoint that calls Gemini and returns the tokens and finish reason along with the text.

Part 1 · Gemini from our API

Slide 6

In lecture 1 we saw that for us an LLM is just another HTTP API. We won't build the HTTP request by hand: .NET has a common layer for this — Microsoft.Extensions.AI. In this part we create the first endpoint in RestaurantApi that calls Gemini.

IChatClient — the “DbContext” of LLMs

Slide 7

You already know this idea from EF Core: you write code with DbContext and LINQ, and a provider talks to the database (SqlServer, Npgsql). Changing the database = changing the provider; LINQ stays the same.

Microsoft.Extensions.AI does exactly this for language models:

  • IChatClient — one interface for every chat model. The main method: GetResponseAsync.
  • providers implement this interface: Google.GenAI (Gemini), Microsoft.Extensions.AI.OpenAI (OpenAI and OpenAI-compatible services), OllamaSharp (local models).

Our code knows only IChatClient. Switching to another provider = changing one line where the client is created.

💡

Microsoft.Extensions.AI is the official “AI layer” of .NET — just like ILogger is for logging. Microsoft Agent Framework is built on it too (lecture 14). DI registration and configuration — in lecture 3.

📘 Terms
IChatClient
the Microsoft.Extensions.AI interface for talking to a chat model; the same for every provider
provider
a library that implements the common interface for a specific service (Gemini, OpenAI…)

Setup: the key and two NuGet packages

Slide 8

1. The key → User Secrets. You got a Gemini API key in the homework (aistudio.google.com → Get API key). Now we store it in User Secrets — .NET's built-in store for development. In the terminal, in the project folder:

bash
dotnet user-secrets initdotnet user-secrets set "Gemini:ApiKey" "AIza..."

Or in Visual Studio: right-click the project → Manage User Secrets → secrets.json opens:

secrets.json
{  "Gemini": {    "ApiKey": "AIza..."  }}

Gemini:ApiKey is a .NET configuration key: : means a nested section (Gemini → ApiKey). In code we read it as config["Gemini:ApiKey"]. secrets.json lives outside the project (in your user folder), so it can't end up in Git.

⚠️

An API key = a password. Never put it in code, appsettings.json or launchSettings.json — they go to Git, and bots find a key leaked on GitHub within minutes.

2. Two packages in RestaurantApi (or your project):

Package What for
Microsoft.Extensions.AI IChatClient, ChatOptions, ChatMessage, ChatResponse — one API for every model
Google.GenAI Google's official .NET SDK. Its AsIChatClient() method gives us an IChatClient

In Visual Studio: right-click the project → Manage NuGet Packages → Browse. Or from the terminal:

bash
dotnet add package Microsoft.Extensions.AIdotnet add package Google.GenAI

The first endpoint: POST /api/ai-lab/ask

Slide 9

In RestaurantApi we create a “lab” — a separate Controller for experiments. It isn't for customers: we use it to study how the model behaves.

DTOs — ready-made, copy them (Dtos/AiLab/AskDtos.cs):

Dtos/AiLab/AskDtos.cs
using Microsoft.Extensions.AI; public record AskRequest(string Prompt); public record AskResponse(    string Text,    long? InputTokens,    long? OutputTokens,    long? ReasoningTokens,    string? FinishReason){    public static AskResponse From(ChatResponse response) => new(        response.Text,        response.Usage?.InputTokenCount,        response.Usage?.OutputTokenCount,        response.Usage?.ReasoningTokenCount,        response.FinishReason?.Value);}

From is a small static method that turns a ChatResponse into our DTO. We'll use it in every endpoint today.

The Controller — we write it together:

Controllers/AiLabController.cs
using Google.GenAI;using Microsoft.AspNetCore.Mvc;using Microsoft.Extensions.AI; [ApiController][Route("api/ai-lab")]public class AiLabController : ControllerBase{    private readonly IChatClient _chat;     // created here for now — moves to DI in lecture 3    public AiLabController(IConfiguration config)    {        _chat = new Client(apiKey: config["Gemini:ApiKey"])            .AsIChatClient("gemini-3.8-flash");    }     [HttpPost("ask")]    public async Task<IActionResult> Ask(AskRequest request)    {        ChatResponse response = await _chat.GetResponseAsync(request.Prompt);        return Ok(AskResponse.From(response));    }}

Line by line:

  • IConfiguration config — .NET configuration (appsettings.json + User Secrets + …); DI hands it to the constructor.
  • new Client(apiKey: config["Gemini:ApiKey"]) — the Google SDK client; we pass it the key from User Secrets.
  • .AsIChatClient("gemini-3.8-flash") — turns the client into the common IChatClient; the parameter is the model name (model list). The variable's type is the interface, the object is Gemini's.
  • GetResponseAsync(request.Prompt) — sends the HTTP request and waits for the answer. async, because it's a network operation.
  • ChatResponse — the answer: Text, Usage (tokens), FinishReason.
  • ?. — Usage and FinishReason can be null (not every provider always returns them).
⚠️

new Client(...).AsIChatClient(...) inside the Controller is exactly what we avoided in the DI lecture: the Controller creates its own dependency. Today it's on purpose, so the focus stays on the model. In lecture 3 we register IChatClient in DI.

The first answer in Swagger

Slide 10

Run the project (F5), open POST /api/ai-lab/ask in Swagger → Try it out:

json
{ "prompt": "Suggest one light vegetarian dish. One sentence." }

The response will look roughly like this (the text and numbers will differ for you):

json
{  "text": "Try grilled eggplant with walnuts…",  "inputTokens": 10,  "outputTokens": 19,  "reasoningTokens": 212,  "finishReason": "stop"}
Field What it means From lecture 1
inputTokens how many tokens we sent tokens, input price
outputTokens how many tokens the answer has output price (expensive)
reasoningTokens how many tokens it spent thinking reasoning models
finishReason why it stopped: stop — on its own, length — at the limit Max Tokens

What is reasoningTokens? Gemini 3.8 Flash is a reasoning model: it “thinks” before writing the answer. We can't see the thinking text, but we pay for its tokens at the output price. In this example 212 thinking tokens were spent on a 19-token answer — so we pay for 231 output tokens.

📘 Terms
reasoningTokens
tokens the model spent thinking before the answer; billed at the output price
finishReason
why the model stopped: stop (finished on its own) or length (hit the limit)

Part 2 · Lecture 1 theory in our code

Slide 11

In lecture 1 we saw the Temperature slider and Max Tokens on a slide. Now we set them from code and check the result on a real model.

Parameters from code — ChatOptions

Slide 12

In C# the parameters from lecture 1 live in the ChatOptions class:

ChatOptions In lecture 1
Temperature Temperature
TopP Top-P
MaxOutputTokens Max Tokens
ModelId a different model for this request

We add two optional fields to AskRequest:

Dtos/AiLab/AskDtos.cs
public record AskRequest(    string Prompt,    float? Temperature = null,    int? MaxOutputTokens = null);

and in Ask we create ChatOptions:

Controllers/AiLabController.cs
var options = new ChatOptions{    Temperature = request.Temperature,    MaxOutputTokens = request.MaxOutputTokens}; ChatResponse response =    await _chat.GetResponseAsync(request.Prompt, options);

null means “not specified” — the model uses its default. This way we can try any combination from Swagger with one endpoint.

💡

options belongs to a single request: one Temperature in one endpoint, another in a different one — exactly as we planned in the lecture 1 table.

🔮 2 experiments — guess first, then run

Slide 13

For each experiment, first write down your prediction, then check it in Swagger.

1 · Temperature.

json
{ "prompt": "Invent a name for a new Georgian dish. Only the name.", "temperature": 0 }

Three times with 0, then three times with 2. What you'll see: at 0 the names are (almost) the same, at 2 they're different every time — sometimes strange. This confirms the lecture 1 slider on a real model.

2 · Max Tokens.

json
{ "prompt": "Describe khachapuri", "maxOutputTokens": 15 }

What you'll see: "finishReason": "length", the text is empty or cut in the middle, and reasoningTokens equals the limit. Gemini thinks before answering and the thinking tokens count toward the same limit — the 15 tokens were spent on thinking and nothing was left for the answer. Try 300 and compare.

💡

Gemini 3 and Temperature. For Gemini 3 models Google recommends leaving Temperature at the default (1.0): these are reasoning models, and at a low Temperature quality may drop or the answer may fall into repetition. In the experiment we change Temperature to see the effect. In a real endpoint on Gemini 3 we keep the default and get an exact format with the prompt — we learn that in part 3.

👉

Max Tokens on a reasoning model: always set the limit with room to spare — the thinking needs it too. Want a short answer? Say it in the prompt (“in one sentence”), not with the limit.

Chapter 3 · ~5 min read

Prompt engineering: roles, system prompt, few-shot

🎯 After this you'll write a system prompt that sets boundaries for the assistant, and get an exact answer with few-shot.

Part 3 · How do we talk to the model?

Slide 15

In lecture 1 we saw that the model picks the next token based on the whole text. So what we give it changes the answer. Prompt engineering means building this text deliberately: who the assistant is, what it talks about, in what form it answers.

We send the model a list of messages

Slide 16

Nobody told ChatGPT in the chat to be polite and act as an “assistant” — that's in the system message, which the app sends with every request, hidden from the user. We do exactly the same.

We send the model not one text but a list of messages. Each has a role:

Role Who writes it What it contains
System we, in code who the assistant is, what it talks about, how it answers, what it doesn't do
User the user a question, a request
Assistant the model its previous answers (in the history)

The model “reads” the list from top to bottom and writes the next Assistant message.

In C# the list is built like this:

csharp
List<ChatMessage> messages =[    new(ChatRole.System, "You are…"),    new(ChatRole.User, request.Prompt)]; ChatResponse response = await _chat.GetResponseAsync(messages);
💡

GetResponseAsync("text"), which we used in part 1, is actually the same thing: a list with one User message. We'll add the history (previous User/Assistant messages) in lecture 7 — that gives the model a “memory”.

📘 Terms
System prompt
the system message: the assistant's role, boundaries and answer format; the developer writes it, the user can't see it
ChatMessage
one message with a role (ChatRole.System / User / Assistant) and text

System prompt: the restaurant assistant

Slide 17

We add a second endpoint — POST /api/ai-lab/assistant. It has a system prompt: an instruction that goes before the user's question in every request.

Controllers/AiLabController.cs · Assistant
private const string RestaurantName = "Supra";private const string OpenHours = "12:00–23:00"; [HttpPost("assistant")]public async Task<IActionResult> Assistant(AskRequest request){    List<ChatMessage> messages =    [        new(ChatRole.System, $"""            You are the assistant of the restaurant "{RestaurantName}".            You answer only about the menu, bookings and hours ({OpenHours}).            Answer: at most 3 sentences, in the language you are written in.            On any other topic you politely decline and say what you can help with.            You don't invent prices or ingredients — you say they are on the menu.            """),        new(ChatRole.User, request.Prompt)    ];     ChatResponse response = await _chat.GetResponseAsync(messages);    return Ok(AskResponse.From(response));}

A good system prompt — 4 parts:

Part Ours Why
👤 Role “the assistant of the restaurant Supra” the model knows on whose behalf it speaks
🎯 Topics menu, reservations, hours a boundary: what it answers about
📏 Format at most 3 sentences, in the user's language length and language — set in advance
🚫 Boundaries another topic — decline; doesn't invent prices what to do when a question doesn't fit

The template ($"""…""") is C# raw string interpolation. {RestaurantName} and {OpenHours} are filled in at run time. For now these are constants; later, data from the database goes here (lecture 4: tools, lecture 11: RAG).

👉

“Be smart and helpful” tells the model nothing. A concrete role, topics, format and boundary do. Write it the way you'd explain the job to a new employee on their first day.

📘 Terms
prompt template
a prompt template into which data from code is inserted

3 questions for the assistant — guess first

Slide 18

Three questions on POST /api/ai-lab/assistant:

  1. A normal one: “There'll be four of us tomorrow at 8. Do you have anything vegetarian?” — answers briefly, on topic.
  2. Another topic: “Write me a poem for my mom's birthday” — politely declines and returns to its topic.
  3. A price: “How much is khinkali?” — doesn't invent a price.

Then send the same questions to /ask (without a system prompt) and compare: it will happily write the poem and confidently “invent” a price — that's the hallucination from lecture 1.

⚠️

A system prompt is not a security guarantee. It changes what is likely, but the model can still make a mistake or the user can “talk it out of it” (“forget your previous instructions…” — this is called prompt injection). What must happen — prices, discounts, who's allowed to do what — is checked by C# code. More in lecture 19.

Zero-shot vs few-shot

Slide 19
  • Zero-shot — we only explain to the model what to do. For a simple task this is often enough.
  • Few-shot — we add a few examples to the explanation: “question → correct answer”. The model takes the examples as a pattern and continues in the same form.

Why do we need it? Often the AI's answer isn't read by a person — it's used by our C# code:

csharp
if (label == "Negative") NotifyManager();

Zero-shot may write an answer that's right in content but “wrong” in form: “negative”, “Negative.”, or a whole paragraph. The if won't catch that. Few-shot fixes the form: the answer is exactly one word from the list.

Zero-shot Few-shot
What we give only the instruction the instruction + 3–5 examples
When a simple task, free text an exact format, categories, “borderline” cases
Cost fewer tokens the examples go with every request — more input
👉

Always include a hard case in the examples (here — “good, but expensive” → Mixed). Zero-shot fails most often right at the border.

📘 Terms
zero-shot
a prompt with only an instruction, no examples
few-shot
a prompt with an instruction and a few “question → correct answer” examples

Few-shot in code: User / Assistant pairs

Slide 20

We don't send the examples as a separate parameter — they are in the same message list, as a “previous conversation”: the User asked, the Assistant answered. The model sees how it “answered” before and answers the last question in the same form.

Controllers/AiLabController.cs · ReviewSentiment
[HttpPost("review-sentiment")]public async Task<IActionResult> ReviewSentiment(AskRequest request){    List<ChatMessage> messages =    [        new(ChatRole.System, "Classify the restaurant review. " +            "Answer with one word only: Positive, Negative or Mixed."),        new(ChatRole.User, "The khinkali was delicious, the service fast"),        new(ChatRole.Assistant, "Positive"),        new(ChatRole.User, "We waited an hour, the food came cold"),        new(ChatRole.Assistant, "Negative"),        new(ChatRole.User, "The dishes are good, but the prices are very high"),        new(ChatRole.Assistant, "Mixed"),        new(ChatRole.User, request.Prompt)    ];     ChatResponse response = await _chat.GetResponseAsync(messages);    return Ok(AskResponse.From(response));}

Try it in Swagger: “The dishes are good, but it's very noisy” → Mixed. Then comment out the examples (lines 8–13) and run the same — compare the zero-shot answer. Also compare inputTokens: the examples are tokens and go with every request.

💡

An exact word is still not a C# type. The model writes what's likely, so in the Controller we should check the answer against the list (e.g. Positive / Negative / Mixed, otherwise — an error or Mixed). In the next lecture, with structured output (GetResponseAsync<T>), we'll get the answer directly as a C# object — with an enum and fields.

Summary

Slide 23

Remember:

  1. IChatClient — the “DbContext” of LLMs: one API for every model; switching providers is one line. The key — in User Secrets (Gemini:ApiKey), never in code or Git.
  2. ChatOptions — Temperature and Max Tokens per request. On Gemini 3 we leave Temperature at the default; Max Tokens — with room to spare, because thinking is inside that limit too.
  3. Usage and FinishReason — input, output and thinking tokens (thinking is billed at the output price too); stop / length.
  4. A list of messages — System (our rules), User (the user), Assistant (the model).
  5. System prompt = role + topics + format + boundaries. It changes probabilities, not guarantees — C# checks the rules that must hold.
  6. Few-shot — 3–5 examples as User/Assistant pairs; the answer comes in an exact format so the code can use it.

All terms of the lecture

Terms

IChatClient
the Microsoft.Extensions.AI interface for talking to a chat model; the same for every provider
provider
a library that implements the common interface for a specific service (Gemini, OpenAI…)
reasoningTokens
tokens the model spent thinking before the answer; billed at the output price
finishReason
why the model stopped: stop (finished on its own) or length (hit the limit)
System prompt
the system message: the assistant's role, boundaries and answer format; the developer writes it, the user can't see it
ChatMessage
one message with a role (ChatRole.System / User / Assistant) and text
prompt template
a prompt template into which data from code is inserted
zero-shot
a prompt with only an instruction, no examples
few-shot
a prompt with an instruction and a few “question → correct answer” examples
