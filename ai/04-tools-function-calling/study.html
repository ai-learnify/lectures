Tools და Function Calling

🎯 ამ ლექციის შემდეგ შეძლებ

  • ახსნი function calling-ის ციკლს: tool-ების სია → გამოძახების თხოვნა → ჩვენი კოდი ასრულებს → შედეგი → პასუხი
  • C# მეთოდს tool-ად აქცევ AIFunctionFactory.Create-ით და [Description]-ით, და ChatOptions.Tools-ში გადასცემ
  • UseFunctionInvocation-ით ციკლს ავტომატურად ატრიალებ და response.Messages-ში ნახავ, რომელი tool გამოიძახა მოდელმა
  • დაწერ კარგ tool-ს: ზმნა-სახელი, აღწერა, ტიპიზებული პარამეტრები; ახსნი, რატომ არის დღეს tool-ები მხოლოდ კითხვისთვის

⚡ მთავარი

  1. მოდელი ჩვენს ბაზას ვერ ხედავს: ან იგონებს, ან უარს ამბობს. მთელი ბაზის prompt-ში ჩაწერა ძვირია და ძველდება.
  2. Function calling: ვაგზავნით შეკითხვას + tool-ების სიას → მოდელი ითხოვს გამოძახებას → ჩვენი კოდი ასრულებს მეთოდს → შედეგი მოდელს → ტექსტური პასუხი.
  3. Tool = სახელი + აღწერა ([Description]) + პარამეტრების JSON Schema. AIFunctionFactory.Create(method, name: "...") მას C# მეთოდიდან ქმნის, ChatOptions.Tools მოთხოვნასთან აგზავნის.
  4. .UseFunctionInvocation() Program.cs-ში ციკლს ავტომატურად ატრიალებს. response.Messages-ში ჩანს, რომელი tool გამოიძახა.
  5. კარგი tool: სახელი = ზმნა + რა, ზუსტი აღწერა, ტიპიზებული პარამეტრები, ერთი საქმე. დღეს მხოლოდ კითხვის tool-ებია: ჩანაწერს დადასტურება სჭირდება.

  2. წაიკითხე თემები: ~6 წთ, თითოს ბოლოს „შეამოწმე თავი“

მოდელი და ჩვენი ბაზა

▶ სლაიდები 6–9

მომხმარებელი წერს: "There are four of us, tomorrow at 8, do you have a table?". მოდელს ჩვენი ბაზა არ აქვს, ამიტომ ან მოიგონებს („კი, გვაქვს!“), ან უარს იტყვის.

მოდელი ჩვენს მეთოდს ვერ იძახებს: ის Google-ის სერვერზეა, ბაზა კი ჩვენთან. ის მხოლოდ ითხოვს, ჩვენ ვასრულებთ:

  1. ვაგზავნით შეკითხვას და tool-ების სიას (სახელი, აღწერა, პარამეტრები)
  2. მოდელი პასუხის ნაცვლად ითხოვს: „გამოიძახე check_availability(at: …, guests: 4)“
  3. ჩვენი კოდი ასრულებს მეთოდს და შედეგს უკან აგზავნის
  4. მოდელი შედეგის მიხედვით ტექსტურ პასუხს წერს

Gemini-სთან ერთ კითხვაზე მინიმუმ ორი მოთხოვნა მიდის.

using System.ComponentModel;using Microsoft.EntityFrameworkCore; public record MenuItemInfo(string Name, decimal Price); public class RestaurantTools{    private readonly DataContext _db;     public RestaurantTools(DataContext db)    {        _db = db;    }     [Description("Returns the restaurant menu: dish name and price in GEL")]    public async Task<List<MenuItemInfo>> GetMenu()    {        return await _db.Products            .Select(p => new MenuItemInfo(p.Name, p.Price))            .ToListAsync();    }}

პარამეტრები და კარგი tool

▶ სლაიდები 15–18

ახლა tool, რომლის პარამეტრებს მოდელი მომხმარებლის ტექსტიდან ავსებს. [Description] პარამეტრებზე სქემაში ჯდება, ისე როგორც ლექცია 3-ის BookingRequest-ში:

Ai/RestaurantTools.cs · CheckAvailability
public record AvailabilityInfo(bool Available, int FreeTables); [Description("Checks whether a table is free at the given time")]public async Task<AvailabilityInfo> CheckAvailability(    [Description("Booking date and time")] DateTime at,    [Description("Number of guests")] int guests){    var busyTableIds = await _db.Bookings        .Where(b => b.At > at.AddHours(-2) && b.At < at.AddHours(2))        .Select(b => b.TableId)        .ToListAsync();     int free = await _db.Tables        .CountAsync(t => t.Seats >= guests && !busyTableIds.Contains(t.Id));     return new AvailabilityInfo(free > 0, free);}

კარგი tool, 4 წესი:

  1. სახელი = ზმნა + რა (check_availability, არა data)
