Tools and Function Calling

🎯 After this lecture you can

  • You'll explain the function-calling loop: list of tools → call request → our code runs it → result → answer
  • You'll turn a C# method into a tool with AIFunctionFactory.Create and [Description] and pass it in ChatOptions.Tools
  • You'll run the loop automatically with UseFunctionInvocation and see in response.Messages which tool the model called
  • You'll write a good tool: a verb name, a description, typed parameters; and explain why today's tools only read

⚡ Key points

  1. The model cannot see our database: it either makes things up or refuses. Putting the whole database into the prompt is expensive and goes stale.
  2. Function calling: we send the question + a list of tools → the model asks for a call → our code runs the method → the result goes back to the model → a text answer.
  3. Tool = name + description ([Description]) + the parameters' JSON Schema. AIFunctionFactory.Create(method, name: "...") creates it from a C# method; ChatOptions.Tools sends it with the request.
  4. .UseFunctionInvocation() in Program.cs runs the loop automatically. response.Messages shows which tool was called.
  5. A good tool: name = verb + what, a precise description, typed parameters, one job. Today only read tools: writing needs confirmation.

The model and our database

▶ Slides 6–9

The user writes: "There are four of us, tomorrow at 8, do you have a table?". The model has no access to our database, so it either invents an answer ("Yes, we do!") or refuses.

The model cannot call our method: it runs on Google's server, and the database is with us. It can only ask, and we execute:

  1. We send the question and the list of tools (name, description, parameters)
  2. Instead of an answer the model asks: "call check_availability(at: …, guests: 4)"
  3. Our code runs the method and sends the result back
  4. The model writes a text answer based on the result

Gemini receives at least two requests for one question.

👉

The model cannot see a tool's code, only its name, description and parameters. That is why the description is decisive.

✅ Check yourself think first, then open the answer
How many times did we call Gemini for one question if it called one tool?
Twice: first the question and the tool list, then the history and the tool's result.

The first tool: the menu

▶ Slides 10–13

A tool is an ordinary C# method. All tools live in one class:

Ai/RestaurantTools.cs
using System.ComponentModel;using Microsoft.EntityFrameworkCore; public record MenuItemInfo(string Name, decimal Price); public class RestaurantTools{    private readonly DataContext _db;     public RestaurantTools(DataContext db)    {        _db = db;    }     [Description("Returns the restaurant menu: dish name and price in GEL")]    public async Task<List<MenuItemInfo>> GetMenu()    {        return await _db.Products            .Select(p => new MenuItemInfo(p.Name, p.Price))            .ToListAsync();    }}
Program.cs
builder.Services.AddScoped<RestaurantTools>();

The controller receives RestaurantTools through its constructor and attaches the tool to the request:

Controllers/AssistantController.cs
private readonly IChatClient _chat;private readonly RestaurantTools _tools;private readonly ILogger<AssistantController> _logger; public AssistantController(IChatClient chat, RestaurantTools tools, ILogger<AssistantController> logger){    _chat = chat;    _tools = tools;    _logger = logger;}
Controllers/AssistantController.cs · Chat
[HttpPost("chat")]public async Task<IActionResult> Chat(ChatRequest request){    List<ChatMessage> messages =    [        SystemPrompt(),        new(ChatRole.User, request.Message)    ];     ChatResponse response = await _chat.GetResponseAsync(messages, CreateChatOptions());     List<string> toolCalls = response.Messages        .SelectMany(m => m.Contents)        .OfType<FunctionCallContent>()        .Select(c => c.Name)        .ToList();    _logger.LogInformation("Tools called: {Tools}", string.Join(", ", toolCalls));     return Ok(new ChatReply(response.Text));} private ChatOptions CreateChatOptions() => new(){    Tools = [AIFunctionFactory.Create(_tools.GetMenu, name: "get_menu")]};

In Program.cs one line turns the loop on:

Program.cs
builder.Services.AddChatClient(        new Client(apiKey: apiKey).AsIChatClient(model))    .UseFunctionInvocation();
💡

_db.Products and p.Price are RestaurantApi's names. Use your own entities in your project.

Result: "What dishes do you have under 15 GEL?" on POST /api/diagnostics/ai/ask (no tools) invents dishes, while POST /api/assistant/chat answers from the database and Tools called shows get_menu. For "Hello!" it does not call the tool: the model decides whether it needs one.

✅ Check yourself think first, then open the answer
Why AddScoped<RestaurantTools> and not AddSingleton?
It contains a DataContext, which is Scoped.
AIFunctionFactory.Create(_tools.GetMenu()). What is wrong here?
The parentheses: we must pass the method, not its result. The model decides later whether to call it.

Parameters and a good tool

▶ Slides 15–18

Now a tool whose parameters the model fills in from the user's text. [Description] on parameters goes into the schema, just like the fields of lecture 3's BookingDetails:

Ai/RestaurantTools.cs · CheckAvailability
public record AvailabilityInfo(bool Available, int FreeTables); [Description("Checks whether a table is free at the given time")]public async Task<AvailabilityInfo> CheckAvailability(    [Description("Booking date and time")] DateTime at,    [Description("Number of guests")] int guests){    var busyTableIds = await _db.Bookings        .Where(b => b.At > at.AddHours(-2) && b.At < at.AddHours(2))        .Select(b => b.TableId)        .ToListAsync();     int free = await _db.Tables        .CountAsync(t => t.Seats >= guests && !busyTableIds.Contains(t.Id));     return new AvailabilityInfo(free > 0, free);}

In the controller we add the second tool and today's date (otherwise "tomorrow" cannot be worked out):

Controllers/AssistantController.cs
private ChatOptions CreateChatOptions() => new(){    Tools =    [        AIFunctionFactory.Create(_tools.GetMenu, name: "get_menu"),        AIFunctionFactory.Create(_tools.CheckAvailability, name: "check_availability")    ]}; private static ChatMessage SystemPrompt() => new(ChatRole.System, $"""    You are the assistant of the restaurant "Supra".    You answer only about the menu, bookings and opening hours (12:00–23:00).    Answer in at most 3 sentences, in the language the guest writes in.    Take menu and free-table data only from the tools, never make anything up.    Today is {DateTime.Now:yyyy-MM-dd, dddd}.    """);

A good tool, 4 rules:

  1. Name = verb + what (check_availability, not data)
  2. The description says exactly when to call it
  3. Parameters are typed (DateTime, int) and described
  4. One tool = one job
👉

If the model calls a tool at the wrong time, improve the description first, not the code.

✅ Check yourself think first, then open the answer
Why don't we give the model create_booking?
It is possible but dangerous: "at 8" might be taken as 08:00 and the booking created without asking anyone. Writing needs confirmation (lecture 15).

An assistant with tools

With code · your project · a table in the README

Requirements

  • Tools class: Ai/<Your>Tools.cs, AddScoped, data from your database (or your existing service)
  • 2 tools: one without parameters, one with at least 2 parameters; both only read; [Description] on the methods and parameters; names are verb + what
  • POST /api/assistant/chat: System — the assistant's role, “data only from the tools”, today's date (if you have a date parameter); Tools called in the log with parameters
  • A table in the README — 5 texts: no tool · the first tool · the second tool · both together · one where a parameter is missing. Columns: text · Tools called (with arguments) · is the answer correct? · what you noticed
  • The study notes quiz (8 questions) — write down your score

✓ Done when

All 5 texts are in the table; data from the database shows up in the answer and isn't made up; on the “no tool” text Tools called is empty; for the “parameter missing” text you describe what the model did (did it ask? pick something itself?)

⭐ Bonus

  • Bad-description experiment: remove one tool's description and name it Data → the same 5 texts. What changed? Put it back and note it in the table
  • A C# check in the tool: on a wrong parameter (a past date, a negative count) return an object with an explanation, not an exception
  • Think: which writing tool would be useful in your project and what confirmation would it need? 2–3 sentences in the README (no code needed)

💡 Details

  • Don't return an entity as a tool result — a record with only the needed fields (fewer tokens, no navigation cycles)
  • Pass the method to AIFunctionFactory.Create without parentheses: _tools.GetMenu, not _tools.GetMenu()
  • For arguments in the log: .Select(c => $"{c.Name}({string.Join(", ", c.Arguments ?? new Dictionary<string, object?>())})")
  • If a tool isn't called, fix the description first, the code second

📝 Classwork

Your tool — in your project

Your project or RestaurantApi · with code · in Swagger

Steps

  • 1 · Tools class — Ai/<Your>Tools.cs: DbContext (or your service) through the constructor, AddScoped in Program.cs
  • 2 · A tool with a parameter — one read method over your database, with at least 1 parameter; [Description] on the method and on the parameter; name = verb + what
  • 3 · POST /api/assistant/chat — System: who the assistant is + “data only from the tool, don't make anything up” → ChatOptions.Tools → GetResponseAsync(messages, options) → Ok(new { response.Text, ToolCalls }). .UseFunctionInvocation() in Program.cs
  • 4 · 3 texts in Swagger: one where the tool should be called · one where it should not be called · one where the parameter is written in the text in other words

✓ Done when

On the first text your tool shows up in Tools called and the answer contains data from your database; on the second Tools called is empty; on the third the parameter is filled in correctly

⭐ Bonus

  • Show the parameters in Tools called too: c.Arguments (there's a tip in the study notes)
  • Add a second tool and write a text where both get called
  • A C# check inside the tool: on a wrong parameter (e.g. the date is in the past) the tool returns an object with an explanation, not an exception

💡 If you're stuck

  • Ideas: library — find_books(string author), is_book_available(string title) · gym — get_classes(DayOfWeek day) · shop — get_products_under(decimal maxPrice), get_stock(string productName)
  • The tool isn't called? Check: did you pass options to GetResponseAsync? Is .UseFunctionInvocation() in Program.cs? Does the System prompt say “only from the tool”?
  • Tools called is empty and text is empty? You forgot .UseFunctionInvocation() — the model asked for a call, but nobody ran it
  • Cannot resolve scoped service? Register the Tools class with AddScoped, not AddSingleton (DbContext is Scoped)
  • A date parameter? In the System prompt: Today is {DateTime.Now:yyyy-MM-dd, dddd}.
