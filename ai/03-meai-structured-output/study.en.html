The whole lecture in chapters, ~18 minutes of reading. Your progress is saved in the browser. This page follows the presentation: when the slide changes, the matching part is highlighted.

⚡ In 5 minutes

If this is all you remember, you know the core of the lecture:

  1. AddChatClient — IChatClient is created once in Program.cs and registered in DI as a Singleton. The Controller receives it through the constructor — like DbContext in the API course.
  2. The key — in User Secrets (dotnet user-secrets set "Gemini:ApiKey" "..."), the model — in appsettings.json. Another model = configuration only, another provider = Program.cs only.
  3. GetResponseAsync<T> — a JSON Schema is created from the C# type, sent with the request, and the model can't write outside it. response.Result is already a T.
  4. enum — one value from a list (classification); record — several fields from text (extraction). Nullable fields and “leave null” — so it doesn't make things up; today's date — in the prompt.
  5. The shape is guaranteed, the content is not. C# checks the received object before the database.

[HttpPost("classify")]public async Task<IActionResult> Classify(AskRequest request){    List<ChatMessage> messages =    [        new(ChatRole.System, "Classify the library request. Chapter 1 · ~4 min read

IChatClient in DI: AddChatClient and configuration

🎯 After this You'll register IChatClient in Program.cs, keep the key in User Secrets and the model in appsettings.json, and the Controller will receive it through its constructor.

Part 1 · IChatClient in DI

Slide 6

Nothing new in this part — in the API course you registered DbContext and your services exactly like this. We apply the same pattern to IChatClient: we create it once in Program.cs, and the Controller receives it through its constructor.

What's wrong with the lecture 2 code

Slide 7

In lecture 2 we created IChatClient right inside the Controller, so that our attention stayed on the model:

Controllers/AiLabController.cs · lecture 2
public AiLabController(IConfiguration config){    _chat = new Client(apiKey: config["Gemini:ApiKey"])        .AsIChatClient("gemini-3.8-flash");}

It works, but it has three problems:

Problem Why it's bad
♻️ A new client on every request ASP.NET Core creates a Controller anew for every request. The _chat field is created with it — a new client and a new HTTP connection every time. On a server that's a waste of resources
📌 The model name is in the code To switch to another model you have to change the code and deploy again
🧪 It can't be tested The Controller creates the Gemini client itself. In a test we can't plug in a fake client — every test would call the real Gemini and spend money

You already know this from the API course: we don't create a DbContext with new in a Controller — we register it in DI and receive it through the constructor. The same rule applies to IChatClient.

Program.cs: AddChatClient

Slide 8

We create IChatClient once, when the application starts, and register it in DI:

Program.cs
using Google.GenAI;using Microsoft.Extensions.AI; var builder = WebApplication.CreateBuilder(args); string apiKey = builder.Configuration["Gemini:ApiKey"]    ?? throw new InvalidOperationException("Gemini:ApiKey is missing");string model = builder.Configuration["Gemini:Model"]    ?? throw new InvalidOperationException("Gemini:Model is missing"); builder.Services.AddChatClient(    new Client(apiKey: apiKey).AsIChatClient(model)); builder.Services.AddControllers();// ... the rest — as it was
  • AddChatClient(...) — an extension from Microsoft.Extensions.AI. It registers IChatClient as a Singleton: one client for the whole application, one pool of HTTP connections. The Gemini client is thread-safe, so it serves concurrent requests without problems.
  • new Client(apiKey: apiKey) — the same line that was in the lecture 2 Controller, but now it runs once, when the app starts.
  • ?? throw — if the key or the model is missing, the application fails right at startup with a clear error, not on the first request with a strange 401.

The model name goes in appsettings.json. It isn't a secret, it goes to Git too:

appsettings.json
{  "Gemini": {    "Model": "gemini-3.8-flash"  }}

The key is already in User Secrets — we put it there in lecture 2 as Gemini:ApiKey. In secrets.json it looks like this (VS → right-click the project → Manage User Secrets):

secrets.json
{  "Gemini": {    "ApiKey": "AIza..."  }}

Both files hold one section — Gemini: Model in appsettings.json (not a secret, goes to Git), ApiKey in secrets.json (a secret, stored outside the project). IConfiguration merges them into one section.

If you haven't set the key yet — in the terminal, in the project folder:

bash
dotnet user-secrets initdotnet user-secrets set "Gemini:ApiKey" "AIza..."

builder.Configuration["Gemini:ApiKey"] reads from both places the same way — the code doesn't know where the value is written.

💡

User Secrets don't exist on a server — there the same value comes from an environment variable: Gemini__ApiKey (two underscores = :). The code doesn't change. We'll see this in DevOps, at deploy time.

📘 Terms
AddChatClient
the Microsoft.Extensions.AI method that registers IChatClient in DI (Singleton by default)
User Secrets
configuration for secrets stored on the developer's computer, outside the project; it never goes to Git

Controller: constructor injection

Slide 9

In AiLabController only the way we get the client changes: the constructor takes IChatClient directly instead of IConfiguration. The field name stays the same — _chat, so we don't touch the lecture 2 endpoints (ask, assistant, review-sentiment):

Controllers/AiLabController.cs
[ApiController][Route("api/ai-lab")]public class AiLabController : ControllerBase{    private readonly IChatClient _chat;     public AiLabController(IChatClient chat)    {        _chat = chat;    }     // ask, assistant, review-sentiment — unchanged}

We no longer need using Google.GenAI; in the Controller — the Controller no longer knows it works with Gemini. It knows only IChatClient.

Check: Swagger → POST /api/ai-lab/ask → the answer still comes back.

What changes where now:

I want I change
Another Gemini model only appsettings.json — "Model"
Another provider (OpenAI, Ollama…) only Program.cs — the line that creates the client (and the matching package)
A fake client in a test the test itself passes its own IChatClient to the Controller

None of the three touches the Controller.

Chapter 2 · ~3 min read

Structured output: a C# type instead of text

🎯 After this You'll get an enum from the model with GetResponseAsync<T> and understand why it's more reliable than few-shot.

Part 2 · Structured output

Slide 10

In lecture 2 we used few-shot to make the model return the exact word almost every time. “Almost” isn't enough for code. Structured output doesn't ask the model to “answer with one word” — it asks it to “answer in exactly the shape of this C# type”.

few-shot: “almost” always

Slide 11

In the homework you wrote a classify endpoint with few-shot. It mostly returns the exact word, but sometimes — Search., search or a whole sentence. All of it is a string, and if (label == "Search") fails on them.

Few-shot asks the model for a shape: we show it with examples, and the model repeats it with some probability. Probability ≠ a guarantee (lecture 1).

The idea: what if the answer were not a string but a C# enum?

csharp
public enum RequestType { Search, Reserve, Question }

"Search." can't get into a variable of type RequestType — only one of the three values can. That's exactly what structured output does: it forces the shape on the model instead of asking for it.

GetResponseAsync<T>: an enum

Slide 12

The lecture 2 ReviewSentiment worked with few-shot. Now we write the same endpoint with an enum:

Controllers/AiLabController.cs · ReviewSentiment
public enum Sentiment { Positive, Negative, Mixed } [HttpPost("review-sentiment")]public async Task<IActionResult> ReviewSentiment(AskRequest request){    List<ChatMessage> messages =    [        new(ChatRole.System, "Classify the restaurant review."),        new(ChatRole.User, request.Prompt)    ];     ChatResponse<Sentiment> response =        await _chat.GetResponseAsync<Sentiment>(messages);     Sentiment sentiment = response.Result;    if (sentiment == Sentiment.Negative) { /* notify the manager */ }     return Ok(sentiment.ToString());}

Line by line:

  • enum Sentiment — the list of allowed answers. The model can't return anything outside it. You can move the enum to its own file.
  • The system prompt gets shorter. “Answer with only one word: Positive, Negative or Mixed” and the few-shot examples are no longer needed for the shape — the type defines the shape. Less text = fewer input tokens.
  • GetResponseAsync<Sentiment>(messages) — the same GetResponseAsync, but with a type. It returns a ChatResponse<Sentiment>: a normal ChatResponse (Text, Usage, FinishReason) plus Result.
  • response.Result — already a Sentiment, not a string. if (sentiment == Sentiment.Negative) always works correctly.
  • sentiment.ToString() — by default ASP.NET Core returns an enum in JSON as a number (Mixed → 2). ToString() gives us the name.
👉

Few-shot examples are still useful for content: for example, if you want the model to understand exactly what you mean by Mixed. For the shape you don't need them anymore — the type protects the shape.

What happens inside GetResponseAsync<T>

Slide 13

There are four steps in one line:

  1. C# type → JSON Schema. Microsoft.Extensions.AI generates a JSON Schema from the type (Sentiment) — a description of the shape: “the answer is an object with one field whose value is one of these three”.
  2. The schema goes into the request. The schema is put into ChatOptions.ResponseFormat and sent to Gemini with the request. We don't write it in the prompt.
  3. The model follows the schema. Gemini writes the answer so that it matches the schema: at every step it chooses only among tokens that don't break the schema. That's why "Search." or a paragraph simply can't appear.
  4. JSON → C#. The answer ({"data":"Mixed"}) is turned into a C# object with System.Text.Json — response.Result.
💡

Why "data"? At the top level of JSON, models return only an object. An enum, a number or a list isn't an object — so Microsoft.Extensions.AI automatically “wraps” it in {"data": …} and unwraps it again itself. This doesn't happen for an object (e.g. a record).

📘 Terms
structured output
a model answer in a predefined shape (JSON Schema) that the code reads as a C# type
JSON Schema
a description of the shape of JSON: which fields, of which types, which values are allowed
ChatResponse
the response of GetResponseAsync: a normal ChatResponse + Result (an object of type T)

Chapter 3 · ~3 min read

Text → object: a record with several fields

🎯 After this You'll extract an object with several fields from a user's text and check that the values are correct.

Part 3 · Text → object

Slide 15

An enum is one value. In real tasks we need several pieces of data from text: a date, a count, a name. Structured output does this too — T can be a record with several fields. This is how a user's free text reaches our existing logic.

BookingRequest: an object with several fields

Slide 16

A user writes: “there are four of us, tomorrow at 8”. The booking logic needs a DateTime and an int. Structured output is the bridge between the two:

Controllers/AiLabController.cs · ParseBooking
public record BookingRequest(    [property: Description("Booking date and time")] DateTime? At,    [property: Description("Number of guests")] int? Guests); [HttpPost("parse-booking")]public async Task<IActionResult> ParseBooking(AskRequest request){    List<ChatMessage> messages =    [        new(ChatRole.System, $"""            Extract the booking details from the user's text.            Today is {DateTime.Now:yyyy-MM-dd, dddd}.            Leave null whatever is not in the text.            """),        new(ChatRole.User, request.Prompt)    ];     ChatResponse<BookingRequest> response =        await _chat.GetResponseAsync<BookingRequest>(messages);    return Ok(response.Result);}

For Description, at the top of the file: using System.ComponentModel;

Three important details:

  1. Today's date in the prompt. The model doesn't know what today's date is: it's stateless and its knowledge stops at its training date (lecture 1). For it to understand “tomorrow”, we give it the date — with the lecture 2 prompt template ($"""…{…}…""").
  2. Nullable fields (DateTime?, int?). ? tells the model: “you might not know this”. Without ? the model is forced to write something — and it will make it up. The prompt line “leave null whatever is not in the text” reinforces the same thing.
  3. [property: Description(...)] — the description goes into the schema and explains the field's meaning to the model. property: is needed because on a record parameter the attribute has to be applied to the property.
👉

Google's recommendation: don't repeat the schema in the prompt (e.g. “return JSON with fields at and guests”) — it's sent with the request anyway, and repeating it lowers the quality. In the prompt write what to extract and by which rules.

The shape is guaranteed, the content is not

Slide 17

One endpoint, three texts. Every time a BookingRequest comes back — the shape is always correct. The content is a different matter:

Text Result What to notice
“there are four of us, tomorrow at 8” at: …T08:00, guests: 4 “8” is ambiguous. The model may pick 8 in the morning, but the restaurant opens at 12:00
“I'd like a table on Saturday evening” at: …T19:00, guests: null The number of guests isn't written → null (it didn't make it up). “Evening” → 19:00, though, is the model's guess
“how much is khinkali?” at: null, guests: null There's no booking — the shape is still correct, everything is null

Your exact result may differ — the model works with probabilities.

Conclusion: structured output guarantees that the answer is of our type. It doesn't guarantee that the values are correct. So before the object goes into our logic (the database), C# checks it:

csharp
BookingRequest b = response.Result; if (b.At is null) return BadRequest("Which day and what time?");if (b.Guests is null) return BadRequest("How many of you?");if (b.At.Value.Hour < 12 || b.At.Value.Hour >= 23)    return BadRequest("We're open 12:00–23:00"); // from here — your existing booking logic

It's the same rule as in lecture 2: the prompt and the model change the probability; what must hold, C# checks.

Classwork: an object from text in your project

Classwork: Text to object — in your project

Slide 18

Your project or RestaurantApi · with code · in Swagger

Steps

  • 1 · DI — if you haven't done it yet: AddChatClient in Program.cs, the key in User Secrets, AiLabController — through the constructor
  • 2 · Your type — a record with at least 3 fields for text in your project; one field is an enum, optional fields are nullable (?)
  • 3 · An endpoint POST /api/ai-lab/extract — System: what to extract and “leave null whatever is not in the text” → GetResponseAsync<your type> → Ok(response.Result)
  • 4 · 3 texts in Swagger: complete · partial (something is missing) · off-topic

✓ Done when

All three texts return your type; whatever isn't in the text is null, not made up; the enum field contains only values from your list

⭐ Bonus

  • Add [property: Description("...")] to the fields — did the result change on an ambiguous text?
  • Check the result in the endpoint with C#: a required field is null → BadRequest with a question (“which day?”)

💡 If you're stuck

  • Ideas: library — “hold The Gadfly for me until Monday” → { Title, Until, Action: Reserve } · gym — “two of us will come to yoga tomorrow at 7” → { Class, At, People } · shop — “a red T-shirt, size M, two of them” → { Product, Size, Color, Quantity }
  • Got a date among your fields? Add Today is {DateTime.Now:yyyy-MM-dd, dddd}. to the system prompt — otherwise it can't understand “tomorrow”
  • The enum shows up as a number in Swagger? That's normal — ASP.NET Core returns enums as numbers. For the name: in Program.cs, AddControllers().AddJsonOptions(o => o.JsonSerializerOptions.Converters.Add(new JsonStringEnumConverter()))
  • InvalidOperationException on .Result? Check that you haven't set MaxOutputTokens to a small number — thinking eats the limit (lecture 2)

Summary

Slide 20
  • AddChatClient — IChatClient is created once in Program.cs and registered in DI as a Singleton. The Controller receives it through its constructor. The key — in User Secrets, the model name — in appsettings.json.
  • Changing the provider — only Program.cs; changing the model — only appsettings.json. Neither touches the Controller.
  • GetResponseAsync<T> — a JSON Schema is created from the C# type, sent with the request, the model follows the schema, and the answer in response.Result is already of type T.
  • enum — one value from an allowed list (classification). record — several fields from text (extraction).
  • Nullable fields (DateTime?, int?) and “leave null whatever is not in the text” in the prompt — let the model not make things up.
  • The shape is guaranteed, the content is not. C# checks the object before it reaches the database.
