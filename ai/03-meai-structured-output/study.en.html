Microsoft.Extensions.AI: DI and Structured Output

🎯 After this lecture you can

  • Register IChatClient in DI with AddChatClient: the key in User Secrets, the model in appsettings.json
  • Get an enum with GetResponseAsync<T> and explain why it's more reliable than few-shot
  • Extract an object from text with a record: nullable fields, Description, today's date in the prompt
  • Explain why the shape is guaranteed but the content is not, and check the received object in C#

⚡ Key points

  1. IChatClient is created once in Program.cs (AddChatClient) and registered in DI as a Singleton. The controller receives it through the constructor, like a DbContext.
  2. The key lives in User Secrets, the model name in appsettings.json. Switching models is a configuration change.
  3. GetResponseAsync<T> → ChatResponse<T> → .Result is already a C# type.
  4. Few-shot asks for a format; structured output enforces it: the schema travels with the request.
  5. Nullable fields and "leave null" so the model does not invent values. The form is guaranteed, the content is not: C# checks the object before it reaches the database.

IChatClient in DI

▶ Slides 6–9

In lecture 2 we created IChatClient in the controller with new. That has three problems: a new client on every request, the model name in code, and the controller creating its own dependency. We use the same pattern as for DbContext in the API course:

Program.cs
using Google.GenAI;using Microsoft.Extensions.AI; var builder = WebApplication.CreateBuilder(args); string apiKey = builder.Configuration["Gemini:ApiKey"]    ?? throw new InvalidOperationException("Gemini:ApiKey is missing");string model = builder.Configuration["Gemini:Model"]    ?? throw new InvalidOperationException("Gemini:Model is missing"); builder.Services.AddChatClient(    new Client(apiKey: apiKey).AsIChatClient(model)); builder.Services.AddControllers();// ... the rest — as it was
appsettings.json
{  "Gemini": {    "Model": "gemini-3.8-flash"  }}

The controller receives the client through its constructor. The field name stays the same (_chat), so the rest of the code does not change:

Controllers/AssistantController.cs
[ApiController][Route("api/assistant")]public class AssistantController : ControllerBase{    private readonly IChatClient _chat;     public AssistantController(IChatClient chat)    {        _chat = chat;    }     // chat — unchanged (the same change in AiDiagnostics and Feedback)}
💡

There are no User Secrets on a server: the same value comes from an environment variable, Gemini__ApiKey (two underscores = :). The code does not change.

✅ Check yourself think first, then open the answer
If we wanted OpenAI instead of Gemini, which file would we change?
Only Program.cs (creating the client and the package). For another Gemini model, only appsettings.json.
📘 Terms
AddChatClient
registers IChatClient in DI (Singleton by default)
User Secrets

Structured output: enum

▶ Slides 10–13

Few-shot returns the exact word "almost" always, but sometimes you get Search. or search, and the if fails. "Almost" is not enough for code.

Structured output: we write the answer type in C#, and the model cannot write anything outside it:

Dtos/Feedback/SentimentDtos.cs
public enum Sentiment { Positive, Negative, Mixed }
Controllers/FeedbackController.cs · AnalyzeSentiment
[HttpPost("sentiment")]public async Task<IActionResult> AnalyzeSentiment(SentimentRequest request){    List<ChatMessage> messages =    [        new(ChatRole.System, "Classify the guest's review of the restaurant."),        new(ChatRole.User, request.Text)    ];     ChatResponse<Sentiment> response =        await _chat.GetResponseAsync<Sentiment>(messages);     Sentiment sentiment = response.Result;    if (sentiment == Sentiment.Negative) { /* notify the manager */ }     return Ok(new SentimentResponse(sentiment.ToString()));}

Inside there are four steps: C# type → JSON Schema → the schema goes to Gemini with the request → the answer is read as a C# object (.Result).

💡

An enum, a number or a list is not a JSON object, so the answer comes wrapped: {"data": "Positive"}. .Result unwraps it for you.

✅ Check yourself think first, then open the answer
What does the schema change in how the model picks tokens?
It restricts them: tokens outside the schema can no longer be picked. Whether the value is correct still depends on probability.
📘 Terms
structured output
a model answer in a predefined shape (JSON Schema) that code reads as a C# type
JSON Schema
a description of a JSON shape: which fields and of which types

Text → object

▶ Slides 15–17

The user writes "There are four of us, tomorrow at 8", but a booking needs a DateTime and an int. Structured output bridges the two:

Dtos/Bookings/BookingParseDtos.cs
using System.ComponentModel; public record BookingParseRequest(string Text); public record BookingDetails(    [property: Description("Booking date and time")] DateTime? At,    [property: Description("Number of guests")] int? Guests);
Controllers/BookingsController.cs · Parse
[HttpPost("parse")]public async Task<IActionResult> Parse(BookingParseRequest request){    List<ChatMessage> messages =    [        new(ChatRole.System, $"""            Extract the booking details from the guest's message.            Today is {DateTime.Now:yyyy-MM-dd, dddd}.            Leave null whatever is not in the message.            """),        new(ChatRole.User, request.Text)    ];     ChatResponse<BookingDetails> response =        await _chat.GetResponseAsync<BookingDetails>(messages);    return Ok(response.Result);}
  • Nullable fields (?): if the text does not say it, the model leaves null instead of inventing a value.
  • Today's date in the prompt: the model does not know today's date, so it cannot work out "tomorrow" on its own.
  • Description explains the meaning of a field to the model.

The form is guaranteed, the content is not. "At 8" may become 08:00, and for "khinkali" every field will be null. So C# checks:

csharp
BookingDetails b = response.Result; if (b.At is null) return BadRequest("Which day and what time?");if (b.Guests is null) return BadRequest("How many of you?");if (b.At.Value.Hour < 12 || b.At.Value.Hour >= 23)    return BadRequest("We're open 12:00–23:00"); // from here — your existing booking logic
✅ Check yourself think first, then open the answer
Why int? Guests and not int?
An int cannot be empty, so if the text does not give a number, the model invents one. null means "not said".
We got a BookingDetails. Can we write it straight to the database?
No. First we check it in C# (nulls, a past date, the size), because the content may be wrong.

💡 If you're stuck

  • Ideas: library — “hold The Gadfly for me until Monday” → { Title, Until, Action: Reserve } · gym — “two of us will come to yoga tomorrow at 7” → { Class, At, People } · shop — “a red T-shirt, size M, two of them” → { Product, Size, Color, Quantity }
  • Got a date among your fields? Add Today is {DateTime.Now:yyyy-MM-dd, dddd}. to the system prompt — otherwise it can't understand “tomorrow”
  • The enum shows up as a number in Swagger? That's normal — ASP.NET Core returns enums as numbers. For the name: in Program.cs, AddControllers().AddJsonOptions(o => o.JsonSerializerOptions.Converters.Add(new JsonStringEnumConverter()))
  • InvalidOperationException on .Result? Check that you haven't set MaxOutputTokens to a small number — thinking eats the limit (lecture 2)

Why is it bad to create IChatClient with new in a Controller field?
ASP.NET Core creates the Controller anew for every request. Besides, the model name is in the code and we can't plug a fake client into a test. Review · slide 7
2
With what lifetime does AddChatClient register IChatClient by default?
The client holds HTTP connections and is thread-safe, so one is enough for the whole application. Review · slide 8
3
We want OpenAI instead of Gemini. Which file changes?
The Controllers know only IChatClient. The provider is created in one place — Program.cs. Switching to another Gemini model is only appsettings.json. Review · slide 9
4
The few-shot classify sometimes returns Search.. Why doesn't this happen with GetResponseAsync<RequestType>?
Few-shot asks for a shape, structured output forces it. The allowed values are in the schema, and the model chooses only among them. Review · slide 11
5
The endpoint returns Ok(response.Result) where Result = Sentiment.Mixed. What do we see in Swagger?
That's why on the slide we return sentiment.ToString(). The alternative is JsonStringEnumConverter in Program.cs. Review · slide 12
6
“There are four of us, tomorrow at 8” — why do we write Today is {DateTime.Now:…} in the system prompt?
The model is stateless and its knowledge stops at its training date. Today's date is context we provide — with the lecture 2 prompt template. Review · slide 16
7
Structured output returned a BookingDetails. What is guaranteed?
The shape is guaranteed, the content is not: “at 8” may become 08:00, a field may be null. C# checks before the database. Review · slide 17
8
In a structured output prompt, is it better to write “return JSON with fields at and guests”?
Google recommends not repeating the schema in the prompt — it lowers quality. The schema sets the shape, the prompt sets the rules (e.g. “leave null whatever is not in the text”). Review · slide 16
