Today's topic

Structured Output: the AI's answer as a C# type

🤔Why you need this

In lecture 2 the model's answer was free text — “almost” exact with a prompt (even with few-shot). But “almost” isn't enough for code: if (label == "Negative") needs the exact value. Today we force the model to return a C# type instead of text: an enum or an object that goes straight into our logic. This is the bridge between a user's free text and our code.

🎯By the end of the lecture you can

  • Drive code with a typed answer (Negative → notify the manager) and tell response.Resultfrom response.Textapart
  • GetResponseAsync<T> — get an enum and explain why it's more reliable than a prompt (even with examples)
  • Extract an object from text with a record: nullable fields, Description, today's date in the prompt
  • Explain why the shape is guaranteed but the content is not, and check the received object in C#

5 questions

1Why do we return response.Result.ToString()and not response.Text?Text is the model's raw JSON: {"data": "Negative"} · the typed value lives only in Result· ToString() → "Negative", so the API client doesn't get a number (1)
