Microsoft.Extensions.AI: DI და Structured Output

🎯 ამ ლექციის შემდეგ შეძლებ

  • IChatClient-ის რეგისტრაცია DI-ში AddChatClient-ით: key — User Secrets-ში, მოდელი — appsettings.json-ში
  • GetResponseAsync<T>-ით enum-ის მიღება და ახსნა, რატომ არის ეს few-shot-ზე საიმედო
  • ტექსტიდან ობიექტის ამოღება record-ით: nullable ველები, Description, დღევანდელი თარიღი prompt-ში
  • ახსნა, რატომ არის ფორმა გარანტირებული და შინაარსი — არა, და მიღებული ობიექტის შემოწმება C#-ში

⚡ მთავარი

  1. IChatClient ერთხელ იქმნება Program.cs-ში (AddChatClient) და DI-ში Singleton-ად რეგისტრირდება. Controller მას constructor-ით იღებს, როგორც DbContext-ს.
  2. key User Secrets-შია, მოდელის სახელი appsettings.json-ში. მოდელის შეცვლა კონფიგურაციის შეცვლაა.
  3. GetResponseAsync<T> → ChatResponse<T> → .Result უკვე C# ტიპია.
  4. few-shot ფორმას სთხოვს, structured output კი აიძულებს: სქემა მოთხოვნასთან ერთად მიდის.
  5. nullable ველები და „დატოვე null“, რომ მოდელმა არ მოიგონოს. ფორმა გარანტირებულია, შინაარსი არა: ობიექტს ბაზაში ჩაწერამდე C# ამოწმებს.

Structured output: enum

▶ სლაიდები 10–13

few-shot „თითქმის“ ყოველთვის აბრუნებს ზუსტ სიტყვას, მაგრამ ხანდახან მოდის Search. ან search, და if ჩავარდება. „თითქმის“ კოდისთვის საკმარისი არ არის.

Structured output: პასუხის ტიპს C#-ში ვწერთ, და მოდელი მის გარეთ ვერაფერს დაწერს:

Controllers/AiLabController.cs · ReviewSentiment
public enum Sentiment { Positive, Negative, Mixed } [HttpPost("review-sentiment")]public async Task<IActionResult> ReviewSentiment(AskRequest request){    List<ChatMessage> messages =    [        new(ChatRole.System, "Classify the restaurant review."),        new(ChatRole.User, request.Prompt)    ];     ChatResponse<Sentiment> response =        await _chat.GetResponseAsync<Sentiment>(messages);     Sentiment sentiment = response.Result;    if (sentiment == Sentiment.Negative) { /* notify the manager */ }     return Ok(sentiment.ToString());}

შიგნით ოთხი ნაბიჯია: C# ტიპი → JSON Schema → სქემა მიდის Gemini-სთან მოთხოვნასთან ერთად → პასუხი C# ობიექტად იკითხება (.Result).

💡

enum, რიცხვი ან სია JSON ობიექტი არ არის, ამიტომ პასუხი wrapper-შია: {"data": "Positive"}. .Result მას თვითონ ამოიღებს.

ტექსტი → ობიექტი

▶ სლაიდები 15–17

მომხმარებელი წერს "There are four of us, tomorrow at 8", ჯავშანს კი DateTime და int სჭირდება. structured output ამ ორს შორის ხიდია:

  • nullable ველები (?): თუ ტექსტში არ წერია, მოდელი null-ს დატოვებს და არ მოიგონებს.
  • დღევანდელი თარიღი prompt-ში: მოდელმა არ იცის, დღეს რა რიცხვია, ამიტომ „ხვალ“ ვერ გამოითვლის.
  • Description მოდელს ველის მნიშვნელობას უხსნის.

ფორმა გარანტირებულია, შინაარსი არა. „8-ზე“ შეიძლება 08:00 გახდეს, „ხინკალი“-ზე კი ყველა ველი null იქნება. ამიტომ C# ამოწმებს:

მივიღეთ BookingRequest. შეიძლება პირდაპირ ბაზაში ჩავწეროთ?
არა. ჯერ C#-ში ვამოწმებთ (null, წარსული თარიღი, ზომა), რადგან შინაარსი შეიძლება არასწორი იყოს.
