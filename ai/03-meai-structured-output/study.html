Microsoft.Extensions.AI: DI და Structured Output

ლექციის სრული მასალა თავებად, ~15 წუთი კითხვა. შენი პროგრესი ბრაუზერში ინახება. ეს გვერდი პრეზენტაციას მიჰყვება: სლაიდის შეცვლისას შესაბამისი ნაწილი მოინიშნება.

⚡ 5 წუთში

თუ მხოლოდ ეს დაგამახსოვრდა, ლექციის მთავარი იცი:

  1. AddChatClient — IChatClient ერთხელ იქმნება Program.cs-ში და DI-ში Singleton-ად რეგისტრირდება. Controller მას constructor-ით იღებს — როგორც DbContext-ს API კურსზე.
  2. key — User Secrets-ში (dotnet user-secrets set "Gemini:ApiKey" "..."), მოდელი — appsettings.json-ში. სხვა მოდელი = მხოლოდ კონფიგურაცია, სხვა პროვაიდერი = მხოლოდ Program.cs.
  3. GetResponseAsync<T> — C# ტიპიდან JSON Schema იქმნება, მოთხოვნასთან მიდის, მოდელი სქემის გარეთ ვერ წერს. response.Result უკვე T-ია.
  4. enum — ერთი მნიშვნელობა სიიდან (კლასიფიკაცია); record — რამდენიმე ველი ტექსტიდან (ამოღება). nullable ველები და „დატოვე null“ — რომ არ მოიგონოს; დღევანდელი თარიღი — prompt-ში.
  5. ფორმა გარანტირებულია, შინაარსი — არა. მიღებულ ობიექტს ბაზამდე C# ამოწმებს.

  • AddChatClient(...) — Microsoft.Extensions.AI-ის extension. IChatClient-ს არეგისტრირებს Singleton-ად: მთელ აპლიკაციაზე ერთი client, ერთი HTTP კავშირების pool. Gemini-ს client thread-safe-ია, ამიტომ ერთდროულ მოთხოვნებს უპრობლემოდ ემსახურება.
  • new Client(apiKey: apiKey) — იგივე ხაზი, რაც ლექცია 2-ის Controller-ში იყო, ოღონდ ახლა ერთხელ სრულდება, აპლიკაციის გაშვებისას.
  • ?? throw — თუ key ან მოდელი არ წერია, აპლიკაცია გაშვებისთანავე ჩავარდება გასაგები შეცდომით, და არა პირველ მოთხოვნაზე, უცნაური 401-ით.

მოდელის სახელი — appsettings.json-ში. ეს საიდუმლო არ არის, Git-შიც მიდის:

secrets.json

ორივე ფაილში ერთი სექციაა — Gemini: appsettings.json-ში Model (საიდუმლო არ არის, Git-ში მიდის), secrets.json-ში ApiKey (საიდუმლოა, პროექტის გარეთ ინახება). IConfiguration ორივეს ერთ სექციად აერთიანებს.

თუ key ჯერ არ ჩაგიწერია — ტერმინალში, პროექტის საქაღალდეში:

საშინაოში classify endpoint few-shot-ით დაწერე. უმეტესად ზუსტ სიტყვას აბრუნებს, მაგრამ ხანდახან — Search., search ან მთელ წინადადებას. ეს ყველაფერი string-ია, და if (label == "Search") მათზე ჩავარდება.

იდეა: რა იქნება, თუ პასუხი string კი არა, C# enum იქნება?

  • System prompt მოკლდება. „უპასუხე მხოლოდ ერთი სიტყვით: Positive, Negative ან Mixed“ და few-shot მაგალითები ფორმისთვის აღარ გვჭირდება — ფორმას ტიპი განსაზღვრავს. ნაკლები ტექსტი = ნაკლები input ტოკენი.

  • response.Result — უკვე Sentiment, არა string. if (sentiment == Sentiment.Negative) ყოველთვის სწორად მუშაობს.
  • sentiment.ToString() — ASP.NET Core enum-ს JSON-ში ნაგულისხმევად რიცხვად აბრუნებს (Mixed → 2). ToString() სახელს გვიბრუნებს.

რა ხდება GetResponseAsync<T>-ის შიგნით

სლაიდი 13

ერთ ხაზში ოთხი ნაბიჯია:

  1. C# ტიპი → JSON Schema. Microsoft.Extensions.AI ტიპიდან (Sentiment) აგენერირებს JSON Schema-ს — ფორმის აღწერას: „პასუხი ობიექტია ერთი ველით, რომლის მნიშვნელობა ამ სამიდან ერთია“.
  2. სქემა მოთხოვნაში. სქემა ChatOptions.ResponseFormat-ში ჯდება და Gemini-ს მოთხოვნასთან ერთად მიდის. prompt-ში ამას ჩვენ არ ვწერთ.
  3. მოდელი სქემას მისდევს. Gemini პასუხს წერს ისე, რომ ის სქემას ემთხვეოდეს: ყოველ ნაბიჯზე მხოლოდ იმ ტოკენებს შორის ირჩევს, რომლებიც სქემას არ არღვევს. ამიტომ "Search." ან აბზაცი უბრალოდ ვერ გაჩნდება.
  4. JSON → C#. პასუხი ({"data":"Mixed"}) System.Text.Json-ით C# ობიექტად იქცევა — response.Result.
💡

რატომ "data"? მოდელები JSON-ში ზედა დონეზე მხოლოდ ობიექტს აბრუნებენ. enum, რიცხვი ან სია ობიექტი არ არის — ამიტომ Microsoft.Extensions.AI მას ავტომატურად {"data": …}-ში „ახვევს“ და მერე თვითონვე ხსნის. ობიექტზე (მაგ. record) ეს არ ხდება.

სამი მნიშვნელოვანი დეტალი:

  1. დღევანდელი თარიღი prompt-ში. მოდელმა არ იცის, დღეს რა რიცხვია: ის stateless-ია და მისი ცოდნა ვარჯიშის დღეზე ჩერდება (ლექცია 1). „ხვალ“ რომ გაიგოს, თარიღს ჩვენ ვაწვდით — ლექცია 2-ის prompt შაბლონით ($"""…{…}…""").
  2. Nullable ველები (DateTime?, int?). ? მოდელს ეუბნება: „ეს შეიძლება არ იცოდე“. ?-ის გარეშე მოდელი იძულებულია რაიმე დაწეროს — და მოიგონებს. prompt-ის ხაზი „რაც არ წერია, დატოვე null“ იგივეს ამყარებს.
  3. [property: Description(...)] — აღწერა სქემაში ჯდება და მოდელს ველის მნიშვნელობას უხსნის. property: საჭიროა, რადგან record-ის პარამეტრზე ატრიბუტი თვისებას (property) უნდა მიეწეროს.
