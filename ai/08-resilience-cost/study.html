Error Handling, Resilience და ხარჯის კონტროლი

🎯 ამ ლექციის შემდეგ შეძლებ

  • შეცდომას დროებითად, მუდმივად ან შინაარსის შეცდომად დაალაგებ და ახსნი, რომელზე შველის retry
  • AddStandardResilienceHandler-ით HttpClient-ს retry-ს, timeout-ს და circuit breaker-ს დაუმატებ, Google.GenAI-ს ამ client-ს მისცემ და მის საკუთარ retry-ს გამორთავ
  • დაწერ FallbackChatClient-ს, რომელიც დროებით შეცდომაზე სარეზერვო მოდელს იძახებს
  • ყოველი გამოძახების ტოკენებს ბაზაში ჩაწერ (IServiceScopeFactory) და დღის ხარჯს დაითვლი

⚡ მთავარი

  1. შეცდომები სამ ჯგუფადაა: დროებითი (429, 5xx, timeout: retry შველის), მუდმივი (400, 401, 403, 404: არა), შინაარსის (length, ცუდი JSON: კოდში ვამოწმებთ).
  2. სწორი retry: backoff + jitter, Retry-After, timeout და circuit breaker.
  3. AddStandardResilienceHandler HttpClient-ზე. SDK-ის საკუთარი retry გამორთულია: retry ერთ ადგილასაა.
  4. FallbackChatClient სხვა მოდელზე მხოლოდ დროებით შეცდომაზე გადადის და ყველაზე შიგნით დგას.
  5. ტოკენებს ბაზაში ვწერთ. Singleton ფენაში Scoped DbContext-ს IServiceScopeFactory-ით ვიღებთ.

2

retry და timeout

▶ სლაიდები 9–12

„ჩავარდა? მაშინვე თავიდან, 10-ჯერ“ პრობლემას აუარესებს: Gemini უკვე გადატვირთულია. სწორი retry:

  • backoff: პაუზა ყოველ ცდაზე იზრდება (1 წმ, 2 წმ, 4 წმ)
  • jitter: პაუზას შემთხვევითი ნაწილი ემატება, რომ ყველა კლიენტი ერთდროულად არ დაბრუნდეს
  • Retry-After: თუ სერვერმა თქვა, რამდენ ხანს დაველოდოთ, ვუსმენთ
  • circuit breaker: ბევრი ჩავარდნის შემდეგ ცოტა ხნით აღარ ვცდით

Microsoft.Extensions.Http.Resilience ამას HttpClient-ზე ერთი ხაზით ამატებს. Google.GenAI-ს თავისი retry აქვს, ამიტომ მას ვთიშავთ, რომ retry-ები ერთმანეთში არ ჩაჯდეს:

fallback და ხარჯი

▶ სლაიდები 14–16

თუ მოდელი 5 წუთია გადატვირთულია, სამი retry-ც ჩავარდება. მაშინ სხვა მოდელზე გადავდივართ. ფენა შეცდომას იჭერს, ოღონდ მხოლოდ დროებითს:

Ai/FallbackChatClient.cs
public class FallbackChatClient : DelegatingChatClient{    private readonly IChatClient _fallback;    private readonly ILogger<FallbackChatClient> _logger;     public FallbackChatClient(IChatClient inner, IChatClient fallback,        ILogger<FallbackChatClient> logger) : base(inner)    {        _fallback = fallback;        _logger = logger;    }     public override async Task<ChatResponse> GetResponseAsync(        IEnumerable<ChatMessage> messages, ChatOptions? options = null,        CancellationToken cancellationToken = default)    {        try        {            return await base.GetResponseAsync(messages, options, cancellationToken);        }        catch (Exception ex) when (IsTransient(ex))        {            _logger.LogWarning("🛟 {Error} — fallback model", ex.Message);            return await _fallback.GetResponseAsync(messages, options, cancellationToken);        }    }     private static bool IsTransient(Exception ex) => ex switch    {        ApiException api => api.StatusCode is 429 or >= 500,        HttpRequestException or TimeoutRejectedException => true,        _ => false    };}
