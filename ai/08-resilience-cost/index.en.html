1Why doesn't the model remember the previous question, and how do we “remind” it?The model is stateless: it only sees this request · we send the history in every request — the memory is in our code, not in the model
2What goes into the context, and which part grows fastest?System + the tool descriptions + the history + the tool results + the new question · often the tool results (e.g. the whole menu), which stay in the history
3Why do we store the whole ChatMessage in jsonb and not a Text column?Contents has different types: text, functionCall, functionResult, the thought signature · AIJsonUtilities.DefaultOptions stores them with $type · jsonb reorders keys → AllowOutOfOrderMetadataProperties
4Why don't we store the System prompt in the database?It's ours, not part of the conversation: it has today's date in it and the rules may change · we build it again on every request and put it at the top of the list
5What does MessageCountingChatReducer(10) do, and what stays in the database?It keeps the last 10 messages in the context and drops the tool messages · everything stays in the database · the model gets the price again with a tool

Today's topic

Error Handling, Resilience and Cost Control

🤔Why you need this

Every question is one or more HTTP calls to Gemini, and Gemini sometimes fails: 429, 503, a timeout. Right now the user sees a 500 when that happens. Today we sort the errors (which ones we retry and which we don't), add retry and timeout with one package, a fallback model, and write the tokens of every call to the database, so we know what today cost. Without this an AI feature doesn't make it to production.

🎯By the end of the lecture you can

  • You'll sort an error as transient, permanent or a content error, and explain which ones retry helps with
  • You'll add retry, timeout and a circuit breaker to an HttpClient with AddStandardResilienceHandler, give that client to Google.GenAI and turn off its own retry
  • You'll write a FallbackChatClient that calls a fallback model on a transient error
  • You'll write the tokens of every call to the database (IServiceScopeFactory) and calculate the day's cost

🧯 The error map

Does trying again help — or not?

What happenedWhat it meansWhat we do
429A limit: too many requests per minutetransient wait (Retry-After) and try again
500 · 503Gemini is overloaded / an internal errortransient retry · didn't work → another model
timeoutNo answer comes · the networktransient a time limit + retry
400 · 401 · 403 · 404A wrong request · key · model namepermanent retry not — the code/configuration
length · bad JSONAn answer arrived, but it's cut off / wrongcontent in code: TryGetResult, MaxOutputTokens
tool exceptionOur C# method failedcontent FunctionInvocation returns the error to the model

02
🔁 Retry · how to try again properly

A growing pause, a random part added

503attempt 1
⏳ ~2 s
503attempt 2
⏳ ~4 s
200 ✓attempt 3
📈
exponential backoff2 → 4 → 8 s: we wait longer each time to let the overloaded service “rest”
🎲
jitterA random part is added to the pause: a thousand clients no longer “pounce” in the same second
⏰
Retry-After · timeoutOn a 429 the server tells us how long to wait. And each attempt has a time limit
🔌
circuit breakerIf many attempts in a row failed — for a while we don't call at all and say “no” right away
🙋 Why not just 10 times in a row, without a pause?
💡 We load an overloaded service even more and get a 429 — that's why backoff and jitter
