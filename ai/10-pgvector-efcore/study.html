PostgreSQL pgvector და EF Core

🎯 ამ ლექციის შემდეგ შეძლებ

  • ახსნი, რა არის ვექტორული ბაზა და რატომ ვიყენებთ PostgreSQL-ს pgvector-ით ცალკე ვექტორული ბაზის ნაცვლად
  • vector(768) სვეტს EF Core-ით დაამატებ (Pgvector.EntityFrameworkCore, UseVector, migration) და ვექტორებს ბაზაში ჩაწერ
  • სემანტიკურ ძებნას LINQ-ით დაწერ (CosineDistance) და ახსნი, რატომ არის distance = 1 − similarity
  • HNSW ინდექსს შექმნი, EXPLAIN-ით შეამოწმებ და ახსნი, რას ნიშნავს მიახლოებითი ძებნა და recall

⚡ მთავარი

  1. pgvector PostgreSQL-ს vector(768) სვეტს და მანძილის ოპერატორებს უმატებს. Docker-ში pgvector/pgvector, იმავე ვერსიით.
  2. <=> არის cosine distance = 1 − similarity. პატარა = ახლოს, ამიტომ ORDER BY ზრდადობით.
  3. EF Core: UseVector(), HasPostgresExtension("vector"), Vector? Embedding და EmbeddingModel.
  4. ძებნა: OrderBy(p => p.Embedding!.CosineDistance(q)).Take(3), დალაგება ბაზაში ხდება.
  5. HNSW ინდექსი მიახლოებითი და სწრაფია. ოპერატორი = ძებნის ფუნქცია. პატარა ცხრილზე seq scan ნორმალურია.

ვექტორი ბაზაში

▶ სლაიდები 6–8

ლექცია 9-ში ვექტორები მეხსიერებაში იყო. ამას სამი პრობლემა აქვს: რესტარტზე ქრება, ძებნა ყველა ვექტორს სათითაოდ ადარებს, და მონაცემი ორ ადგილასაა (ბაზაში კერძი, მეხსიერებაში ვექტორი).

ცალკე ვექტორული ბაზის ნაცვლად PostgreSQL-ს pgvector გაფართოებას ვუმატებთ. Docker-ში image იცვლება:

docker-compose.yml
services:  db:    image: pgvector/pgvector:pg17   # before: postgres:17 — keep the same version!
⚠️

ვერსია (pg17, pg16…) შენს ძველ image-ს უნდა ემთხვეოდეს, თორემ ძველ მონაცემებს ვერ წაიკითხავს.

ვექტორი ჩვეულებრივი სვეტია, ძებნა კი ORDER BY + LIMIT:

sql
CREATE EXTENSION IF NOT EXISTS vector;ALTER TABLE "Products" ADD COLUMN "Embedding" vector(768);
sql
SELECT "Name", "Embedding" <=> @q AS distanceFROM "Products"ORDER BY distanceLIMIT 3;

ლექცია 9-ში score 0.71 იყო. <=> რას დააბრუნებს?
0.29, რადგან distance = 1 − similarity.

▶ სლაიდები 9–11

[HttpPost("menu/index")]public async Task<IActionResult> IndexMenu(CancellationToken ct){    string model = _config["Gemini:EmbeddingModel"]!;     // only the dishes that have no vector, or have one from another model    List<Product> products = await _db.Products        .Where(p => p.Embedding == null || p.EmbeddingModel != model)        .ToListAsync(ct);     foreach (Product[] batch in products.Chunk(100))          // Gemini: up to 100 per request    {        var vectors = await _embeddings.GenerateAsync(            batch.Select(p => EmbeddingText.Document(p.Name, p.Description)),            cancellationToken: ct);         for (int i = 0; i < batch.Length; i++)        {            batch[i].Embedding = new Vector(vectors[i].Vector);  // ReadOnlyMemory<float> → Vector            batch[i].EmbeddingModel = model;        }    }     await _db.SaveChangesAsync(ct);    return Ok(new { Indexed = products.Count });}

ძებნა: CosineDistance SQL-ში <=> ოპერატორად ითარგმნება, და დალაგება ბაზაში ხდება:

Controllers/AiLabController.cs · menu/search
[HttpGet("menu/search")]public async Task<IActionResult> SearchMenu(string q, CancellationToken ct){    var query = new Vector(await _embeddings.GenerateVectorAsync(        EmbeddingText.Query(q), cancellationToken: ct));     var top = await _db.Products        .Where(p => p.Embedding != null)        .OrderBy(p => p.Embedding!.CosineDistance(query))       // → ORDER BY "Embedding" <=> @query        .Select(p => new { p.Name, Distance = p.Embedding!.CosineDistance(query) })        .Take(3)                                                  // → LIMIT 3        .ToListAsync(ct);     return Ok(top.Select(x => new { x.Name, Score = 1 - x.Distance }));   // distance → similarity}

ვექტორული ინდექსი

▶ სლაიდები 13–16

ინდექსის გარეშე ბაზა ყველა ხაზს კითხულობს (sequential scan): ზუსტია, მაგრამ მილიონ ჩანაწერზე ნელი. HNSW ინდექსი მიახლოებით ეძებს: სწრაფია, მაგრამ იშვიათად ერთ ახლოს მყოფს შეიძლება გამოტოვოს.

Data/DataContext.cs · OnModelCreating
modelBuilder.Entity<Product>()    .HasIndex(p => p.Embedding)    .HasMethod("hnsw")                       // the index type    .HasOperators("vector_cosine_ops");      // for which distance
bash
dotnet ef migrations add ProductEmbeddingIndexdotnet ef database update

რას შეასრულებს ბაზა, EXPLAIN აჩვენებს:

sql
SET enable_seqscan = off;   -- only for the test: we forbid the planner a seq scanEXPLAIN SELECT "Name" FROM "Products"ORDER BY "Embedding" <=> (SELECT "Embedding" FROM "Products" WHERE "Name" = 'Lobio in a clay pot')LIMIT 3;-- Limit -> Index Scan using "IX_Products_Embedding" on "Products"
💡

პატარა ცხრილზე EXPLAIN Seq Scan-ს აჩვენებს: ბაზისთვის ასე უფრო იაფია. ეს ნორმალურია.

⚠️

ოპერატორი (vector_cosine_ops) ძებნის ფუნქციას უნდა ემთხვეოდეს (CosineDistance), თორემ ინდექსი არ გამოიყენება.
