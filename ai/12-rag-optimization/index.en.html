Review · Lecture 11

Let's recall: Simple RAG: Answers from Documents

1Why don't we put the whole PDF into the context, and why don't we train the model (fine-tuning)?The whole PDF — thousands of tokens on every question, slow, a large document doesn't fit, “lost in the middle” · fine-tuning — expensive, again on every change, it memorizes facts badly and can't name the source
2What are RAG's two pipelines, and when does each one run?ingestion — once, on upload: PDF → text → parts → vectors → database · query — on every question: vector → top 5 → prompt → an answer with a source
3Why do we cut a document into parts, and what do we need the overlap for?The vector of a whole document is the “average” of everything — blurry; a part = one idea, a precise vector and a cheap context · the overlap — the last sentence in the next part too, so an idea isn't cut at the boundary
4Why do we need a threshold in RAG's search?A search always finds something · without a threshold, for “a borscht recipe” the model would get 5 meaningless parts and might make something up · with a threshold — 0 parts and “I don't have information”
5Why do we store the original question in the chat history and not the message with the sources (augmented)?The sources are only for this request — others will be found next time · storing them in the history would inflate every message with 5 parts (the budget, lecture 7)

Today's topic

RAG Optimization and Evaluation

🤔Why you need this

Lecture 11's RAG sometimes finds the wrong part — especially on exact words (“B-2”, “12%”). But “sometimes” isn't a number, and “I think it's better” doesn't count. In real teams every RAG change — chunking, the search method, the prompt — is proven by measurement. Today we measure (golden set, hit@k, MRR), improve (hybrid search, filtering, chunking) and check the answer's groundedness.

  • You'll add metadata filtering in SQL and explain why it's also a security matter

Controllers/AiLabController.cs · EvalRagpublic record GoldenItem(string Question, string MustContain); [HttpPost("rag/eval")]public async Task<IActionResult> EvalRag(CancellationToken ct){    string json = await System.IO.File.ReadAllTextAsync("golden.json", ct);    var golden = JsonSerializer.Deserialize<List<GoldenItem>>(json, JsonSerializerOptions.Web)!;     int hits = 0; double rr = 0; List<string> misses = [];    foreach (GoldenItem item in golden)    {        List<FoundChunk> found = await SearchChunksAsync(item.Question, ct);        int rank = found.FindIndex(c => c.Content.Contains(item.MustContain)) + 1;         if (rank is >= 1 and <= 3) hits++; else misses.Add(item.Question);        if (rank > 0) rr += 1.0 / rank;    }     return Ok(new { HitAt3 = (double)hits / golden.Count,                    Mrr = rr / golden.Count, Misses = misses });}

✂️ chunking strategies

Four ways to cut — measuring chooses

📏 By size
Every 800 characters. Simple, but cuts a sentence in the middle
🔤 By sentence
Lecture 11's. The sentence is whole, but it doesn't see the topic boundary
📑 By heading
A part = a section. The heading — in the prefix: title: Booking
🧠 By meaning
Cuts where the vectors of consecutive sentences “drift apart”. Expensive, not always better
Change → upload again → /rag/eval by sentence, 800: hitAt3 0.83 mrr 0.72 by heading: hitAt3 0.92 mrr 0.81 by sentence, 300: hitAt3 0.75 mrr 0.60
🙋 Why does the heading in the prefix help?
💡 The part's vector “knows” the topic too, even if the word “booking” isn't in the text
