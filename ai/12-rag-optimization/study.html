RAG ოპტიმიზაცია და შეფასება

🎯 ამ ლექციის შემდეგ შეძლებ

  • ახსნი, სად ცდება RAG (retrieval vs generation), შეადგენ golden set-ს და /rag/eval-ით hit@3-სა და MRR-ს გამოთვლი
  • hybrid search-ს ააწყობ: ვექტორი + PostgreSQL full-text (tsvector, 'english'), შერწყმული RRF-ით, და გაუმჯობესებას ციფრით დაამტკიცებ
  • metadata filtering-ს SQL-ში დაამატებ და ახსნი, რატომ არის ის უსაფრთხოების საკითხიც
  • chunking-ის სტრატეგიებს და reranking-ს შეადარებ, და პასუხის groundedness-ს GroundednessEvaluator-ით შეაფასებ

⚡ მთავარი

  1. RAG ორ ადგილას ცდება: ძებნაში (ყველაზე ხშირად) და პასუხში. ცვლილებას „თვალით“ არ ვამოწმებთ, ვზომავთ.
  2. golden set = შეკითხვები და ფრაზა, რომელიც უნდა მოიძებნოს. hit@3 და MRR გვეუბნება, რამდენად კარგია ძებნა.
  3. hybrid search = ვექტორი (მნიშვნელობა) + full-text (ზუსტი სიტყვა), გაერთიანებული RRF-ით.
  4. ფილტრი (კატეგორია, ფილიალი, უფლებები) SQL-შია, მოდელამდე. ეს უსაფრთხოების საკითხია.
  5. groundedness ამოწმებს, ეყრდნობა თუ არა პასუხი წყაროებს (LLM-as-judge). მსაჯსაც ვამოწმებთ.

📍 ლექცია გააცდინე?

  1. ნახე პრეზენტაცია: სლაიდები ლექციის მთელ გზას აჩვენებს
  2. წაიკითხე თემები: ~9 წთ, თითოს ბოლოს „შეამოწმე თავი“
  3. გაიარე ტესტი: 8 კითხვა
  4. გააკეთე დავალებები

🔗 ბმულები

  • Microsoft.Extensions.AI.Evaluation — Quality evaluators: Groundedness, Relevance, Retrieval, Completeness
  • PostgreSQL — Full Text Search — tsvector, tsquery, ts_rank, GIN
  • Npgsql EF Core — Full Text Search — HasGeneratedTsVectorColumn, Matches, Rank
  • Reciprocal Rank Fusion (Cormack et al., 2009) — RRF-ის ორიგინალი სტატია: k = 60
  • pgvector — Hybrid Search — pgvector + full-text ერთად

გაზომვა

▶ სლაიდები 6–9

„ზოგჯერ არასწორს პოულობს“ ციფრი არ არის. ჩანქის ზომა 800-დან 400-მდე შევამცირეთ: უკეთესი გახდა? ამის გასაგებად გაზომვა გვჭირდება.

golden set: შეკითხვები, რომლებზეც ვიცით, რა უნდა მოიძებნოს. სწორ ნაწილს ფრაზით ვნიშნავთ და არა Id-ით, რადგან chunking-ის შეცვლისას Id-ები იცვლება.

  • hit@3: რა წილ შეკითხვაზე მოხვდა სწორი ნაწილი პირველ სამში
  • MRR: რამდენად მაღლა: 1-ლი ადგილი = 1, მე-2 = ½, მე-3 = ⅓, ვერ იპოვა = 0, და საშუალო

▶ სლაიდები 10–13

ვექტორი მნიშვნელობას პოულობს ("without meat" → ლობიო), მაგრამ ზუსტ სიტყვებს უჭირს: „B-2“, "15 GEL", „12%“. PostgreSQL-ის full-text search ზუსტად სიტყვებს ეძებს. ორივეს ვიყენებთ და შედეგს RRF-ით ვაერთიანებთ (რიგით, რადგან score-ები სხვადასხვა მასშტაბისაა).

private async Task<List<FoundChunk>> HybridSearchAsync(string q, CancellationToken ct){    float minScore = _config.GetValue<float>("Rag:MinScore");    var query = new Vector(await _embeddings.GenerateVectorAsync(        EmbeddingText.Query(q), cancellationToken: ct));    var words = EF.Functions.ToTsQuery("english", OrQuery(q));     List<int> byMeaning = await _db.DocumentChunks                    // by vector, with a threshold        .Where(c => 1 - c.Embedding!.CosineDistance(query) >= minScore)        .OrderBy(c => c.Embedding!.CosineDistance(query))        .Select(c => c.Id).Take(20).ToListAsync(ct);     List<int> byWords = await _db.DocumentChunks                      // by words        .Where(c => c.SearchVector.Matches(words))        .OrderByDescending(c => c.SearchVector.Rank(words))        .Select(c => c.Id).Take(20).ToListAsync(ct);     List<int> top = Rrf(byMeaning, byWords).Take(5).ToList();     var chunks = await _db.DocumentChunks        .Where(c => top.Contains(c.Id))        .Select(c => new { c.Id, c.Document.FileName, c.Page, c.Content })        .ToDictionaryAsync(c => c.Id, ct);    return top.Select((id, i) => new FoundChunk(chunks[id].FileName, chunks[id].Page,        chunks[id].Content, Score: 1.0 / (i + 1))).ToList();        // Score — here simply by rank} private static IEnumerable<int> Rrf(params List<int>[] lists) => lists    .SelectMany(l => l.Select((id, i) => (id, s: 1.0 / (60 + i + 1))))    .GroupBy(x => x.id)    .OrderByDescending(g => g.Sum(x => x.s))    .Select(g => g.Key);

დაჭრა და პასუხი

▶ სლაიდები 15–18

Chunking. ზომით (უმარტივესი), აბზაცით/სათაურით (თემა არ წყდება), რეკურსიულად ან მნიშვნელობით. ყველაზე ხშირად სათაურით ჭრა და სათაურის ნაწილზე მიწერა შველის. რომელი ჯობია, მხოლოდ გაზომვა იტყვის: 300 სიმბოლო „უფრო ზუსტი“ არ არის, ხშირად კონტექსტს კარგავს.

Reranking. ძებნა სწრაფია, მაგრამ უხეში: შეკითხვას და ნაწილს ცალ-ცალკე აფასებს. reranker კანდიდატებს (მაგ. 20) შეკითხვასთან ერთად კითხულობს და ზუსტად ალაგებს. ის ნელია, ამიტომ მხოლოდ კანდიდატებზე.

Groundedness. ნაწილი სწორია, მაგრამ მოდელმა რამე მოიგონა? მეორე მოდელი (მსაჯი) ამოწმებს, ეყრდნობა თუ არა პასუხი წყაროებს:

🏠 საშინაო

RAG — გაზომილი და გაუმჯობესებული

კოდით · შენი პროექტი · README-ში შედეგების ცხრილი და დასკვნა

მოთხოვნები

  • golden set — 10 შეკითხვა (2 ზუსტი სიტყვით/კოდით/რიცხვით, 2 სინონიმით, 1 ორ ადგილას პასუხით); /rag/eval — HitAt3, Mrr, Misses
  • hybrid search — tsvector generated column ('english') + GIN ინდექსი, OrQuery, ვექტორი + full-text → RRF → top 5; /chat და /rag/eval hybrid-ს იყენებს
  • metadata filtering — Document-ს ერთი metadata ველი (კატეგორია, ენა, ფილიალი…), ატვირთვისას ივსება; ძებნას ფილტრის პარამეტრი, ფილტრი — SQL-ში
  • ერთი chunking-ის ექსპერიმენტი — ზომა (მაგ. 400 ან 1500) ან სათაური prefix-ში; თავიდან ატვირთვა და გაზომვა
  • groundedness — 3 პასუხზე GroundednessEvaluator: ციფრი და Reason
  • README — ცხრილი და დასკვნა: ვერსია · hitAt3 · MRR · misses (vector-only, hybrid, hybrid + chunking-ის ექსპერიმენტი), groundedness-ის 3 შედეგი, და 3–4 წინადადება: რა გაუმჯობესდა, რა — არა, რას აირჩევდი production-ში
  • კონსპექტის ტესტი (8 კითხვა) — ქულა ჩაწერე

✓ მზადაა, როცა

ცხრილში სამი ვერსია ციფრებით და hybrid ზუსტ სიტყვებზე ჩანს; ფილტრიანი ძებნა ერთი SQL-ია; groundedness-ის 3 შეფასება ახსნით; დასკვნა ციფრებს ეყრდნობა

⭐ ბონუსი

  • LLM-rerank: hybrid-ის 20 კანდიდატი → Gemini (GetResponseAsync<RankResult>) → 5. hit@3 და დრო — ღირს?
  • pg_trgm: CREATE EXTENSION pg_trgm და similarity() — ბეჭდვის შეცდომებზე ("cancelation" / "cancellation") უშველა?
  • eval ტესტად: xUnit ტესტი, რომელიც /rag/eval-ს უშვებს და ჩავარდება, თუ HitAt3 < 0.8 (ლექცია 22-ის წინასწარი ვერსია)

💡 დეტალები

  • chunking-ის ექსპერიმენტამდე ძველი ნაწილები წაშალე (ან ახალი ბაზა), თორემ ორივე ვერსია ერთად იძებნება
  • სათაური prefix-ში: EmbeddingText.Document(sectionTitle, chunk) — Word/Markdown-ში სათაურები მზაა; PDF-ში — ხაზი, რომელიც მოკლეა და წერტილით არ მთავრდება (მარტივი ევრისტიკა)
  • GroundednessEvaluator — NuGet Microsoft.Extensions.AI.Evaluation.Quality; მსაჯად ცალკე IChatClient (tool-ების გარეშე)
  • ცარიელი OrQuery (შეკითხვა მხოლოდ სიმბოლოებით) — full-text გამოტოვე
