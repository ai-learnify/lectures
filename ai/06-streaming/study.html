Streaming და Real-time AI პასუხები

ლექციის სრული მასალა თავებად, ~13 წუთი კითხვა. შენი პროგრესი ბრაუზერში ინახება. ეს გვერდი პრეზენტაციას მიჰყვება: სლაიდის შეცვლისას შესაბამისი ნაწილი მოინიშნება.

⚡ 5 წუთში

თუ მხოლოდ ეს დაგამახსოვრდა, ლექციის მთავარი იცი:

  1. სტრიმინგი პასუხს დაწერისთანავე აჩვენებს: მთლიანი დრო იგივეა, მაგრამ TTFT (დრო პირველ სიტყვამდე) წამებიდან მილიწამებამდე მცირდება.
  2. GetStreamingResponseAsync → IAsyncEnumerable<ChatResponseUpdate> → await foreach. იგივე messages და options; tool-ებიც მუშაობს.
  3. ნაწილების სიაში შეგროვება სტრიმს Controller-ში წყვეტს. yield return (async iterator) თითო ნაწილს მაშინვე აბრუნებს.
  4. SSE: text/event-stream, data: … + ცარიელი ხაზი, ღია კავშირი. TypedResults.ServerSentEvents (.NET 10). Swagger სტრიმს ვერ აჩვენებს — curl -N.
  5. CancellationToken სამ ადგილას: action-ის პარამეტრი, [EnumeratorCancellation], GetStreamingResponseAsync. მომხმარებელი წავიდა → Gemini ჩერდება.

📍 ლექცია გააცდინე?

  1. წაიკითხე თავები — სულ ~13 წთ. ყოველი თავის ბოლოს არის „შეამოწმე თავი“
  2. გაიარე ტესტი — 11 კითხვა, ქულით
  3. გააკეთე კლასის დავალება სახლში
  4. საშინაო დავალება — შემდეგ ლექციაზე განვიხილავთ

სტრიმი Gemini-დან: GetStreamingResponseAsync

🎯 ამის შემდეგ: ახსნი, რას ცვლის სტრიმინგი, და Gemini-დან პასუხს ნაწილ-ნაწილ მიიღებ, თითო ნაწილის დროის გაზომვით.

ნაწილი 1 · სტრიმი Gemini-დან

სლაიდი 6

ჯერ ვხედავთ, რატომ გვჭირდება სტრიმინგი: პრობლემა UX-შია, არა სიჩქარეში. მერე ვიღებთ პასუხს Gemini-დან ნაწილ-ნაწილ და ვზომავთ, როდის მოდის თითოეული ნაწილი.

პრობლემა: ცარიელი ეკრანი

სლაიდი 7

Gemini პასუხს ტოკენ-ტოკენ წერს (ლექცია 1: next-token prediction), და გრძელ პასუხს, ფიქრის ჩათვლით, რამდენიმე წამი სჭირდება. აქამდე ვიყენებდით GetResponseAsync-ს, რომელიც ბოლომდე ელოდება და მერე მთელ ტექსტს ერთბაშად აბრუნებს:

რას ხედავს მომხმარებელი
GetResponseAsync ~8 წამი ცარიელ ეკრანს, მერე მთელ ტექსტს ერთად
Streaming ~0.6 წამში პირველ სიტყვებს, მერე ტექსტი თანდათან „იწერება“

მთლიანი დრო თითქმის იგივეა: Gemini ორივე შემთხვევაში ერთი და იმავე სისწრაფით წერს. იცვლება მხოლოდ ის, როდის ხედავს მომხმარებელი პირველ სიტყვას. 8 წამი ცარიელ ეკრანზე „გაფუჭებულს“ ჰგავს, 8 წამი იწერებადი ტექსტი კი ნორმალურია: კითხვას მაშინვე იწყებ.

ამიტომ ყველა AI ჩატი (ChatGPT, Claude, Gemini, Copilot) სტრიმავს.

GetStreamingResponseAsync: პასუხი ნაწილ-ნაწილ

სლაიდი 8

IChatClient-ს ორი მეთოდი აქვს. აქამდე მხოლოდ პირველს ვიყენებდით:

csharp
// 1) ერთი პასუხი, ბოლოსChatResponse response = await _chat.GetResponseAsync(messages); // 2) ბევრი ნაწილი, მოსვლისთანავეawait foreach (ChatResponseUpdate update in _chat.GetStreamingResponseAsync(messages)){    Console.Write(update.Text);}
  • IAsyncEnumerable<T> — IEnumerable<T>-ის ასინქრონული ვერსია. foreach ჩვეულებრივ სიას გადის, ხოლო await foreach შემდეგ ელემენტს ელოდება, რადგან ის ჯერ არ არსებობს: Gemini ჯერ წერს. ციკლის სხეული თითო ნაწილზე მაშინვე სრულდება, როგორც კი ნაწილი მოვიდა.
  • ChatResponseUpdate — პასუხის ერთი ნაწილი: Text (ტექსტის ნაჭერი), Role, ხოლო ბოლო ნაწილებში FinishReason და ტოკენები (UsageContent).
  • არგუმენტები იგივეა: messages, options (tool-ების ჩათვლით), cancellationToken. UseFunctionInvocation სტრიმინგშიც მუშაობს: tool-ის ციკლი ჯერ შიგნით სრულდება, მერე ტექსტი იწყებს მოსვლას.

მაგრამ Swagger-მა ყველაფერი ერთბაშად აჩვენა. რატომ? ჩვენ ნაწილებს ვაგროვებთ chunks სიაში და Ok(chunks)-ს ბოლოს ვაბრუნებთ. სტრიმი Gemini-დან Controller-მდე მოდის, მაგრამ Controller-ში წყდება. კლიენტამდე რომ მივიდეს, ყოველი ნაწილი მაშინვე უნდა გავაგზავნოთ. ეს მეორე ნაწილის თემაა.

🎯 ამის შემდეგ: დაწერ SSE endpoint-ს TypedResults.ServerSentEvents-ით და curl -N-ით დაინახავ, როგორ ჩნდება პასუხი ნაწილ-ნაწილ.

ნაწილი 2 · Server-Sent Events

სლაიდი 11

სტრიმი Controller-მდე მოდის. ახლა ის კლიენტამდე უნდა მივიდეს: ყოველი ნაწილი მაშინვე, ერთი HTTP პასუხის შიგნით. ამისთვის არსებობს მარტივი სტანდარტი, Server-Sent Events (SSE), და .NET 10-ში მისთვის მზა TypedResults.ServerSentEvents გვაქვს.

Server-Sent Events: ერთი პასუხი, რომელიც ღია რჩება

სლაიდი 12

SSE ჩვეულებრივი HTTP-ა. სერვერი პასუხს აბრუნებს Content-Type: text/event-stream-ით, კავშირს არ ხურავს და ტექსტს ნაწილ-ნაწილ წერს:

plain
HTTP/1.1 200 OKContent-Type: text/event-stream data: ხვალ 20:00-ზე data:  ოთხი კაცისთვის data:  ორი მაგიდაა თავისუფალი
  • data: … — ერთი შეტყობინება. ცარიელი ხაზი მის ბოლოს ნიშნავს.
  • სერვერი თითო ნაწილს მაშინვე წერს და flush-ავს (გზავნის), ბუფერში არ აგროვებს.
  • ბრაუზერს ამისთვის ჩაშენებული EventSource აქვს, ტერმინალში კი curl -N საკმარისია.

SSE, WebSocket თუ SignalR?

მიმართულება როდის
SSE სერვერი → კლიენტი AI ჩატის პასუხი, შეტყობინებები, პროგრესის ზოლი
WebSocket ორივე მხარეს თამაში, ერთობლივი რედაქტირება
SignalR ორივე მხარეს + ჯგუფები, ავტომატური გადაერთება ადამიანებს შორის ჩატი, live დაშბორდი

AI-ს პასუხი ცალმხრივია: მომხმარებელი კითხვას ერთხელ აგზავნის (ჩვეულებრივი მოთხოვნით), სერვერი კი პასუხს დიდხანს წერს. SSE ზუსტად ამისთვისაა: ჩვეულებრივი HTTP, დამატებითი ბიბლიოთეკისა და პროტოკოლის გარეშე. ამიტომ OpenAI, Anthropic და Gemini-ს API-ებიც თავიანთ სტრიმს SSE-თი აბრუნებენ. SignalR კარგია, როცა სერვერსა და კლიენტს ორივე მხარეს ბევრი აქვთ სათქმელი.

რა ხდება:

  • TypedResults.ServerSentEvents(...) — .NET 10-ის ახალი შედეგი (Controller-შიც მუშაობს). IAsyncEnumerable<string>-ს იღებს და ყველაფერს თვითონ აკეთებს: Content-Type: text/event-stream, თითო ელემენტი data: …-ად და მაშინვე flush.
  • StreamAnswer — async iterator მეთოდი (async IAsyncEnumerable<string> + yield return). Gemini-ს ყოველ ნაწილს მაშინვე აბრუნებს, სიაში არ აგროვებს. ასე სტრიმი Gemini-დან კლიენტამდე არ წყდება.
  • if (!string.IsNullOrEmpty(update.Text)) — ზოგ ნაწილში ტექსტი არ არის (მაგ. tool-ის გამოძახება ან ბოლო ნაწილი ტოკენებით). ცარიელს არ ვაგზავნით.

  • CancellationToken და [EnumeratorCancellation] — მესამე ნაწილის თემაა.

შემოწმება ტერმინალში (პორტი შენი launchSettings.json-იდან):

bash

-N (no buffer) — curl-მა მიღებული მონაცემი არ დააგროვოს და მაშინვე აჩვენოს. Windows-ზე PowerShell-ში curl.exe დაწერე (უბრალო curl PowerShell-ში სხვა ბრძანებაა).

⚠️

Swagger-ში ეს endpoint არ გამოგადგება: Swagger პასუხს ბოლომდე ელოდება და ერთბაშად აჩვენებს. სტრიმი რომ დაინახო, გამოიყენე curl -N ან ბრაუზერის EventSource (⭐ ქვემოთ).

⭐ ბრაუზერში — EventSource. სურვილისამებრ: პატარა გვერდი, რომელიც პასუხს ბრაუზერში ნაწილ-ნაწილ აჩვენებს. Program.cs-ში app.UseStaticFiles();, ფაილი კი wwwroot/chat.html:

გაუქმება: CancellationToken

🎯 ამის შემდეგ: token-ს სამ ადგილას გადასცემ და შეამოწმებ, რომ კლიენტის წასვლისას Gemini-ს მოთხოვნაც წყდება.

ნაწილი 3 · გაუქმება

სლაიდი 14

სტრიმი დიდხანს გრძელდება. თუ მომხმარებელმა შუაში ფანჯარა დახურა, სერვერმა ეს უნდა გაიგოს და Gemini-ს მოთხოვნაც უნდა შეწყვიტოს. თორემ Gemini ცარიელ ოთახში წერს, ჩვენ კი მის ტოკენებს ვიხდით.

გაუქმება: კლიენტი წავიდა, Gemini-ც ჩერდება

სლაიდი 15

პრობლემა: მომხმარებელმა კითხვა დასვა და 2 წამში ფანჯარა დახურა, Gemini კი პასუხს 30 წამი წერს. თუ სერვერმა ეს არ გაიგო, Gemini-სთან მოთხოვნა შეიძლება ბოლომდე გაგრძელდეს: ტოკენებს ვიხდით, პასუხს კი არავინ კითხულობს.

გამოსავალი — CancellationToken, სამ ადგილას:

csharp
[HttpGet("chat/stream")]public IResult ChatStream(string prompt, CancellationToken cancellationToken)   // ①{    return TypedResults.ServerSentEvents(StreamAnswer(prompt, cancellationToken));} private async IAsyncEnumerable<string> StreamAnswer(string prompt,    [EnumeratorCancellation] CancellationToken cancellationToken)               // ②{    // ...    await foreach (ChatResponseUpdate update in        _chat.GetStreamingResponseAsync(messages, ChatToolOptions(), cancellationToken))   // ③    // ...}
  1. Action-ის პარამეტრი. ASP.NET Core მას თვითონ ავსებს HttpContext.RequestAborted-ით: token „გაუქმდება“, როცა კლიენტი კავშირს წყვეტს. API კურსიდან იცი: ყველა async endpoint-ში ასე გადაეცემა ToListAsync(cancellationToken)-საც.
  2. [EnumeratorCancellation] — async iterator-ის token-ის პარამეტრზე. ის აკავშირებს iterator-ის token-ს იმ token-თან, რომელსაც ServerSentEvents იტერაციისას გადასცემს. ატრიბუტის გარეშე კომპილატორი გაფრთხილებას წერს.
  3. GetStreamingResponseAsync(..., cancellationToken) — token Gemini-ს HTTP მოთხოვნამდე მიდის. გაუქმებისას კავშირი წყდება და Gemini აღარ წერს.

შემოწმება: curl -N-ით გრძელი პასუხი („მოგვიყევი ქართულ სამზარეულოზე დეტალურად“), შუაში Ctrl+C. სერვერის ლოგში (UseLogging, ლექცია 5) გამოჩნდება, რომ მოთხოვნა გაუქმდა (canceled), და არა ჩვეულებრივად დასრულდა (completed).

👉

წესი API კურსიდან: ყოველ async გამოძახებას, რომელიც CancellationToken-ს იღებს, token გადაეცი: ToListAsync, GetResponseAsync, GetStreamingResponseAsync. AI-სთან ეს განსაკუთრებით მნიშვნელოვანია, რადგან მოთხოვნები გრძელია და ფული ჯდება.

  • სტრიმინგი პასუხს დაწერისთანავე აჩვენებს. მთლიან დროს არ ამცირებს, მაგრამ TTFT-ს (დროს პირველ სიტყვამდე) წამებიდან მილიწამებამდე ამცირებს. ცარიელი ეკრანი აღარ არის.
  • GetStreamingResponseAsync აბრუნებს IAsyncEnumerable<ChatResponseUpdate>-ს. ვკითხულობთ await foreach-ით. იგივე messages და options, tool-ებიც მუშაობს.
  • თუ ნაწილებს სიაში ვაგროვებთ, სტრიმი Controller-ში წყდება. yield return (async iterator) თითო ნაწილს მაშინვე აბრუნებს.
  • SSE — HTTP პასუხი text/event-stream-ით, რომელიც ღია რჩება; data: … + ცარიელი ხაზი. AI-ს ცალმხრივი პასუხისთვის საკმარისია. WebSocket/SignalR ორმხრივი კომუნიკაციისთვისაა.
  • TypedResults.ServerSentEvents (.NET 10) SSE-ს თვითონ აწყობს. Swagger სტრიმს ვერ აჩვენებს, ამიტომ ვამოწმებთ curl -N-ით.
  • CancellationToken სამ ადგილას: action-ის პარამეტრი, [EnumeratorCancellation] და GetStreamingResponseAsync. მომხმარებელი წავიდა → Gemini ჩერდება → ტოკენები აღარ იხარჯება.
