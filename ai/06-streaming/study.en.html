Chapter 1 · ~3 min read

A stream from Gemini: GetStreamingResponseAsync

🎯 After this You'll explain what streaming changes and get the answer from Gemini piece by piece, measuring each piece's time.

Part 1 · A stream from Gemini

Slide 6

First we see why we need streaming: the problem is UX, not speed. Then we get the answer from Gemini piece by piece and measure when each piece arrives.

The problem: an empty screen

Slide 7

Gemini writes the answer token by token (lecture 1: next-token prediction), and a long answer, thinking included, takes several seconds. Until now we used GetResponseAsync, which waits until the end and then returns all the text at once:

What the user sees
GetResponseAsync ~8 seconds of an empty screen, then all the text together
Streaming the first words in ~0.6 seconds, then the text gradually “gets written”

The total time is almost the same: Gemini writes at the same speed in both cases. The only thing that changes is when the user sees the first word. 8 seconds of an empty screen looks “broken”, while 8 seconds of text being written is normal: you start reading right away.

That's why every AI chat (ChatGPT, Claude, Gemini, Copilot) streams.

📘 Terms
Streaming
getting and showing the answer in pieces, as it's written, rather than all at the end
TTFT (time to first token)
the time from the request to the first token; streaming improves exactly this

GetStreamingResponseAsync: the answer in pieces

Slide 8

IChatClient has two methods. Until now we've only used the first one:

csharp
// 1) one answer, at the endChatResponse response = await _chat.GetResponseAsync(messages); // 2) many pieces, as they arriveawait foreach (ChatResponseUpdate update in _chat.GetStreamingResponseAsync(messages)){    Console.Write(update.Text);}
  • IAsyncEnumerable<T> — the asynchronous version of IEnumerable<T>. A foreach walks an ordinary list, while await foreach waits for the next item, because it doesn't exist yet: Gemini is still writing. The loop body runs for each piece right away, as soon as it arrives.
  • ChatResponseUpdate — one piece of the answer: Text (a chunk of text), Role, and in the last pieces FinishReason and the tokens (UsageContent).
  • The arguments are the same: messages, options (tools included), cancellationToken. UseFunctionInvocation works with streaming too: the tool loop finishes inside first, then the text starts arriving.
📘 Terms
IAsyncEnumerable
a stream of items where each item arrives asynchronously; read with await foreach
ChatResponseUpdate
one piece of a streaming answer: a chunk of text and metadata

Measuring: when does each piece arrive

Slide 9
Controllers/AiLabController.cs · ChatChunks
[HttpPost("chat/chunks")]public async Task<IActionResult> ChatChunks(AskRequest request){    Stopwatch sw = Stopwatch.StartNew();    List<object> chunks = [];     await foreach (ChatResponseUpdate update in        _chat.GetStreamingResponseAsync(request.Prompt))    {        chunks.Add(new { Ms = sw.ElapsedMilliseconds, update.Text });    }     return Ok(chunks);}

Stopwatch (using System.Diagnostics;) measures how many milliseconds passed before each piece arrived. For “tell us about Georgian cuisine”, a sample result looks like this:

ms text
640 “Georgian cuisine”
910 “ is famous for khinkali…”
1180 “ and khachapuri…”
… …
5420 “.”
  • The first piece at ~0.6 seconds (TTFT), the last at ~5.4 seconds. Without streaming the user would wait 5.4 seconds.
  • A piece ≠ one token. Gemini sends several tokens together. The size of a piece depends on the provider.

But Swagger showed everything at once. Why? We collect the pieces in the chunks list and return Ok(chunks) at the end. The stream comes from Gemini to the Controller but stops in the Controller. For it to reach the client, every piece has to be sent right away. That's the topic of part two.

Server-Sent Events: the stream to the client

🎯 After this You'll write an SSE endpoint with TypedResults.ServerSentEvents and see with curl -N how the answer appears piece by piece.

Part 2 · Server-Sent Events

Slide 11

The stream reaches the Controller. Now it has to reach the client: every piece right away, inside one HTTP response. There's a simple standard for this, Server-Sent Events (SSE), and in .NET 10 we have a ready-made TypedResults.ServerSentEvents for it.

Server-Sent Events: one response that stays open

Slide 12

SSE is ordinary HTTP. The server returns a response with Content-Type: text/event-stream, doesn't close the connection and writes the text piece by piece:

plain
HTTP/1.1 200 OKContent-Type: text/event-stream data: Tomorrow at 20:00 data:  for four people data:  two tables are free
  • data: … — one message. An empty line marks its end.
  • The server writes each piece right away and flushes it (sends it), instead of collecting it in a buffer.
  • Browsers have a built-in EventSource for this, and in a terminal curl -N is enough.

SSE, WebSocket or SignalR?

Direction When
SSE server → client an AI chat answer, notifications, a progress bar
WebSocket both ways a game, collaborative editing
SignalR both ways + groups, automatic fallback chat between people, a live dashboard

An AI answer is one-way: the user sends the question once (with an ordinary request), and the server writes the answer for a long time. SSE is made exactly for this: plain HTTP, without an extra library or protocol. That's why the OpenAI, Anthropic and Gemini APIs also return their streams over SSE. SignalR is good when the server and the client both have a lot to say to each other.

📘 Terms
Server-Sent Events (SSE)
an HTTP response of type text/event-stream that stays open, and the server writes messages into it piece by piece

TypedResults.ServerSentEvents: the stream to the client

Slide 13
Controllers/AiLabController.cs · ChatStream
[HttpGet("chat/stream")]public IResult ChatStream(string prompt, CancellationToken cancellationToken){    return TypedResults.ServerSentEvents(StreamAnswer(prompt, cancellationToken));} private async IAsyncEnumerable<string> StreamAnswer(string prompt,    [EnumeratorCancellation] CancellationToken cancellationToken){    List<ChatMessage> messages =    [        new(ChatRole.System, $"""            You are a restaurant assistant. Answer briefly.            Take menu and table data only from the tools.            Today is {DateTime.Now:yyyy-MM-dd, dddd}.            """),        new(ChatRole.User, prompt)    ];     await foreach (ChatResponseUpdate update in        _chat.GetStreamingResponseAsync(messages, ChatToolOptions(), cancellationToken))    {        if (!string.IsNullOrEmpty(update.Text))            yield return update.Text;    }}

ChatToolOptions() — lecture 4's ChatOptions with tools, moved into its own method so that /chat and /chat/stream use the same one:

Controllers/AiLabController.cs
private ChatOptions ChatToolOptions() => new(){    Tools =    [        AIFunctionFactory.Create(_tools.GetMenu, name: "get_menu"),        AIFunctionFactory.Create(_tools.CheckAvailability, name: "check_availability")    ]};

What happens:

  • TypedResults.ServerSentEvents(...) — a new result in .NET 10 (it works in Controllers too). It takes an IAsyncEnumerable<string> and does everything itself: Content-Type: text/event-stream, each item as data: …, and an immediate flush.
  • StreamAnswer — an async iterator method (async IAsyncEnumerable<string> + yield return). It returns each Gemini piece right away, without collecting it in a list. This way the stream doesn't break between Gemini and the client.
  • if (!string.IsNullOrEmpty(update.Text)) — some pieces have no text (e.g. a tool call or the last piece with tokens). We don't send empty ones.
  • [HttpGet] and string prompt — from the query string (?prompt=...). GET because the browser's EventSource only allows GET.
  • CancellationToken and [EnumeratorCancellation] — the topic of part three.

using System.Runtime.CompilerServices; — for [EnumeratorCancellation].

Checking it in a terminal (the port from your launchSettings.json):

bash
curl -N "http://localhost:5080/api/ai-lab/chat/stream?prompt=What%20do%20you%20have%20under%2015%20GEL%3F"

-N (no buffer) — curl shouldn't collect the data it receives but show it right away. On Windows in PowerShell write curl.exe (a plain curl is a different command in PowerShell).

⚠️

Swagger won't work for this endpoint: Swagger waits for the response to finish and shows it all at once. To see the stream, use curl -N or the browser's EventSource (⭐ below).

⭐ In the browser — EventSource. Optional: a small page that shows the answer in the browser piece by piece. app.UseStaticFiles(); in Program.cs, and the file wwwroot/chat.html:

wwwroot/chat.html
<!doctype html><meta charset="utf-8"><input id="q" size="60" placeholder="question"><button onclick="ask()">Send</button><pre id="out"></pre><script>  function ask() {    out.textContent = '';    const es = new EventSource('/api/ai-lab/chat/stream?prompt=' + encodeURIComponent(q.value));    es.onmessage = e => out.textContent += e.data;    es.onerror = () => es.close();   // the stream ended — don't reconnect  }</script>

EventSource is a built-in browser class: it reads text/event-stream by itself and calls onmessage for every data:. When the connection closes it reconnects automatically, which is why we close it in onerror.

💡

Our lecture 5 layers (TokenCounter, InputGuard) only cover GetResponseAsync. With streaming, DelegatingChatClient passes the request through unchanged: tokens aren't counted and the guard doesn't work either. In the homework you'll add GetStreamingResponseAsync to InputGuard too.

Cancellation: CancellationToken

🎯 After this You'll pass the token in three places and check that the Gemini request stops when the client leaves.

Part 3 · Cancellation

Slide 14

A stream lasts a long time. If the user closes the window halfway through, the server has to notice and stop the Gemini request too. Otherwise Gemini writes to an empty room, and we pay for its tokens.

Cancellation: the client left, Gemini stops too

Slide 15

The problem: a user asked a question and closed the window 2 seconds later, while Gemini writes the answer for 30 seconds. If the server doesn't notice, the request to Gemini may go on to the end: we pay for the tokens, and nobody reads the answer.

The solution — a CancellationToken, in three places:

csharp
[HttpGet("chat/stream")]public IResult ChatStream(string prompt, CancellationToken cancellationToken)   // ①{    return TypedResults.ServerSentEvents(StreamAnswer(prompt, cancellationToken));} private async IAsyncEnumerable<string> StreamAnswer(string prompt,    [EnumeratorCancellation] CancellationToken cancellationToken)               // ②{    // ...    await foreach (ChatResponseUpdate update in        _chat.GetStreamingResponseAsync(messages, ChatToolOptions(), cancellationToken))   // ③    // ...}
  1. The action's parameter. ASP.NET Core fills it in itself with HttpContext.RequestAborted: the token gets “cancelled” when the client drops the connection. You know this from the API course: in every async endpoint it's passed on to ToListAsync(cancellationToken) too.
  2. [EnumeratorCancellation] — on the token parameter of an async iterator. It connects the iterator's token with the token ServerSentEvents passes while iterating. Without the attribute the compiler shows a warning.
  3. GetStreamingResponseAsync(..., cancellationToken) — the token goes all the way to Gemini's HTTP request. On cancellation the connection is dropped and Gemini stops writing.

Checking it: a long answer with curl -N (“tell us about Georgian cuisine in detail”), and Ctrl+C halfway through. The server log (UseLogging, lecture 5) will show that the request was cancelled (canceled) rather than finished normally (completed).

👉

A rule from the API course: pass the token to every async call that accepts a CancellationToken: ToListAsync, GetResponseAsync, GetStreamingResponseAsync. With AI this matters even more, because requests are long and cost money.

📘 Terms
CancellationToken
a “stop” signal; in ASP.NET Core it comes as an action parameter and gets cancelled when the client leaves
[EnumeratorCancellation]
an attribute on an async iterator's token parameter, so the iteration's token reaches it

Summary

Slide 18
  • Streaming shows the answer as it's written. It doesn't reduce the total time, but it cuts the TTFT (time to the first word) from seconds to milliseconds. No more empty screen.
  • GetStreamingResponseAsync returns an IAsyncEnumerable<ChatResponseUpdate>. We read it with await foreach. The same messages and options; tools work too.
  • If we collect the pieces in a list, the stream stops in the Controller. yield return (an async iterator) returns each piece right away.
  • SSE — an HTTP response with text/event-stream that stays open; data: … + an empty line. Enough for an AI's one-way answer. WebSocket/SignalR are for two-way communication.
  • TypedResults.ServerSentEvents (.NET 10) builds the SSE itself. Swagger can't show a stream, so we check with curl -N.
  • CancellationToken in three places: the action parameter, [EnumeratorCancellation] and GetStreamingResponseAsync. The user left → Gemini stops → no more tokens are spent.
