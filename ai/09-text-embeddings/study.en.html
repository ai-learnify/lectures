Which error does retry help with, and which doesn't it? One example each.
Transient — 429, 500/503, timeout, the network: trying again helps · permanent — 400, 401, 403, 404: the same request brings the same error · content (length, bad JSON) — in code
Why don't we retry 10 times right away? What are backoff and jitter?
We'd send an overloaded service even more requests · backoff — a growing pause (2→4→8 s) · jitter — a random part, so many clients don't retry at the same time · on a 429 — Retry-After
Why do we turn off Google.GenAI's own retry?
Retry must be in one place · two nested retries = 4 × 4 = 16 attempts and minutes of waiting · HttpRetryOptions { Attempts = 1 } + our HttpClient through ClientOptions.HttpClientFactory
Where does FallbackChatClient stand in the pipeline, and which errors does it catch?
Innermost (the last .Use) — every request of the tool loop gets its own fallback · only transient ones: ApiException 429/5xx, the network, a timeout · catch … when
Why does TokenCounter get the DbContext through IServiceScopeFactory to write to the database?
The pipeline is a Singleton, the DbContext is Scoped · injecting it directly = a captive dependency · the layer creates its own scope every time

What an embedding is

🎯 After this You'll explain how an embedding turns text into a vector and why a similar meaning is close together.

Part 1 · What an embedding is

Slide 6

First we see why searching by words isn't enough. Then the idea: the “coordinates of meaning” of a text. And finally, which model does this and how many numbers there are in one vector.

The problem: searching by words doesn't see meaning

Slide 7

The user writes “something light, without meat”. An ordinary search looks for words:

sql
SELECT "Name" FROM "Products" WHERE "Description" ILIKE '%without meat%';-- 0 results
Dish Description LIKE
Lobio in a clay pot red beans, onion, coriander, with hot mchadi ✗
Aubergine with walnuts fried aubergine, walnut paste, pomegranate ✗
Mtsvadi pork on a skewer, with onion ✗
Khinkali beef and pork, in dough ✗
Tomato salad tomato, cucumber, walnut ✗

A person sees right away that the lobio, the aubergine and the salad match. And if we search for the word “meat”, LIKE finds exactly the wrong dishes: the mtsvadi and the khinkali. A word and a meaning are different things: “without meat”, “vegetarian” and “ვეგეტარიანული” mean the same thing, and not a single letter matches.

In lecture 7's terms: we want selection — only the dishes that match the question go into the context. For that we need to search by meaning.

Embedding: the “coordinates of meaning” of a text

Slide 8

Embedding — turning a text into a list of numbers: "Lobio in a clay pot" → [0.021, -0.047, 0.009, 0.063, …]. This list is called a vector. A vector is a point in space: two numbers give a point on a map (x, y), 768 numbers give a point in a 768-dimensional space.

The key property: an embedding model is trained so that texts with a similar meaning stand close together:

  • “Lobio in a clay pot”, “Aubergine with walnuts”, “Tomato salad” — on one side (vegetables, no meat);
  • “Mtsvadi”, “Khinkali” — on the other side (meat);
  • the question “without meat” lands next to the first group, and “ვეგეტარიანული” is right there too: the language is different, the meaning is the same.

The slide shows a two-dimensional picture so we can see it with our eyes. In reality one vector holds hundreds or thousands of numbers, and each number is some “direction” of meaning that the model learned by itself during training (none of them has a name a person would understand).

The answer to lecture 1's question “how does the model know what token 3293 means?” is this: inside the model every token has a vector like this.

📘 Terms
Embedding
turning a text (or an image) into a list of numbers so that a similar meaning is close together
Vector
a list of numbers; the result of an embedding; a point in space
Dimension
how many numbers there are in the vector (e.g. 768)

The embedding model: a separate model, a separate interface

Slide 9

It isn't the chat model (gemini-3.8-flash) that generates the vector, but a separate embedding model:

Chat model Embedding model
In messages text
Out text (token by token) one vector (all at once)
Interface IChatClient IEmbeddingGenerator
Price input + output input only — much cheaper

Our model: gemini-embedding-2 — Gemini's newest embedding model (Stable). It takes up to 8,192 tokens of input, and the vector size can be anywhere from 128 to 3072. The recommended sizes are 768, 1536 and 3072.

We take 768: the quality is good, the vector is 4 times smaller (less space in the database, faster search), and lecture 10's pgvector index handles this size easily.

One model — one “map”. Every embedding model creates its own space. A gemini-embedding-2 vector can't be compared with a vector from another model (or from the same model at another size) — the numbers are on a different “map”. So the model and the size are chosen once: if we change them, every stored vector has to be calculated again.

📘 Terms
Embedding model
a model that turns text into a vector; it doesn't write text
IEmbeddingGenerator
Microsoft.Extensions.AI's interface for embeddings, like IChatClient

Task prefix: the question and the document in different formats

Slide 12

A question (“something light?”) and its answer (a dish's description) don't look like the same kind of text: the question is short and describes a “wish”, the document is long and describes “facts”. This kind of search is called asymmetric. For gemini-embedding-2, Google recommends that on text tasks we write a description of the task (a prefix) in front of the text:

What Format
Question task: search result \| query: {question}
Document title: {title} \| text: {text} (without a title — title: none)
Ai/EmbeddingText.cs
public static class EmbeddingText{    public static string Query(string q) =>        $"task: search result | query: {q}";     public static string Document(string title, string text) =>        $"title: {title} | text: {text}";}

The prefix tells the model which text plays which role, and the search quality goes up. One rule never changes: every document in one format, every question in the other. If we store half with the prefix and half without, the vectors compare badly.

Besides search result there are other tasks too (question answering, fact checking, code search) — on Gemini's embeddings page.

📘 Terms
Asymmetric search
searching for a long document with a short question; the question and the document in different formats
Task prefix
a description of the task written in front of the text, which raises the quality of the embedding

Cosine similarity and semantic search

🎯 After this You'll measure similarity and write a menu search by meaning.

Part 3 · Similarity and search

Slide 14

We have two vectors. How close are they? We learn cosine similarity, write it in C# and build a semantic search for the menu.

Cosine similarity: the angle between two arrows

Slide 15

We can picture a vector as an arrow pointing from the centre in some direction. Cosine similarity measures the angle between two arrows:

Angle cosine What it means
0° — the same direction 1 very similar
90° — perpendicular 0 nothing in common
180° — opposite −1 (practically never happens with texts)

The formula — the dot product divided by the product of the lengths:

By hand — how it's calculated
static float Cosine(ReadOnlySpan<float> a, ReadOnlySpan<float> b){    float dot = 0, na = 0, nb = 0;    for (int i = 0; i < a.Length; i++)    {        dot += a[i] * b[i];   // the dot product        na  += a[i] * a[i];   // the length of a, squared        nb  += b[i] * b[i];   // the length of b, squared    }    return dot / (MathF.Sqrt(na) * MathF.Sqrt(nb));}

In .NET this is ready-made and fast too (SIMD — the processor multiplies several numbers at once):

csharp
using System.Numerics.Tensors;   // NuGet: System.Numerics.Tensorsfloat score = TensorPrimitives.CosineSimilarity(a.Span, b.Span);

How we read the numbers. A sample: “without meat” ↔ lobio 0.71, ↔ mtsvadi 0.38. The absolute number depends on the model: on some models even completely unrelated texts show 0.4. So we don't judge a number on its own (“is 0.7 good?”), we compare: which one is closer. That's exactly what a search needs — ordering.

📘 Terms
Cosine similarity
a measure of how similar two vectors are, by the angle between them: 1 — the same direction, 0 — nothing in common
TensorPrimitives
a System.Numerics.Tensors class for vector computations (CosineSimilarity, Dot…), with SIMD

A semantic search for the menu

Slide 16

Two steps: indexing — the vectors of every dish on the menu are calculated once and stored; search — on every question only the question's vector is calculated and compared with every dish.

Where we keep the vectors (for now): in memory, in a Singleton service:

Ai/MenuIndex.cs
public class MenuIndex{    public List<(string Name, ReadOnlyMemory<float> Vector)> Items { get; } = [];}// Program.cs: builder.Services.AddSingleton<MenuIndex>();
Controllers/AiLabController.cs · menu/index, menu/search
[HttpPost("menu/index")]public async Task<IActionResult> IndexMenu(CancellationToken ct){    List<Product> products = await _db.Products.ToListAsync(ct);    GeneratedEmbeddings<Embedding<float>> vectors = await _embeddings.GenerateAsync(        products.Select(p => EmbeddingText.Document(p.Name, p.Description)),        cancellationToken: ct);     _menu.Items.Clear();    for (int i = 0; i < products.Count; i++)        _menu.Items.Add((products[i].Name, vectors[i].Vector));     return Ok(new { Indexed = products.Count });} [HttpGet("menu/search")]public async Task<IActionResult> SearchMenu(string q, CancellationToken ct){    ReadOnlyMemory<float> query = await _embeddings.GenerateVectorAsync(        EmbeddingText.Query(q), cancellationToken: ct);     var top = _menu.Items        .Select(m => new { m.Name, Score = TensorPrimitives.CosineSimilarity(query.Span, m.Vector.Span) })        .OrderByDescending(x => x.Score)        .Take(3);     return Ok(top);}
  • GenerateAsync(texts) — every dish in one call; vectors[i] is in the same order as products[i].
  • The document: title: name | text: description. The embedding only “sees” what we give it: if a dish has no description, the search is weak. (If Product has no Description, add one with a migration.)
  • The search: the question's vector (task: search result | query: …) → cosine with every dish → sort → the best three.

The result (sample): “without meat” → lobio 0.71, aubergine 0.68, salad 0.63. LIKE found 0.

Why don't we calculate the menu's vectors on every question? 200 dishes every time — money and seconds. The menu rarely changes: we calculate once and store. Again only when a dish is added or changed.

⚠️

For now the vectors are in memory: they disappear when the app restarts, and the search compares every vector one by one. On 200 dishes that's milliseconds, on a million documents it isn't. In lecture 10 we move the vectors to PostgreSQL (pgvector), with an index.

Summary

Slide 19
  • An embedding turns a text into a vector (a list of numbers) so that a similar meaning is close together — even across languages (“without meat” ≈ “ვეგეტარიანული”). This way search happens by meaning, not by words.
  • The vector is generated by a separate embedding model: ours is gemini-embedding-2, with 768 dimensions. One model — one “map”: vectors from different models can't be compared.
  • IEmbeddingGenerator — Microsoft.Extensions.AI's interface (next to IChatClient): AddEmbeddingGenerator, AsIEmbeddingGenerator(model, defaultModelDimensions), GenerateVectorAsync (one) and GenerateAsync (many).
  • Task prefix: the question — task: search result | query: …, the document — title: … | text: …. Always by the same rule.
  • Cosine similarity measures the angle between two vectors (1 — very similar, 0 — nothing in common). We compare the numbers, we don't judge them on their own. In .NET: TensorPrimitives.CosineSimilarity.
  • Semantic search: the menu's vectors once (GenerateAsync), on a question — only the question's vector, cosine with every dish, top 3.
