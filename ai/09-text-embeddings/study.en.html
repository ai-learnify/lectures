Text Embeddings: Vectorizing Text

🎯 After this lecture you can

  • You'll explain what an embedding and a vector are, why a similar meaning is “close”, and why vectors from different models can't be compared
  • You'll register an IEmbeddingGenerator (gemini-embedding-2, 768 dimensions) and get vectors with GenerateVectorAsync / GenerateAsync
  • You'll write the question and the document with the right task prefix and explain why the search is asymmetric
  • You'll calculate cosine similarity (by hand and with TensorPrimitives) and write a semantic search for the menu with a top 3

⚡ Key points

  1. Embedding: text → vector (a list of numbers) where similar meaning is close, regardless of language and wording.
  2. A vector is created by a separate embedding model. One model and size = one "map": changing the model means recomputing everything.
  3. IEmbeddingGenerator: GenerateVectorAsync for one text, GenerateAsync for many.
  4. Task prefix: the query and the document in different formats, always the same way.
  5. Cosine similarity measures an angle. We compare and rank results; we do not judge a number on its own.

What an embedding is

▶ Slides 6–9

The user writes "something light, without meat". A word search (LIKE) will not find it, because those words are not in the dish descriptions:

sql
SELECT "Name" FROM "Products" WHERE "Description" ILIKE '%without meat%';-- 0 results

An embedding turns text into a list of numbers: "Lobio in a clay pot" → [0.021, -0.047, 0.009, …]. Picture a map: texts with similar meaning are close, and "vegetarian" lands next to lobio even if you never mention the word "lobio". In reality it is 768 numbers, not 2.

The vector is created not by the chat model but by a separate embedding model (gemini-embedding-2). It does not write text; it only returns a vector.

✅ Check yourself think first, then open the answer
Can one model's vector be compared with another model's?
No: each model has its own "map". When you change the model, every vector has to be recomputed.
📘 Terms
embedding
turning text into a list of numbers so that similar meaning is close
vector
a list of numbers, the result of an embedding

Task prefix. A query is short, a document (a dish description) is long. We tell the model which is which:

Ai/Embeddings/EmbeddingInput.cs
public static class EmbeddingInput{    public static string Query(string q) =>        $"task: search result | query: {q}";     public static string Document(string title, string text) =>        $"title: {title} | text: {text}";}
⚠️

The prefix rule must be the same everywhere: when indexing and when searching.

Similarity and search

▶ Slides 14–16

A vector is an arrow pointing from the centre in some direction. Cosine similarity measures the angle between two arrows: 1 means the same direction, 0 means 90°. By hand:

By hand — how it's calculated
static float Cosine(ReadOnlySpan<float> a, ReadOnlySpan<float> b){    float dot = 0, na = 0, nb = 0;    for (int i = 0; i < a.Length; i++)    {        dot += a[i] * b[i];   // the dot product        na  += a[i] * a[i];   // the length of a, squared        nb  += b[i] * b[i];   // the length of b, squared    }    return dot / (MathF.Sqrt(na) * MathF.Sqrt(nb));}

The same in one line:

csharp
using System.Numerics.Tensors;   // NuGet: System.Numerics.Tensorsfloat score = TensorPrimitives.CosineSimilarity(a.Span, b.Span);

Menu search is two steps: indexing (every dish's vector is computed once) and search (the query's vector, then ranking by similarity):

Controllers/MenuController.cs · GenerateEmbeddings, Search
// temporary: the vectors in memory, lost when the app restarts (lecture 10 → database)private static List<(string Name, ReadOnlyMemory<float> Vector)> _vectors = []; [HttpPost("embeddings")]public async Task<IActionResult> GenerateEmbeddings(CancellationToken ct){    List<Product> products = await _db.Products.ToListAsync(ct);     GeneratedEmbeddings<Embedding<float>> vectors = await _embeddings.GenerateAsync(        products.Select(p => EmbeddingInput.Document(p.Name, p.Description)),        cancellationToken: ct);     _vectors = products        .Select((p, i) => (p.Name, vectors[i].Vector))        .ToList();     return Ok(new EmbeddingsResult(products.Count));} [HttpGet("search")]public async Task<IActionResult> Search(string query, CancellationToken ct){    ReadOnlyMemory<float> queryVector = await _embeddings.GenerateVectorAsync(        EmbeddingInput.Query(query), cancellationToken: ct);     List<MenuMatch> top = _vectors        .Select(v => new MenuMatch(v.Name,            TensorPrimitives.CosineSimilarity(queryVector.Span, v.Vector.Span)))        .OrderByDescending(m => m.Score)        .Take(3)        .ToList();     return Ok(top);}
⚠️

The vectors are in memory for now: they disappear on restart. In lecture 10 we move them into the database.

✅ Check yourself think first, then open the answer
Why don't we compute the menu vectors on every query?
Money and time: 200 dishes on every query. The menu rarely changes, so we compute them once.
Is a score of 0.71 good?
A number on its own says nothing. What matters is the ranking: which result is highest.
📘 Terms
cosine similarity
the similarity of two vectors by the angle between them: 1 is the same direction, 0 nothing in common

Semantic search in your project

With code · your project · a comparison table in the README

Requirements

  • IEmbeddingGenerator in your project: gemini-embedding-2, 768 dimensions, the model in appsettings.json
  • EmbeddingInput — the Query and Document prefixes; every document in one format, every question in the other
  • The index: POST .../embeddings — your main records (dishes, books, courses…) with GenerateAsync in one call, the vectors in memory for now (a static list); if a record has no description — add one
  • The search: GET .../search?query= — top 3 with scores, with a threshold: if the best score is below the threshold (the threshold in appsettings.json), return an empty list. Choose the threshold through your own tests
  • README — a comparison table: 5 questions (one in English, one about something that isn't in your data at all). Columns: question · the LIKE result · the embeddings top 3 with scores · correct?
  • The study notes quiz (8 questions) — write down your score
