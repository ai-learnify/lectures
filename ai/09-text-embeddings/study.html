Text Embeddings: ტექსტის ვექტორიზაცია

🎯 ამ ლექციის შემდეგ შეძლებ

  • ახსნი, რა არის embedding და ვექტორი, რატომ არის მსგავსი მნიშვნელობა „ახლოს“ და რატომ არ შეედრება სხვადასხვა მოდელის ვექტორები
  • IEmbeddingGenerator-ს დაარეგისტრირებ (gemini-embedding-2, 768 განზომილება) და GenerateVectorAsync / GenerateAsync-ით ვექტორებს მიიღებ
  • შეკითხვას და დოკუმენტს სწორი task prefix-ით ჩაწერ და ახსნი, რატომ არის ძებნა ასიმეტრიული
  • cosine similarity-ს გამოთვლი (ხელით და TensorPrimitives-ით) და მენიუს სემანტიკურ ძებნას დაწერ top 3-ით

⚡ მთავარი

  1. Embedding: ტექსტი → ვექტორი (რიცხვების სია), სადაც მსგავსი მნიშვნელობა ახლოსაა, ენისა და სიტყვების მიუხედავად.
  2. ვექტორს ცალკე embedding მოდელი ქმნის. ერთი მოდელი და ზომა = ერთი „რუკა“: მოდელის შეცვლა ყველაფრის თავიდან დათვლას ნიშნავს.
  3. IEmbeddingGenerator: GenerateVectorAsync ერთ ტექსტზე, GenerateAsync ბევრზე.
  4. task prefix: შეკითხვა და დოკუმენტი სხვადასხვა ფორმატით, ყოველთვის ერთნაირად.
  5. cosine similarity კუთხეს ზომავს. შედეგებს ვადარებთ და ვალაგებთ, ციფრს ცალკე არ ვაფასებთ.

📍 ლექცია გააცდინე?

  1. ნახე პრეზენტაცია: სლაიდები ლექციის მთელ გზას აჩვენებს
  2. წაიკითხე თემები: ~5 წთ, თითოს ბოლოს „შეამოწმე თავი“
  3. გაიარე ტესტი: 8 კითხვა
  4. გააკეთე დავალებები

რა არის embedding

▶ სლაიდები 6–9

მომხმარებელი წერს "something light, without meat". სიტყვებით ძებნა (LIKE) ამას ვერ იპოვის, რადგან კერძის აღწერაში ეს სიტყვები არ წერია:

sql
SELECT "Name" FROM "Products" WHERE "Description" ILIKE '%without meat%';-- 0 results

Embedding ტექსტს რიცხვების სიად აქცევს: "Lobio in a clay pot" → [0.021, -0.047, 0.009, …]. წარმოიდგინე რუკა: მსგავსი მნიშვნელობის ტექსტები ახლოსაა, და "vegetarian" ლობიოს გვერდით დაჯდება, თუნდაც სიტყვა „ლობიო“ არ ახსენო. სინამდვილეში ეს 768 რიცხვია და არა 2.

ვექტორს ჩატის მოდელი კი არ ქმნის, არამედ ცალკე embedding მოდელი (gemini-embedding-2). ის ტექსტს არ წერს, მხოლოდ ვექტორს აბრუნებს.

მსგავსება და ძებნა

▶ სლაიდები 14–16

ვექტორი ისარია, რომელიც ცენტრიდან რაღაც მიმართულებით იყურება. cosine similarity ორი ისრის კუთხეს ზომავს: 1 ნიშნავს ერთ მიმართულებას, 0 კი 90°-ს. ხელით:

ხელით — როგორ ითვლება
static float Cosine(ReadOnlySpan<float> a, ReadOnlySpan<float> b){    float dot = 0, na = 0, nb = 0;    for (int i = 0; i < a.Length; i++)    {        dot += a[i] * b[i];   // the dot product        na  += a[i] * a[i];   // the length of a, squared        nb  += b[i] * b[i];   // the length of b, squared    }    return dot / (MathF.Sqrt(na) * MathF.Sqrt(nb));}

იგივე ერთი ხაზით:

csharp
using System.Numerics.Tensors;   // NuGet: System.Numerics.Tensorsfloat score = TensorPrimitives.CosineSimilarity(a.Span, b.Span);

მენიუს ძებნა ორი ნაბიჯია: ინდექსაცია (ყველა კერძის ვექტორი ერთხელ ითვლება) და ძებნა (შეკითხვის ვექტორი და დალაგება მსგავსებით):

// temporary: the vectors in memory, lost when the app restarts (lecture 10 → database)private static List<(string Name, ReadOnlyMemory<float> Vector)> _vectors = []; [HttpPost("embeddings")]public async Task<IActionResult> GenerateEmbeddings(CancellationToken ct){    List<Product> products = await _db.Products.ToListAsync(ct);     GeneratedEmbeddings<Embedding<float>> vectors = await _embeddings.GenerateAsync(        products.Select(p => EmbeddingInput.Document(p.Name, p.Description)),        cancellationToken: ct);     _vectors = products        .Select((p, i) => (p.Name, vectors[i].Vector))        .ToList();     return Ok(new EmbeddingsResult(products.Count));} [HttpGet("search")]public async Task<IActionResult> Search(string query, CancellationToken ct){    ReadOnlyMemory<float> queryVector = await _embeddings.GenerateVectorAsync(        EmbeddingInput.Query(query), cancellationToken: ct);     List<MenuMatch> top = _vectors        .Select(v => new MenuMatch(v.Name,            TensorPrimitives.CosineSimilarity(queryVector.Span, v.Vector.Span)))        .OrderByDescending(m => m.Score)        .Take(3)        .ToList();     return Ok(top);}
