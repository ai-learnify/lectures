Let's recall: PostgreSQL pgvector and EF Core

1What three problems do vectors kept in memory have?They disappear on restart — everything is calculated again · the search compares everything one by one (O(n)) · the data is in two places — the description changes, the vector stays old
2What does <=> measure, and why do we sort ascending?cosine distance = 1 − similarity · 0 — the same direction · a small distance = close, so ORDER BY distance ASC · score 0.71 → distance 0.29
3Why does Product also store EmbeddingModel?One model — one map · when the model changes we know which vectors need recalculating · indexing calculates only those (and the nulls)
4What does it mean that HNSW is approximate? What is recall?ANN — it doesn't compare everything, it searches a graph by “floors”; very fast, but it can occasionally miss a correct one · recall — what share of the exact search results it found
5You created an HNSW index, but EXPLAIN shows a Seq Scan. Two possible reasons?The operator doesn't match the search (vector_l2_ops vs CosineDistance) · the table is small — a seq scan is cheaper for the planner, that's normal

Today's topic

Simple RAG: Answers from Documents

🤔Why you need this

“How do I cancel a booking?”, “I'm allergic to nuts” — the answer isn't in the menu but in the restaurant's PDFs, and the model doesn't know it. Putting the whole document into the context is expensive, fine-tuning is expensive and has no sources. RAG is exactly for this kind of task: the chatbots of banks, clinics and public services, internal knowledge assistants — they all work this way. Today we build our first complete RAG: PDF → parts → search → an answer with a source.

🎯By the end of the lecture you can

  • You'll explain RAG's two pipelines (ingestion and query) and why it beats the whole document in the context and fine-tuning
  • You'll extract text from a PDF page by page (PdfPig), cut it into parts with an overlap, and store the parts with vectors in a DocumentChunk table
  • You'll find the parts relevant to a question with a threshold and put them into the prompt as numbered sources
  • You'll plug RAG into lecture 7's chat: an answer with the source number, “I don't have information”, the original question in the history

Controllers/AiLabController.cs · SearchChunksAsyncprivate async Task<List<FoundChunk>> SearchChunksAsync(string q, CancellationToken ct){    float minScore = _config.GetValue<float>("Rag:MinScore");    var query = new Vector(await _embeddings.GenerateVectorAsync(        EmbeddingText.Query(q), cancellationToken: ct));     List<FoundChunk> top = await _db.DocumentChunks        .Where(c => c.Embedding != null)        .OrderBy(c => c.Embedding!.CosineDistance(query))        .Select(c => new FoundChunk(c.Document.FileName, c.Page, c.Content,            1 - c.Embedding!.CosineDistance(query)))        .Take(5)        .ToListAsync(ct);     return top.Where(c => c.Score >= minScore).ToList();}

Let's check

5 questions

1Why don't we put the whole PDF into the context, and why don't we train the model (fine-tuning)?The whole PDF — thousands of tokens on every question, slow, a large document doesn't fit, “lost in the middle” · fine-tuning — expensive, again on every change, it memorizes facts badly and can't name the source
2What are RAG's two pipelines, and when does each one run?ingestion — once, on upload: PDF → text → parts → vectors → database · query — on every question: vector → top 5 → prompt → an answer with a source
3Why do we cut a document into parts, and what do we need the overlap for?The vector of a whole document is the “average” of everything — blurry; a part = one idea, a precise vector and a cheap context · the overlap — the last sentence in the next part too, so an idea isn't cut at the boundary
4Why do we need a threshold in RAG's search?A search always finds something · without a threshold, for “a borscht recipe” the model would get 5 meaningless parts and might make something up · with a threshold — 0 parts and “I don't have information”
5Why do we store the original question in the chat history and not the message with the sources (augmented)?The sources are only for this request — others will be found next time · storing them in the history would inflate every message with 5 parts (the budget, lecture 7)
