1Does the model call our C# method itself? Describe the loop step by step.No · 1) us: the question + the list of tools · 2) the model: a call request (name + arguments) · 3) our code runs the method and sends the result · 4) the model: a text answer · at least 2 requests to Gemini
2The model can't see a tool's code. How does it learn what the tool does and when to call it?From the name, the description ([Description]) and the parameters' JSON Schema · so a bad description = the tool is called at the wrong time or not at all
3What it does .UseFunctionInvocation()do? What would happen without it?It runs the loop for us: sees the request, calls the method, sends the result, returns the final answer · without it GetResponseAsync would return a call request instead of text and we'd have to write the rest ourselves
4Why CheckAvailability(DateTime at, int guests) and not Check(string data)?The name says what it does · typed parameters go into the schema as exact types — the model doesn't have to guess a format and we don't have to parse a string · [Description] on each parameter
5Why did we give the model only read tools today? What would be the problem with create_booking?The model would call a writing tool by itself — it might take “8” as 8 a.m. and not ask the user · writing needs confirmation (human-in-the-loop, lecture 15)

Today's topic

Chat Client Pipeline and Middleware

🤔Why you need this

In lecture 4 one line, .UseFunctionInvocation(), ran the whole tool loop. Today we see that it's a layer around IChatClient— the same idea as ASP.NET Core middleware. With layers we add logging, caching and our own logic: counting tokens, guarding the input. And all of it without changing the Controller, only in Program.cs. In a real AI system, cost control, logging and protection live exactly here.

🎯By the end of the lecture you can

  • You'll explain what a chat client pipeline is: a layer = an IChatClient different IChatClient, and how the order of .Use…()calls matters
  • You'll switch on UseLoggingand see in the log how many requests went to Gemini for one tool question
  • You'll explain when UseDistributedCache helps and when it returns an old, wrong answer
  • You'll write your own layer with DelegatingChatClient: one that looks at the response and one that stops the request

A layer = DelegatingChatClient + one override

Ai/TokenCounterChatClient.csusing Microsoft.Extensions.AI; public class TokenCounterChatClient : DelegatingChatClient{    private readonly ILogger<TokenCounterChatClient> _logger;     public TokenCounterChatClient(IChatClient inner,        ILogger<TokenCounterChatClient> logger) : base(inner)    {        _logger = logger;    }     public override async Task<ChatResponse> GetResponseAsync(        IEnumerable<ChatMessage> messages,        ChatOptions? options = null,        CancellationToken cancellationToken = default)    {        // ↓ here is the request — it hasn't reached Gemini yet        ChatResponse response =            await base.GetResponseAsync(messages, options, cancellationToken);        // ↑ here is the response — Gemini has already answered         _logger.LogInformation("🔢 in: {In}, out: {Out}, total: {Total}",            response.Usage?.InputTokenCount,            response.Usage?.OutputTokenCount,            response.Usage?.TotalTokenCount);         return response;    }}
DelegatingChatClient: passes everything to the inner layer. We change only what we need
inner — the next layer. The logger — from DI
base— before: the request, base— after: the response. Like ASP.NET's await next()

Some layers watch, some stop

Ai/InputGuardChatClient.cspublic class InputGuardChatClient : DelegatingChatClient{    private const int MaxLength = 1000;     public InputGuardChatClient(IChatClient inner) : base(inner) { }     public override Task<ChatResponse> GetResponseAsync(        IEnumerable<ChatMessage> messages,        ChatOptions? options = null,        CancellationToken cancellationToken = default)    {        string? question = messages.LastOrDefault(m => m.Role == ChatRole.User)?.Text;         if (question is not null && question.Length > MaxLength)        {            ChatMessage answer = new(ChatRole.Assistant,                $"The question is too long — {MaxLength} characters at most.");            return Task.FromResult(new ChatResponse(answer));        }         return base.GetResponseAsync(messages, options, cancellationToken);    }}
