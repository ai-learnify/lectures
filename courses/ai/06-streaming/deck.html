## Lecture 6: Streaming and Real-time AI Responses Until now our endpoints returned the answer **whole**: the user stared at an empty screen for 2–8 seconds, and then all the text appeared at once. ChatGPT, Claude and Gemini show the answer **in pieces**, as it's being written. Today we do the same: we get the answer from Gemini in pieces (`GetStreamingResponseAsync`), send it to the client with **Server-Sent Events**, and add **cancellation**: if the user leaves, Gemini stops too and no more tokens are spent.

### Lecture plan: 3 steps 1. 🌊 **A stream from Gemini.** `GetStreamingResponseAsync` returns the answer in pieces (`IAsyncEnumerable`), and we read it with `await foreach`. The first piece arrives in under a second. 2. 📡 **SSE to the client.** We send the pieces to the user right away, with Server-Sent Events: one HTTP response that stays open. In .NET 10 we have `TypedResults.ServerSentEvents` for this. 3. ✋ **Cancellation.** If the user drops the connection, a `CancellationToken` stops the Gemini request too. At the end there's classwork: a streaming version of your chat.

### The problem: an empty screen Gemini writes the answer **token by token** (lecture 1: next-token prediction), and a long answer, thinking included, takes several seconds. Until now we used `GetResponseAsync`, which **waits until the end** and then returns all the text at once: | | What the user sees | |---|---| | `GetResponseAsync` | ~8 seconds of an empty screen, then all the text together | | **Streaming** | the first words in ~0.6 seconds, then the text gradually “gets written” | **The total time is almost the same**: Gemini writes at the same speed in both cases. The only thing that changes is **when** the user sees the first word. 8 seconds of an empty screen looks “broken”, while 8 seconds of text being written is normal: you start reading right away. That's why every AI chat (ChatGPT, Claude, Gemini, Copilot) streams. ```terms Streaming — getting and showing the answer in pieces, as it's written, rather than all at the end TTFT (time to first token) — the time from the request to the first token; streaming improves exactly this ```

### `GetStreamingResponseAsync`: პასუხი ნაწილ-ნაწილ `IChatClient`-ს ორი მეთოდი აქვს. აქამდე მხოლოდ პირველს ვიყენებდით: ```csharp // 1) ერთი პასუხი, ბოლოს ChatResponse response = await _chat.GetResponseAsync(messages); // 2) ბევრი ნაწილი, მოსვლისთანავე await foreach (ChatResponseUpdate update in _chat.GetStreamingResponseAsync(messages)) { Console.Write(update.Text); } ``` - **`IAsyncEnumerable`** — `IEnumerable`-ის ასინქრონული ვერსია. `foreach` ჩვეულებრივ სიას გადის, ხოლო **`await foreach`** შემდეგ ელემენტს **ელოდება**, რადგან ის ჯერ არ არსებობს: Gemini ჯერ წერს. ციკლის სხეული თითო ნაწილზე მაშინვე სრულდება, როგორც კი ნაწილი მოვიდა. - **`ChatResponseUpdate`** — პასუხის ერთი ნაწილი: `Text` (ტექსტის ნაჭერი), `Role`, ხოლო ბოლო ნაწილებში `FinishReason` და ტოკენები (`UsageContent`). - **არგუმენტები იგივეა:** `messages`, `options` (tool-ების ჩათვლით), `cancellationToken`. `UseFunctionInvocation` სტრიმინგშიც მუშაობს: tool-ის ციკლი ჯერ შიგნით სრულდება, მერე ტექსტი იწყებს მოსვლას. ```terms IAsyncEnumerable — ელემენტების ნაკადი, რომლის თითო ელემენტი ასინქრონულად მოდის; იკითხება await foreach-ით ChatResponseUpdate — სტრიმინგ პასუხის ერთი ნაწილი: ტექსტის ნაჭერი და მეტამონაცემები ```
### `GetStreamingResponseAsync`: the answer in pieces `IChatClient` has two methods. Until now we've only used the first one: ```csharp // 1) one answer, at the end ChatResponse response = await _chat.GetResponseAsync(messages); // 2) many pieces, as they arrive await foreach (ChatResponseUpdate update in _chat.GetStreamingResponseAsync(messages)) { Console.Write(update.Text); } ``` - **`IAsyncEnumerable`** — the asynchronous version of `IEnumerable`. A `foreach` walks an ordinary list, while **`await foreach`** **waits** for the next item, because it doesn't exist yet: Gemini is still writing. The loop body runs for each piece right away, as soon as it arrives. - **`ChatResponseUpdate`** — one piece of the answer: `Text` (a chunk of text), `Role`, and in the last pieces `FinishReason` and the tokens (`UsageContent`). - **The arguments are the same:** `messages`, `options` (tools included), `cancellationToken`. `UseFunctionInvocation` works with streaming too: the tool loop finishes inside first, then the text starts arriving. ```terms IAsyncEnumerable — a stream of items where each item arrives asynchronously; read with await foreach ChatResponseUpdate — one piece of a streaming answer: a chunk of text and metadata ```
