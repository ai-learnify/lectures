## 🎯 მთავარი

`/stream-timing`-ს კლასთან ერთად წერ, `/chat/stream`-ს მზას ჩასვამ. ტერმინალი (curl) პროექტორზე უნდა ჩანდეს. სრული კოდი 💻 ღილაკზეა.

### 📌 სტუდენტს უნდა დარჩეს

1. სტრიმინგი ამცირებს **TTFT**-ს (პირველი სიტყვის დრო) და არა მთლიან დროს.
2. `GetStreamingResponseAsync` → `IAsyncEnumerable<ChatResponseUpdate>` → `await foreach`. tool-ებიც მუშაობს.
3. სიაში შეგროვება სტრიმს წყვეტს, `yield return` არა.
4. SSE ჩვეულებრივი HTTP-ია: `text/event-stream`, კავშირი ღიაა. `TypedResults.ServerSentEvents`, შემოწმება `curl -N`-ით.
5. `CancellationToken` სამ ადგილას: მომხმარებელი წავიდა → Gemini ჩერდება.

### ✅ მომზადება

- RestaurantApi-ში წინასწარ დაწერე `/stream-timing`, `CreateChatOptions()`, `/chat/stream` და გაუშვი

შესვენებიდან: **„HTTP პასუხი ერთია. როგორ გავუგზავნოთ ნაწილი, სანამ მთელი მზად არ არის?“** მერე: **„tool-იან კითხვაზე პირველი სიტყვა რატომ იგვიანებს?“** სწორი: ჯერ tool-ის ციკლი სრულდება (Gemini-ს ორი მოთხოვნა), და მხოლოდ მეორე მოთხოვნის პასუხი სტრიმავს.

### 🆘 თუ ვერ გაიგეს

- **„ერთი HTTP პასუხი ნაწილ-ნაწილ?“ →** „სერვერი header-ს აგზავნის, მერე body-ს ნაწილ-ნაწილ წერს. ფაილის ჩამოტვირთვაც ასე მუშაობს“.

### 🙋 ჰკითხე

### 🆘 თუ ვერ გაიგეს

- **ჯაჭვი დაფაზე:** curl დაიხურა → Kestrel → `RequestAborted` → ① action → ② iterator → ③ Gemini-ს HTTP მოთხოვნა წყდება.
- **„`[EnumeratorCancellation]` რატომ?“ →** iterator-ს token ორი გზით მოსდის (პარამეტრით და `WithCancellation`-ით), ატრიბუტი ორივეს აერთიანებს. მის გარეშე CS8425 გაფრთხილება ჩნდება.
