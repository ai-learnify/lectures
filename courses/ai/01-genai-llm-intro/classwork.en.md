# Planning an AI feature — in pairs

Task · RestaurantApi or your project · no code: fill in a table in your notebook

## Steps

- **1 · Come up with 2 AI features** — for your project or for RestaurantApi (not menu recommendation — we did that together)
- **2 · Fill in the table for each**, as in the example: what goes in · what comes out · what comes **from the database** · Temperature and Max Tokens · how many tokens (with Tiktokenizer)

## ✓ Done when

Both tables are filled in; one pair presents to the class and the others ask questions

## ⭐ Bonus

- Which feature needs a reasoning model, and which doesn't?
- What can go wrong: what will the model say if we don't give it the database data?

## 💡 Ideas, if you're stuck

- **Booking from the chat:** “Four of us tomorrow at 8” → date, time, guests
- **Review summary:** 50 comments → “what they like, what they complain about”
- **Order status:** “Where is my order?”
- **Dish description for the menu:** ingredients → an appealing text

## 💡 Tip

We don't write code today — we think like an AI engineer: what the model does, what our code does, what it costs. This plan continues in the homework, and you'll build it over the module.
