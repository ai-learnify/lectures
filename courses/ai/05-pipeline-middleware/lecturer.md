`ChatClientBuilder` შიგნით ინახავს **factory-ების სიას** — ყოველი `.Use…()` ერთ factory-ს ამატებს: `Func<IChatClient, IServiceProvider, IChatClient>` — „მომეცი შიდა client და მე მის გარშემო ფენას დავაბრუნებ“. `Build()` (`AddChatClient`-ის შემთხვევაში DI თვითონ იძახებს, `IChatClient`-ის პირველი მოთხოვნისას) factory-ებს **ბოლოდან** ასრულებს:

```
inner = Gemini client
inner = Logging(inner)            ← last .Use — created first, innermost
inner = FunctionInvocation(inner) ← first .Use — created last, outermost
return inner                       ← this goes into DI as the IChatClient
```

ამიტომ **პირველი `.Use…()` = გარე ფენა**. ზუსტად ASP.NET Core-ის middleware-ის წესი: `app.Use…()`-ის რიგით გადის მოთხოვნა.

#### Decorator ნიმუში

ყოველი ფენა ახორციელებს `IChatClient`-ს და შიგნით სხვა `IChatClient`-ს ინახავს. ეს GoF-ის **decorator**-ია: ობიექტს ფუნქციონალს ვუმატებთ მისი „შეფუთვით“, კლასის შეცვლის გარეშე. ASP.NET Core-ის `HttpClient`-ის `DelegatingHandler`-იც იგივე ნიმუშია (თუ API კურსზე `AddHttpMessageHandler` ნახეთ).

#### Lifetime

`AddChatClient` ნაგულისხმევად Singleton-ს არეგისტრირებს (ლექცია 3) — მთელი pipeline **ერთხელ** იქმნება. ფენებიც Singleton-ია. **მნიშვნელოვანია:** ფენაში Scoped სერვისს (მაგ. `DbContext`) constructor-ით ვერ ჩასვამ — captive dependency. თუ ფენას ბაზა სჭირდება (მაგ. მომხმარებლის ლიმიტი) — `IServiceScopeFactory` ან `IHttpContextAccessor`. ეს ლექცია 8-ის თემაა; დღეს ჩვენი ფენები მხოლოდ `ILogger`-ს იღებენ (Singleton-ისთვის უსაფრთხოა).

#### `UseLogging()`

- `UseLogging(ILoggerFactory? loggerFactory = null, …)` — თუ ფაქტორი არ გადაეცი, DI-დან იღებს (`AddChatClient`-ით რეგისტრირებულ pipeline-ში ასეა). თუ DI-ში ლოგირება „გამორთულია“ (`NullLoggerFactory`), ფენა საერთოდ არ ემატება.

### 📖 ისწავლე: DelegatingChatClient

#### რა არის `DelegatingChatClient`

აბსტრაქტული კლასი `Microsoft.Extensions.AI`-ში. ახორციელებს `IChatClient`-ს და **ყველა** მეთოდს (`GetResponseAsync`, `GetStreamingResponseAsync`, `GetService`, `Dispose`) შიდა client-ს (`InnerClient`) გადასცემს. ჩვენ ვცვლით მხოლოდ საჭიროს.

**ყურადღება:** თუ მხოლოდ `GetResponseAsync`-ს გადავფარავთ, `GetStreamingResponseAsync` **უცვლელად** გადის — ფენა სტრიმინგზე არ მუშაობს. ეს შეცდომა არ არის, მაგრამ უნდა იცოდე — ლექცია 6-ის ხიდია.

#### სამი სახის ფენა

| სახე | კოდი | მაგალითი |
|---|---|---|
| **უყურებს** | base → შემდეგ პასუხის წაკითხვა | TokenCounter, დროის გაზომვა, აუდიტის ლოგი |
| **ცვლის** | base-მდე `messages`/`options`-ის შეცვლა, ან base-ის შემდეგ პასუხის | ნაგულისხმევი `MaxOutputTokens`, System prompt-ის დამატება, PII-ის დამალვა პასუხში |
| **აჩერებს** | base-ის გარეშე პასუხის დაბრუნება ან exception | InputGuard, rate limit, ხარჯის ლიმიტი |

#### `Use` overload-ები

```csharp
.Use(inner => new InputGuardChatClient(inner))                           // only the inner client
.Use((inner, sp) => new TokenCounterChatClient(inner, sp.GetRequiredService<ILogger<TokenCounterChatClient>>()))  // + DI
.Use(async (messages, options, next, ct) => { …; await next(messages, options, ct); })  // lambda — for both methods, but it can't see the response
```

მესამე ფორმა („shared delegate“) მოკლეა და `GetResponseAsync`-საც და სტრიმინგსაც ფარავს, მაგრამ **პასუხს ვერ ხედავს** — მხოლოდ მოთხოვნას (შეცვლა ან შეჩერება exception-ით). TokenCounter-ისთვის არ გამოდგება. ჩვენ კლასს ვწერთ — ცხადია და სტრიმინგსაც ლექცია 6-ზე იმავე კლასში დავამატებთ.

#### რიგი TokenCounter-ზე — რატომ 1 ან 2 ხაზი

`FunctionInvokingChatClient` ციკლის ყველა მოთხოვნის `Usage`-ს **აჯამებს** და Controller-ს ერთ `ChatResponse`-ს უბრუნებს ჯამური `Usage`-ით. ამიტომ:

- **გარეთ** (A) — ერთი ხაზი, ჯამი („რა დაჯდა მომხმარებლის შეკითხვა“).
- **შიგნით** (B) — თითო ხაზი Gemini-ს ყოველ მოთხოვნაზე („რომელი ნაბიჯია ძვირი“). მეორე ძვირია — მასში ისტორია და tool-ის შედეგია.

- მხოლოდ **ბოლო მომხმარებლის** შეტყობინებას ვამოწმებთ — System prompt ჩვენია, ისტორია (ლექცია 7) უკვე შემოწმებულია.

### 🔬 უფრო ღრმად — თუ ჰკითხავენ

**`GetService`.** `IChatClient.GetService(typeof(X))` pipeline-ში ფენას ეძებს — მაგ. `chat.GetService<FunctionInvokingChatClient>()` ან `ChatClientMetadata` (პროვაიდერის სახელი, მოდელი). `DelegatingChatClient` ჯერ საკუთარ თავს ამოწმებს, მერე შიდას გადასცემს.

### ✏️ ფენა, რომელიც ცვლის · 6 წთ

მესამე სახის ფენა — არც უყურებს, არც აჩერებს: **ცვლის**.

```csharp GeorgianOnlyChatClient — მხოლოდ საჩვენებლად
public class GeorgianOnlyChatClient : DelegatingChatClient
{
    public GeorgianOnlyChatClient(IChatClient inner) : base(inner) { }

    public override Task<ChatResponse> GetResponseAsync(IEnumerable<ChatMessage> messages,
        ChatOptions? options = null, CancellationToken cancellationToken = default)
    {
        List<ChatMessage> changed = [new(ChatRole.System, "Always answer in Georgian."), .. messages];
        return base.GetResponseAsync(changed, options, cancellationToken);
    }
}
```

1. `.Use(inner => new GeorgianOnlyChatClient(inner))` → `/ask` ინგლისურად „What is RAG?“ → პასუხი ქართულად.
2. 🙋 „რატომ ახალი სია და არა `messages.Add`?“ → `messages` Controller-ის სიაა; ფენამ სხვისი ობიექტი არ უნდა შეცვალოს.
3. დასკვნა: ასე ემატება კომპანიის „ზოგადი წესები“ ყველა მოთხოვნას — Controller-ების შეხების გარეშე.

### 📡 OpenTelemetry · 8 წთ

ლექცია 20-ის წინასწარი ნახვა.

1. `dotnet add package OpenTelemetry.Extensions.Hosting` და `OpenTelemetry.Exporter.Console`.
2. Program.cs:

```csharp OpenTelemetry — მხოლოდ საჩვენებლად
builder.Services.AddOpenTelemetry()
    .WithTracing(t => t.AddSource("RestaurantApi.AI").AddConsoleExporter());

builder.Services.AddChatClient(gemini)
    .UseFunctionInvocation()
    .UseOpenTelemetry(sourceName: "RestaurantApi.AI");
```

3. `/chat` → კონსოლში Activity: სახელი (`chat gemini-…`), ხანგრძლივობა, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, tool-ის გამოძახება ცალკე span-ად.
4. დასკვნა: ლოგი = ტექსტი; ტელემეტრია = სტრუქტურირებული მონაცემი, რომლითაც დაშბორდები და alert-ები შენდება. Aspire Dashboard-ში ეს ვიზუალურად ჩანს — ლექცია 20.

### 🔁 lambda-ფენა · 4 წთ

```csharp lambda — მხოლოდ საჩვენებლად
.Use(async (messages, options, next, ct) =>
{
    if (messages.LastOrDefault()?.Text?.Length > 1000)
        throw new InvalidOperationException("Too long");
    await next(messages, options, ct);
})
```

🙋 „TokenCounter ასე დაიწერება?“ → არა: `next` პასუხს არ აბრუნებს — lambda-ფენა მხოლოდ მოთხოვნას ხედავს. სამაგიეროდ ორივე მეთოდს (ჩვეულებრივს და სტრიმინგს) ერთად ფარავს. ლექცია 6-ზე ეს მნიშვნელოვანი იქნება.

### ⚙️ ConfigureOptions · 3 წთ

`.ConfigureOptions(o => o.MaxOutputTokens ??= 2000)` — ყველა მოთხოვნას ნაგულისხმევ ლიმიტს უწერს, თუ Controller-მა თვითონ არ მიუთითა. 🙋 „სად გამოგვადგება?“ → ხარჯის კონტროლი (ლექცია 8). ⚠️ Gemini-ს ფიქრის ტოკენები (ლექცია 2) — ლიმიტი არ უნდა იყოს მცირე.
