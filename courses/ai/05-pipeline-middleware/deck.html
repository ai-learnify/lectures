## Lecture 5: The Chat Client Pipeline and Middleware In lecture 4 we added one line to `Program.cs`, `.UseFunctionInvocation()`, and it ran the whole tool loop. Today we see what that line really is: a **layer** (middleware) around `IChatClient`. There are several ready-made layers (logging, caching), and we can write our own: e.g. a layer that counts tokens on every request, or one that doesn't let a too-long question reach Gemini. The Controllers don't change at all.

### `.UseFunctionInvocation()` — what is it In lecture 4 this one line ran the whole tool loop. Where have we seen a similar `.Use…()`? ### The pipeline: layers around the client Each layer is itself an **`IChatClient`** that holds another `IChatClient` inside (this is called the decorator pattern). The Controller calls the outer layer, it calls the inner one, and so on down to the Gemini client: ``` Controller → FunctionInvocation → Logging → Gemini client → Google ← ← ← ← ``` - **The request** goes from left to right, **the response** comes back. Every layer sees both: it can change the request, look at the response, or stop the request altogether. - **`FunctionInvocation`** works like this: it lets the request in, sees a tool request in the response, calls the method and sends the request **in again**. That's why two requests reach Gemini, while the Controller gets one response. - **Order:** the **first** `.Use…()` in `Program.cs` is **closest** to the Controller (the outer layer), and the last one is closest to Gemini. ```csharp Program.cs builder.Services.AddChatClient(gemini) // inside: the Gemini client .UseFunctionInvocation() // 1 — outer layer (close to the Controller) .UseLogging(); // 2 — inner layer (close to Gemini) ``` **The Controller knows nothing** about the layers: it gets an `IChatClient` through the constructor. Adding or removing a layer happens only in `Program.cs`. It's the same benefit as with lecture 3's DI: the Controller's code doesn't change. ```terms Pipeline — a chain of layers from the Controller to Gemini; the request goes in, the response comes back ```

### `UseLogging`: what happens between the Controller and Gemini ```csharp Program.cs builder.Services.AddChatClient( new Client(apiKey: apiKey).AsIChatClient(model)) .UseFunctionInvocation() .UseLogging(); ``` `UseLogging()` takes the logger from DI by itself (`ILoggerFactory`), just like your services in the API course. Every request of the `FunctionInvocation` loop passes through it. ```warn At the **Trace** level (`"Microsoft.Extensions.AI": "Trace"`) the log also contains the **full text** of the request and the response: users' questions, tool results. ### `InputGuardChatClient`: a layer that stops `TokenCounter` only **looks** at the response. A layer can also **stop** the request: if we don't call `base`, the request doesn't go any further in. ```csharp Ai/InputGuardChatClient.cs public class InputGuardChatClient : DelegatingChatClient { private const int MaxLength = 1000; public InputGuardChatClient(IChatClient inner) : base(inner) { } public override Task GetResponseAsync( IEnumerable messages, ChatOptions? options = null, CancellationToken cancellationToken = default) { string? question = messages.LastOrDefault(m => m.Role == ChatRole.User)?.Text; if (question is not null && question.Length > MaxLength) { ChatMessage answer = new(ChatRole.Assistant, $"The question is too long — {MaxLength} characters at most."); return Task.FromResult(new ChatResponse(answer)); } return base.GetResponseAsync(messages, options, cancellationToken); } } ``` - **`messages.LastOrDefault(m => m.Role == ChatRole.User)`** — the user's last question (we don't check the System prompt, it's ours). - **Too long?** We create the response **ourselves** and return it. `base` isn't called → no request goes to Gemini: 0 tokens, 0 GEL. This is called a **short-circuit**. ASP.NET Core middleware returns, say, a `401` the same way. - **We don't need `async` here**: we don't await anything, so we return `Task.FromResult` or `base`'s `Task` directly. **The full pipeline in RestaurantApi:** ```csharp Program.cs builder.Services.AddChatClient( new Client(apiKey: apiKey).AsIChatClient(model)) .Use(inner => new InputGuardChatClient(inner)) // 1 — stops earliest .UseFunctionInvocation() // 2 — the tool loop .Use((inner, sp) => new TokenCounterChatClient( // 3 — every Gemini request inner, sp.GetRequiredService>())) .UseLogging(); // 4 — closest to Gemini ``` **Why is the guard first?** The earlier we stop, the less work: a blocked request reaches neither the tool loop, nor the counter, nor the log. ```warn A stopped request returns **text**. If an endpoint calls `GetResponseAsync` (lecture 3, `parse-booking`), that text isn't JSON and `.Result` will throw an exception. Use `TryGetResult` there (lecture 3's ⭐), or guard at the endpoint itself, with a `400`. ``` ```terms Short-circuit — a layer doesn't pass the request to the next layer and returns a response itself ```

Controller ფენებზე არაფერს იცის. - **რიგი:** პირველი `.Use…()` გარე ფენაა (Controller-თან ახლოს), ბოლო შიდა (Gemini-სთან ახლოს). რიგი შედეგს ცვლის. - **`UseLogging`** — ჩანს, რამდენი მოთხოვნა წავიდა Gemini-სთან. ## Summary - **`ChatClientBuilder`** — what `AddChatClient` returns. Every `.Use…()` adds one **layer** (middleware) to the `IChatClient`. `.UseFunctionInvocation()` is one such layer. - **A layer = an `IChatClient` around another `IChatClient`.** The request goes in, the response comes back, and every layer sees both. The Controller knows nothing about the layers. - **Order:** the first `.Use…()` is the outer layer (close to the Controller), the last is the inner one (close to Gemini). Order changes the result. - **`UseLogging`** — shows how many requests went to Gemini. The Trace level writes the full text: development only. - **`UseDistributedCache`** — doesn't call Gemini for exactly the same request. Only where the answer doesn't change. Not in a chat with tools. - **`DelegatingChatClient`** — your own layer: code before `base` sees the request, code after `base` sees the response. If you don't call `base`, the request is stopped (short-circuit). ### Next lecture Both our layers only cover `GetResponseAsync`. But ChatGPT and Claude don't return the answer all at once: the text appears word by word. In lecture 6: **Streaming** — `GetStreamingResponseAsync`, Server-Sent Events and cancellation. And we'll see what happens to our layers when the response comes in pieces.
