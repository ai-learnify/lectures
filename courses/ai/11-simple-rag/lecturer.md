# ლექტორისთვის · ლექცია 11

## 🎯 მთავარი

`UploadDocument`-ს და `/chat`-ის ცვლილებას კლასთან ერთად წერ. `PdfText`-ს, `TextChunker`-ს, entity-ებს, `SearchChunksAsync`-ს და წესებს მზას ჩასვამ. სრული კოდი 💻 ღილაკზეა.

### 📌 სტუდენტს უნდა დარჩეს

1. RAG = retrieve → augment → generate. რატომ არ ვაგზავნით მთელ PDF-ს და რატომ არა fine-tuning.
2. ორი pipeline: ingestion ერთხელ, query ყოველ შეკითხვაზე.
3. chunk = ერთი აზრი (~800 სიმბოლო, overlap-ით). გვერდს წყაროს მისათითებლად ვინახავთ.
4. ზღვარი + წესები prompt-ში → „ინფორმაცია არ მაქვს“ მოგონების ნაცვლად.
5. ისტორიაში ორიგინალი შეკითხვა ინახება. წყაროები მხოლოდ ამ მოთხოვნაში მიდის.

## 3 · Ingestion · 16 წთ · 9–12

- (10) PDF = ასოები კოორდინატებით. `PdfText` **ჩასვი**: `ContentOrderTextExtractor` და გაწმენდა. ცოცხლად: ერთი გვერდის ტექსტი კონსოლში. ⚠️ სკანი ცარიელს აბრუნებს
- (11) chunking: ორი ნაწილი ეკრანზე, overlap ფერით. `TextChunker` **ჩასვი**, ერთი წინადადებით ახსენი
- (12) **ერთად წერთ** `UploadDocument`, entity-ები ჩასვი. Swagger: `rules.pdf` → `chunks: N`. psql: `SELECT "Page", left("Content", 60) FROM "DocumentChunks"`

### 🙋 ჰკითხე

(10) **„PDF-ში სიტყვები წერია?“** → არა. (11) **„მთელი PDF ერთ ვექტორად?“** → ბუნდოვანი გამოვა. **„ნაწილი ერთი წინადადება რომ იყოს?“** → ვექტორი ზუსტია, მაგრამ კონტექსტი იკარგება. (12) **„ლექცია 10-თან რა არის ახალი?“** → მხოლოდ PDF და chunking.

### 🆘 თუ ვერ გაიგეს

- **regex `(?<=[.!?])\s+` →** „ჰარი, რომლის წინაც წერტილი, კითხვის ან ძახილის ნიშანია, იქ ვჭრით“. regex-ის სიღრმე არ სჭირდებათ.
- **`TakeLast(overlap)` →** დაფაზე [ა, ბ, გ] → ნაწილი, შემდეგი [გ]-ით იწყება.
- **entity-ები →** „ორი ცხრილია: დოკუმენტი და მისი ნაწილები. ნაწილს აქვს გვერდი, ტექსტი, ვექტორი“.
