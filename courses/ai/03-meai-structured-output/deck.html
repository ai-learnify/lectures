### What's wrong with the lecture 2 code In lecture 2 we created `IChatClient` right inside the Controller, so that our attention stayed on the model: ```csharp Controllers/AiLabController.cs · lecture 2 private readonly IChatClient _chat = new Client().AsIChatClient("gemini-3.8-flash"); ``` It works, but it has three problems: | | Problem | Why it's bad | |---|---|---| | ♻️ | **A new client on every request** | ASP.NET Core creates a Controller anew for every request. The `_chat` field is created with it — a new client and a new HTTP connection every time. On a server that's a waste of resources | | 📌 | **The model name is in the code** | To switch to another model you have to change the code and deploy again | | 🧪 | **It can't be tested** | The Controller creates the Gemini client itself. In a test we can't plug in a fake client — every test would call the real Gemini and spend money | You already know this from the API course: we don't create a `DbContext` with `new` in a Controller — **we register it in DI and receive it through the constructor**. The same rule applies to `IChatClient`.

### `Program.cs`: `AddChatClient` `IChatClient`-ს ერთხელ ვქმნით, აპლიკაციის გაშვებისას, და DI-ში ვარეგისტრირებთ: ```csharp Program.cs using Google.GenAI; using Microsoft.Extensions.AI; var builder = WebApplication.CreateBuilder(args); string apiKey = builder.Configuration["Gemini:ApiKey"] ?? throw new InvalidOperationException("Gemini:ApiKey აკლია"); string model = builder.Configuration["Gemini:Model"] ?? throw new InvalidOperationException("Gemini:Model აკლია"); builder.Services.AddChatClient( new Client(apiKey: apiKey).AsIChatClient(model)); builder.Services.AddControllers(); // ... დანარჩენი — როგორც იყო ``` - **`AddChatClient(...)`** — `Microsoft.Extensions.AI`-ის extension. `IChatClient`-ს არეგისტრირებს **Singleton**-ად: მთელ აპლიკაციაზე ერთი client, ერთი HTTP კავშირების pool. Gemini-ს client thread-safe-ია, ამიტომ ერთდროულ მოთხოვნებს უპრობლემოდ ემსახურება. - **`new Client(apiKey: apiKey)`** — key-ს ახლა ცხადად გადავცემთ, კონფიგურაციიდან. - **`?? throw`** — თუ key ან მოდელი არ წერია, აპლიკაცია **გაშვებისთანავე** ჩავარდება გასაგები შეცდომით, და არა პირველ მოთხოვნაზე, უცნაური 401-ით. **მოდელის სახელი** — `appsettings.json`-ში. ეს საიდუმლო არ არის, Git-შიც მიდის: ```json appsettings.json { "Gemini": { "Model": "gemini-3.8-flash" } } ``` **key** — **User Secrets**-ში. ეს ფაილი შენს კომპიუტერზე, პროექტის გარეთ ინახება და Git-ში არასდროს ხვდება. ტერმინალში, პროექტის საქაღალდეში: ```bash dotnet user-secrets init dotnet user-secrets set "Gemini:ApiKey" "AIza..." ``` Visual Studio-ში იგივე: პროექტზე მარჯვენა ღილაკი → **Manage User Secrets** → იხსნება `secrets.json`: ```json secrets.json { "Gemini:ApiKey": "AIza..." } ``` `builder.Configuration["Gemini:ApiKey"]` ორივე ადგილიდან ერთნაირად კითხულობს — კოდმა არ იცის, სად წერია მნიშვნელობა. ```note სერვერზე User Secrets არ არსებობს — იქ იგივე მნიშვნელობა გარემოს ცვლადით მიდის: `Gemini__ApiKey` (ორი ქვედა ტირე = `:`). კოდი არ იცვლება. ამას DevOps-ში, deploy-ზე ვნახავთ. ``` ```terms AddChatClient — Microsoft.Extensions.AI-ის მეთოდი, რომელიც IChatClient-ს DI-ში არეგისტრირებს (ნაგულისხმევად Singleton) User Secrets — დეველოპერის კომპიუტერზე, პროექტის გარეთ შენახული კონფიგურაცია საიდუმლოებისთვის; Git-ში არ ხვდება ```
### `Program.cs`: `AddChatClient` We create `IChatClient` once, when the application starts, and register it in DI: ```csharp Program.cs using Google.GenAI; using Microsoft.Extensions.AI; var builder = WebApplication.CreateBuilder(args); string apiKey = builder.Configuration["Gemini:ApiKey"] ?? throw new InvalidOperationException("Gemini:ApiKey is missing"); string model = builder.Configuration["Gemini:Model"] ?? throw new InvalidOperationException("Gemini:Model is missing"); builder.Services.AddChatClient( new Client(apiKey: apiKey).AsIChatClient(model)); builder.Services.AddControllers(); // ... the rest — as it was ``` - **`AddChatClient(...)`** — an extension from `Microsoft.Extensions.AI`. It registers `IChatClient` as a **Singleton**: one client for the whole application, one pool of HTTP connections. The Gemini client is thread-safe, so it serves concurrent requests without problems. - **`new Client(apiKey: apiKey)`** — now we pass the key explicitly, from configuration. - **`?? throw`** — if the key or the model is missing, the application fails **right at startup** with a clear error, not on the first request with a strange 401. **The model name** goes in `appsettings.json`. It isn't a secret, it goes to Git too: ```json appsettings.json { "Gemini": { "Model": "gemini-3.8-flash" } } ``` **The key** goes in **User Secrets**. This file is stored on your computer, outside the project, and never ends up in Git. In the terminal, in the project folder: ```bash dotnet user-secrets init dotnet user-secrets set "Gemini:ApiKey" "AIza..." ``` The same in Visual Studio: right-click the project → **Manage User Secrets** → `secrets.json` opens: ```json secrets.json { "Gemini:ApiKey": "AIza..." } ``` `builder.Configuration["Gemini:ApiKey"]` reads from both places the same way — the code doesn't know where the value is written. ```note User Secrets don't exist on a server — there the same value comes from an environment variable: `Gemini__ApiKey` (two underscores = `:`). The code doesn't change. We'll see this in DevOps, at deploy time. ``` ```terms AddChatClient — the Microsoft.Extensions.AI method that registers IChatClient in DI (Singleton by default) User Secrets — configuration for secrets stored on the developer's computer, outside the project; it never goes to Git ```

## Part 2 · Structured output In lecture 2 we used few-shot to make the model return the exact word almost every time. “Almost” isn't enough for code. **Structured output** doesn't ask the model to “answer with one word” — it asks it to “answer in exactly the shape of this C# type”.

### few-shot: „თითქმის“ ყოველთვის საშინაოში `classify` endpoint few-shot-ით დაწერე. უმეტესად ზუსტ სიტყვას აბრუნებს, მაგრამ ხანდახან — `Search.`, `search` ან მთელ წინადადებას. ეს ყველაფერი `string`-ია, და `if (label == "Search")` მათზე ჩავარდება. few-shot მოდელს **სთხოვს** ფორმას: მაგალითებით ვაჩვენებთ, მოდელი კი ალბათობით იმეორებს. ალბათობა ≠ გარანტია (ლექცია 1). **იდეა:** რა იქნება, თუ პასუხი `string` კი არა, C# **enum** იქნება? ```csharp public enum RequestType { Search, Reserve, Question } ``` `RequestType` ტიპის ცვლადში `"Search."` ვერ მოხვდება — მხოლოდ სამი მნიშვნელობიდან ერთი. ზუსტად ამას აკეთებს **structured output**: მოდელს ფორმას **აიძულებს**, და არა სთხოვს.
### few-shot: “almost” always In the homework you wrote a `classify` endpoint with few-shot. It mostly returns the exact word, but sometimes — `Search.`, `search` or a whole sentence. All of it is a `string`, and `if (label == "Search")` fails on them. Few-shot **asks** the model for a shape: we show it with examples, and the model repeats it with some probability. Probability ≠ a guarantee (lecture 1). **The idea:** what if the answer were not a `string` but a C# **enum**? ```csharp public enum RequestType { Search, Reserve, Question } ``` `"Search."` can't get into a variable of type `RequestType` — only one of the three values can. That's exactly what **structured output** does: it **forces** the shape on the model instead of asking for it.

### `GetResponseAsync`: an enum The lecture 2 `ReviewSentiment` worked with few-shot. Now we write the same endpoint with an enum: ```csharp Controllers/AiLabController.cs · ReviewSentiment public enum Sentiment { Positive, Negative, Mixed } [HttpPost("review-sentiment")] public async Task ReviewSentiment(AskRequest request) { List messages = [ new(ChatRole.System, "Classify the restaurant review."), new(ChatRole.User, request.Prompt) ]; ChatResponse response = await _chat.GetResponseAsync(messages); Sentiment sentiment = response.Result; if (sentiment == Sentiment.Negative) { /* notify the manager */ } return Ok(sentiment.ToString()); } ``` Line by line: - **`enum Sentiment`** — the list of allowed answers. The model can't return anything outside it. You can move the enum to its own file. - **The system prompt gets shorter.** “Answer with only one word: Positive, Negative or Mixed” and the few-shot examples are no longer needed **for the shape** — the type defines the shape. Less text = fewer input tokens. - **`GetResponseAsync(messages)`** — the same `GetResponseAsync`, but with a type. It returns a **`ChatResponse`**: a normal `ChatResponse` (`Text`, `Usage`, `FinishReason`) plus `Result`. - **`response.Result`** — already a `Sentiment`, not a `string`. `if (sentiment == Sentiment.Negative)` always works correctly. - **`sentiment.ToString()`** — by default ASP.NET Core returns an enum in JSON as a **number** (`Mixed` → `2`). `ToString()` gives us the name. ```tip Few-shot examples are still useful **for content**: for example, if you want the model to understand exactly what you mean by `Mixed`. **For the shape** you don't need them anymore — the type protects the shape. ```

### რა ხდება `GetResponseAsync`-ის შიგნით ერთ ხაზში ოთხი ნაბიჯია: 1. **C# ტიპი → JSON Schema.** Microsoft.Extensions.AI ტიპიდან (`Sentiment`) აგენერირებს JSON Schema-ს — ფორმის აღწერას: „პასუხი ობიექტია ერთი ველით, რომლის მნიშვნელობა ამ სამიდან ერთია“. 2. **სქემა მოთხოვნაში.** სქემა `ChatOptions.ResponseFormat`-ში ჯდება და Gemini-ს მოთხოვნასთან ერთად მიდის. prompt-ში ამას ჩვენ არ ვწერთ. 3. **მოდელი სქემას მისდევს.** Gemini პასუხს წერს ისე, რომ ის სქემას ემთხვეოდეს: ყოველ ნაბიჯზე მხოლოდ იმ ტოკენებს შორის ირჩევს, რომლებიც სქემას არ არღვევს. ამიტომ `"Search."` ან აბზაცი უბრალოდ ვერ გაჩნდება. 4. **JSON → C#.** პასუხი (`{"data":"Mixed"}`) `System.Text.Json`-ით C# ობიექტად იქცევა — `response.Result`. ```note **რატომ `"data"`?** მოდელები JSON-ში ზედა დონეზე მხოლოდ ობიექტს აბრუნებენ. enum, რიცხვი ან სია ობიექტი არ არის — ამიტომ Microsoft.Extensions.AI მას ავტომატურად `{"data": …}`-ში „ახვევს“ და მერე თვითონვე ხსნის. ობიექტზე (მაგ. `record`) ეს არ ხდება. ``` ```terms structured output — მოდელის პასუხი წინასწარ განსაზღვრული ფორმით (JSON Schema), რომელსაც კოდი C# ტიპად კითხულობს JSON Schema — JSON-ის ფორმის აღწერა: რა ველებია, რა ტიპის, რა მნიშვნელობებია დასაშვები ChatResponse — GetResponseAsync-ის პასუხი: ჩვეულებრივი ChatResponse + Result (T ტიპის ობიექტი) ```
### What happens inside `GetResponseAsync` There are four steps in one line: 1. **C# type → JSON Schema.** Microsoft.Extensions.AI generates a JSON Schema from the type (`Sentiment`) — a description of the shape: “the answer is an object with one field whose value is one of these three”. 2. **The schema goes into the request.** The schema is put into `ChatOptions.ResponseFormat` and sent to Gemini with the request. We don't write it in the prompt. 3. **The model follows the schema.** Gemini writes the answer so that it matches the schema: at every step it chooses only among tokens that don't break the schema. That's why `"Search."` or a paragraph simply can't appear. 4. **JSON → C#.** The answer (`{"data":"Mixed"}`) is turned into a C# object with `System.Text.Json` — `response.Result`. ```note **Why `"data"`?** At the top level of JSON, models return only an object. An enum, a number or a list isn't an object — so Microsoft.Extensions.AI automatically “wraps” it in `{"data": …}` and unwraps it again itself. This doesn't happen for an object (e.g. a `record`). ``` ```terms structured output — a model answer in a predefined shape (JSON Schema) that the code reads as a C# type JSON Schema — a description of the shape of JSON: which fields, of which types, which values are allowed ChatResponse — the response of GetResponseAsync: a normal ChatResponse + Result (an object of type T) ```

### ფორმა გარანტირებულია, შინაარსი — არა ერთი და იგივე endpoint, სამი ტექსტი. ყოველ ჯერზე ბრუნდება `BookingRequest` — **ფორმა ყოველთვის სწორია**. შინაარსი კი სხვა საკითხია: | ტექსტი | შედეგი | რა უნდა შენიშნო | |---|---|---| | „ოთხნი ვართ, ხვალ 8-ზე“ | `at: …T08:00`, `guests: 4` | „8“ ორაზროვანია. მოდელმა შეიძლება დილის 8 აირჩიოს, რესტორანი კი 12:00-დან მუშაობს | | „მაგიდა მინდა შაბათს საღამოს“ | `at: …T19:00`, `guests: null` | სტუმრების რაოდენობა არ წერია → `null` (არ მოიგონა). „საღამო“ → 19:00 კი **მოდელის ვარაუდია** | | „ხინკალი რა ღირს?“ | `at: null`, `guests: null` | ჯავშანი არ არის — ფორმა მაინც სწორია, ყველაფერი `null` | ზუსტი შედეგი შენთან შეიძლება განსხვავდებოდეს — მოდელი ალბათობით მუშაობს. **დასკვნა:** structured output იძლევა გარანტიას, რომ პასუხი **ჩვენი ტიპისაა**. ის არ იძლევა გარანტიას, რომ მნიშვნელობები **სწორია**. ამიტომ, სანამ ობიექტი ჩვენს ლოგიკაში (ბაზაში) წავა, **C# ამოწმებს**: ```csharp BookingRequest b = response.Result; if (b.At is null) return BadRequest("რომელ დღეს და რომელ საათზე?"); if (b.Guests is null) return BadRequest("რამდენი ხართ?"); if (b.At.Value.Hour < 12 || b.At.Value.Hour >= 23) return BadRequest("ვმუშაობთ 12:00–23:00"); // აქედან — შენი არსებული ჯავშნის ლოგიკა ``` ეს იგივე წესია, რაც ლექცია 2-ზე: **prompt და მოდელი ალბათობას ცვლის, აუცილებელს კი C# ამოწმებს.**
### The shape is guaranteed, the content is not One endpoint, three texts. Every time a `BookingRequest` comes back — **the shape is always correct**. The content is a different matter: | Text | Result | What to notice | |---|---|---| | “there are four of us, tomorrow at 8” | `at: …T08:00`, `guests: 4` | “8” is ambiguous. The model may pick 8 in the morning, but the restaurant opens at 12:00 | | “I'd like a table on Saturday evening” | `at: …T19:00`, `guests: null` | The number of guests isn't written → `null` (it didn't make it up). “Evening” → 19:00, though, is **the model's guess** | | “how much is khinkali?” | `at: null`, `guests: null` | There's no booking — the shape is still correct, everything is `null` | Your exact result may differ — the model works with probabilities. **Conclusion:** structured output guarantees that the answer is **of our type**. It doesn't guarantee that the values are **correct**. So before the object goes into our logic (the database), **C# checks it**: ```csharp BookingRequest b = response.Result; if (b.At is null) return BadRequest("Which day and what time?"); if (b.Guests is null) return BadRequest("How many of you?"); if (b.At.Value.Hour < 12 || b.At.Value.Hour >= 23) return BadRequest("We're open 12:00–23:00"); // from here — your existing booking logic ``` It's the same rule as in lecture 2: **the prompt and the model change the probability; what must hold, C# checks.**

Controller-ს არცერთი არ ეხება. - **`GetResponseAsync`** — C# ტიპიდან JSON Schema იქმნება, მოთხოვნასთან მიდის, მოდელი სქემას მისდევს, პასუხი `response.Result`-ში უკვე `T` ტიპისაა. - **enum** — ერთი მნიშვნელობა დასაშვები სიიდან (კლასიფიკაცია). **record** — რამდენიმე ველი ტექსტიდან (ამოღება). - **nullable ველები** (`DateTime?`, `int?`) და prompt-ში „რაც არ წერია, დატოვე null“ — მოდელს ნებას აძლევს, არ მოიგონოს. - **ფორმა გარანტირებულია, შინაარსი — არა.** ობიექტს ბაზამდე C# ამოწმებს. ### შემდეგ ლექციაზე მოდელმა ჯავშანი ამოიღო, მაგრამ არ იცის, ხვალ 20:00-ზე მაგიდა თავისუფალია თუ არა — ჩვენს ბაზას ვერ ხედავს. ლექცია 4-ზე — **Tools / Function Calling**: მოდელი თვითონ გადაწყვეტს, როდის გამოიძახოს ჩვენი C# მეთოდი (მაგ. `CheckAvailability` ან `GetMenu`).
## Summary - **`AddChatClient`** — `IChatClient` is created once in `Program.cs` and registered in DI as a Singleton. The Controller receives it through its constructor. The key — in User Secrets, the model name — in `appsettings.json`. - **Changing the provider** — only `Program.cs`; **changing the model** — only `appsettings.json`. Neither touches the Controller. - **`GetResponseAsync`** — a JSON Schema is created from the C# type, sent with the request, the model follows the schema, and the answer in `response.Result` is already of type `T`. - **enum** — one value from an allowed list (classification). **record** — several fields from text (extraction). - **Nullable fields** (`DateTime?`, `int?`) and “leave null whatever is not in the text” in the prompt — let the model not make things up. - **The shape is guaranteed, the content is not.** C# checks the object before it reaches the database. ### Next lecture The model extracted the booking, but it doesn't know whether a table is free tomorrow at 20:00 — it can't see our database. In lecture 4 — **Tools / Function Calling**: the model itself decides when to call our C# method (e.g. `CheckAvailability` or `GetMenu`).
