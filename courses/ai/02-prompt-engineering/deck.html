### `IChatClient` — the “DbContext” of LLMs You already know this idea from EF Core: you write code with `DbContext` and LINQ, and a **provider** talks to the database (`SqlServer`, `Npgsql`). The main method: `GetResponseAsync`. - providers implement this interface: **Google.GenAI** (Gemini), **Microsoft.Extensions.AI.OpenAI** (OpenAI and OpenAI-compatible services), **OllamaSharp** (local models). Our code knows only `IChatClient`. Switching to another provider = changing **one line** where the client is created. ```note Microsoft.Extensions.AI is the official “AI layer” of .NET — just like `ILogger` is for logging. Microsoft Agent Framework is built on it too (lecture 14). DI registration and configuration — in lecture 3. ``` ```terms IChatClient — the Microsoft.Extensions.AI interface for talking to a chat model; the same for every provider provider — a library that implements the common interface for a specific service (Gemini, OpenAI…) ```

### Zero-shot vs few-shot - **Zero-shot** — we only **explain** to the model what to do. For a simple task this is often enough. - **Few-shot** — we add a few **examples** to the explanation: “question → correct answer”. The model takes the examples as a pattern and continues in the same form. **Why do we need it?** Often the AI's answer isn't read by a person — it's used by **our C# code**: ```csharp if (label == "Negative") NotifyManager(); ``` Zero-shot may write an answer that's right in content but “wrong” in form: “negative”, “Negative.”, or a whole paragraph. The `if` won't catch that. Few-shot fixes the form: the answer is exactly one word from the list. | | Zero-shot | Few-shot | |---|---|---| | What we give | only the instruction | the instruction + 3–5 examples | | When | a simple task, free text | an exact format, categories, “borderline” cases | | Cost | fewer tokens | the examples go with every request — more input | ```tip Always include a **hard** case in the examples (here — “good, but expensive” → `Mixed`). Zero-shot fails most often right at the border. ``` ```terms zero-shot — a prompt with only an instruction, no examples few-shot — a prompt with an instruction and a few “question → correct answer” examples ```

## Summary **Remember:** 1. **`IChatClient`** — the “DbContext” of LLMs: one API for every model; switching providers is one line. The key — in User Secrets (`Gemini:ApiKey`), never in code or Git. 2. **`ChatOptions`** — Temperature and Max Tokens per request. On Gemini 3 we leave Temperature at the default; Max Tokens — with room to spare, because thinking is inside that limit too. 3. **`Usage` and `FinishReason`** — input, output and thinking tokens (thinking is billed at the output price too); `stop` / `length`. 4. **A list of messages** — System (our rules), User (the user), Assistant (the model). 5. **System prompt** = role + topics + format + boundaries.
